# 核心决策

Text、Input、Canvas 共享一套文本与绘制基础设施；各自职责分开，不互相污染。

Text 使用 style，Input 与 TextFieldOptions 保留 textStyle，TextStyleProp 类型名称不变。声明字号与行高经前端 Density 转为 PX 后进入统一排版服务；命中、光标及 IME 消费同一后端坐标，不再次缩放，单位见 [基础类型](10-基础类型.md)。

# Foundation 与 Modifier 的组合

Text/Input 是普通 Arrangable，处理自己的 props，将显示或编辑元素追加到外部 Modifier 后，再把组合结果与 MinSizeMeasurePolicy 交给 Layout。正式元素构造遵守可由用户 SFA 组合使用的 UI 契约；具体构造器名称随 API 实现确定，不给予 FA 隐藏入口。

文本 Modifier 实例在自身链层的约束下调用 TextLayoutService，持有排版结果与 baseline，并为绘制、命中和输入提供同一坐标口径。内层 Layout 没有子内容时由 MinSizeMeasurePolicy 完成空内容测量；不再提供由 Layout 读取宿主文本字段的独立 TextMeasurePolicy，也不在 Policy 与 Modifier 两处重复排版。

显示与编辑元素共享文本服务，实例状态各有归属。编辑所需的焦点、选区、光标、滚动、输入连接和 IME 可以由职责明确的多个 Modifier 元素协作，全部遵守同一链条的实例协调与生命周期。业务文本状态由明确的状态对象或 value/onValueChange 持有；平台输入会话和挂接资源不能随描述对象被多受体共享。

共享的 TextPresentation 只保存排版与呈现配置。显示内容来自 TextModifier.text；编辑内容及空值占位来自 TextFieldModifier.value/placeholder，不在 presentation 内再保存一份文字。编辑会话同时绑定 LayoutNode 代际与 Modifier handle；同一节点更换编辑元素后，旧选区、IME 下划线、提交和回调均不得转给新受体。输入编辑经明确回调更新业务状态，不能直接写入已发布模型。

文字内容、字体或排版约束变化触发必要测量；仅颜色变化触发绘制；回调替换更新对应事件绑定。退休元素撤销输入资格、订阅和旧回调，迟到结果不能写入新实例。不得增加 capabilities、Layout 文本模式或直接写宿主文本属性作为第二条通道。

# Text

Text 是组合文本 Modifier 的纯显示 Arrangable。

- C++ 侧负责测量、换行、intrinsic、baseline 与绘制缓存。
- JS 侧只传文本与样式意图。
- 不处理输入。
- 用户优先只需设置字号、字重、颜色、对齐等基础参数。

# Input

Input 是组合编辑 Modifier 的自绘文本 Arrangable。

- Arrange 自己绘制文本、光标、选区、占位符。
- `ArrangeEditor` 负责对接 JUCE 文本输入能力。
- 不直接把 JUCE `TextEditor` 塞进树里。
- 当前正式入口使用 `value 与 onValueChange`；InputState 完整层及 commitMode 属于后续能力，不作为已经实现的公开契约。

编辑会话持有正文、UTF-8 边界光标与选区、IME 事务、撤销历史及横/纵视口。普通编辑通过 `onValueChange` 回写；失焦提交本次会话发生的改变并调用 onBlur，Return 在单行输入提交，在多行输入插入换行，Command/Ctrl+Return 提交。多行文本统一将 CRLF/CR 正规化为 LF，单行插入或粘贴把换行改为空格。

IME marked text 只更新 native 会话和覆盖层，不向业务 value 逐次发送候选文字。JUCE 给出第一次候选后用临时下划线确定组合事务；Windows 的 composition start 空插入在删除选区之前保存基线。清空临时下划线时一次提交完整组合；平台空插入取消、Escape 或组合期间 Undo 恢复组合前正文和选区，不产生新的业务 value 或历史项。整个已提交组合是一项 undo；失焦取消尚未提交的组合，再结束编辑会话。

撤销/重做最多保存 128 项。连续同类的普通输入、Backspace 或 Delete 在 750ms 间隔内合并；移动光标、选择、换行、粘贴、切换编辑种类或时间间隔断开分组。一次选区替换、剪切、粘贴或 IME 提交均按完整动作恢复。Command/Ctrl+A/C/X/V/Z、Shift+Command/Ctrl+Z 与 Command/Ctrl+Y 使用宿主系统剪贴板及撤销栈。业务 value 恰好回执当前编辑正文时保留历史和选区；真正的外部正文替换清除旧历史、组合及视口定位偏好。

多行 Input 的 `maxLines` 约束可见视口和测量高度，正文排版始终保留所有显式换行与自动换行；不截断输入，也不对正文做省略。单行模式由 `singleLine` 决定。纵向视口自动使活动光标可见，Up/Down 按视觉行移动并保持期望横坐标，Home/End 定位当前视觉行首尾，Command/Ctrl+Home/End 定位正文起止，PageUp/PageDown 按输入视口移动；Shift 扩展同一选区。左右方向沿 UTF-8 scalar 边界移动，已有选区在无 Shift 时收敛到对应边缘。

单击定位光标，Shift+单击从已有活动选区锚点扩选。双击按 JUCE 字符分类选择连续词、空白或标点组；沿用其非 ASCII 字符补充判定，并区分常见 Unicode/CJK/全宽标点，不承诺语言学分词。三击选择所点视觉行，包含软换行形成的行、排除硬行末 LF；跨行拖动时包含中间 LF。四击及更多选择全文，与 JUCE TextEditor 一致。双击/三击后的拖动保持词/视觉行粒度，释放只结束拖动，不重置选区。

正文、选择、下划线、光标、点击索引和 IME 候选窗口统一应用 Input 视口偏移，再经 Modifier 几何转换到宿主坐标。平台 character index 在 JUCE adapter 转成 UTF-8 byte index；不混用两种索引。自动化验证覆盖中文组合协议、非 BMP 边界、选区替换、剪贴板、编辑回执、视觉行导航及几何往返；平台输入法窗口及 Windows 实机体验仍按平台验收执行。

# Canvas

Canvas 是自定义绘制节点，节点、布局、命中、生命周期与热更新同其它 Arrangable。它降解为带失效方式的 `drawBehind`，与绘制修饰器共用 `DrawScope`、数值流编码、命令求界与重放：`onDraw` 在绘制准备阶段录制命令，正式 paint 只重放，不进 JS。Canvas 没有固有尺寸，大小由 `modifier` 决定，可与 `pointerInput`、动画等修饰器组合。

失效方式：

- `auto`（默认）：`onDraw` 读取的响应式依赖变化，或读过的原生数据源推进版本时重录。
- `manual`：录制不登记任何依赖，只有 `controller.invalidate()` 触发重录；`controller` 由 `createCanvasController()` 创建，可同时驱动多个 Canvas。
- `frame`：录制不登记依赖，每个视觉帧重录；作用域停用期间暂停。

尺寸变化总会重录。三种方式都只改绘制，不触发结构重排；重绘范围按命令求出的新旧边界局部计算。

数据与绘制来源分三档，三档共用同一 Canvas 与 `DrawScope`，换档只改数据源或绘制源：

| 档 | 数据 | 绘制 | 用途 |
|---|---|---|---|
| A | JS 状态 | JS `DrawScope` | 旋钮、装饰、低频变化 |
| B | 原生数据源 | JS `DrawScope` | meter、波形、频谱 |
| C | 原生数据源 | 原生 painter | 追求性能上限 |

B 档的原生数据源由 `meterSource`、`waveformSource`、`spectrumSource` 取得（[互操作](16-互操作.md#音频观测流)）。音频线程照旧无锁写入原生侧；UI 帧开始交付时把最新数据写进数据源持有的固定 `Float32Array` 并推进版本。`read()` 直接返回该数组，不经响应式；`auto` 下 Canvas 登记录制中读过的数据源，版本变化即重录。

C 档的原生 painter 由 C++ 按名称注册并声明参数表，参数为数值、颜色、布尔或数据源名。JS 以 `scope.drawNative(name, { x, y, width, height, params })` 引用，名称与参数在原生解码时校验：名称未注册、缺少或多出参数、类型不符都使候选失败并进入诊断，不静默跳过。绘制函数接受 JUCE `Graphics`、目标矩形与只读参数视图，重放时裁到目标矩形，边界即该矩形；透明度经图层合成。JS 不持有原生指针，解码时按名称取当前注册项，热更新与重新注册后自然重新绑定。

注册表分两级。实例级挂在处理器持有的 `Interop` 上，绘制函数可以捕获本处理器的数据；进程级是全局表，只适合不依赖实例状态的 painter。解码时先查本 Editor 所接 `Interop` 的实例表，查不到再查进程表，同名时实例项遮蔽进程项。插件多开时各实例注册同名 painter 互不干扰，各画各的数据；名称因此只需在一个处理器内唯一，不需要全局唯一的 id。

C 档的数据由原生 painter 自己读取，JS 录出的命令本身不随数据变化。数据源参数因此可以直接传 `DataSource`：按名称传给 painter，同时登记为读过的数据源，并把各数据源版本之和写进命令。数据推进时 `auto` Canvas 重录，命令随版本不同，片段比较据此局部重绘；painter 读取原生数据的方式由宿主自定，名称只用于区分。

- 字体解析。
- 文本测量缓存。
- baseline 计算。

# 文本语义约定

- `maxLines == 0` 表示不限行；在有宽度约束时 Text 应按宽度 soft wrap。
- `maxLines == 1` 才是单行文本；绘制分支不得把 `0` 当作单行。
- `overflow` 是 Text 自身策略，不是视图树 clipping 策略。
- `overflow: "clip"` 把文本裁在 Text rect 内。
- `overflow: "ellipsis"` 在有界宽度与行数限制下绘制省略；单行省略必须先可靠成立，多行省略后续也必须沿用同一 TextLayoutService 口径。
- `overflow: "visible"` 表示 Text 自身不裁剪超出内容；但祖先 `M.clip(...)`、scroll viewport、Lazy viewport 与宿主根窗口仍可裁剪它。
- 测量、布局、绘制、caret、selection、IME bounds、point-to-index 与长文本 viewport 必须共享同一 text rect / layout origin / viewport offset。
- 当前可以不是完整 shaping 终局，但新增文本几何能力不得另起一套估算模型。

二者不注入主题样式，基础文字颜色为黑色；Input 没有装饰性内边距、背景或边框。FA 的无样式边界见 [内建 Arrangable](12-内建Arrangable.md)。

# TextLayoutService

Text、Input、IME、selection、caret、hit-test 必须共用同一套文本布局模型。

```txt
text + style + width constraints
-> line metrics
-> glyph / cluster positions
-> caret rect
-> selection rects
-> point -> text index
-> draw plan
```

以下路径必须共用 `TextLayoutService`：

- Text 测量与绘制。
- Input 文本绘制。
- Input 光标绘制。
- Input 选区绘制。
- IME `getCaretRectangleForCharIndex(...)`。
- IME `getTextBounds(...)`。
- 鼠标点击定位。
- 拖拽选择。

禁止用 `fontSize * 常数` 作为长期 caret / selection 测量。中文、英文、组合字符、emoji 等必须通过真实字体测量与 glyph / cluster 边界逐步收口。

# 排版资源、复用与失效

`TextLayoutService` 是正式排版入口，返回共享、不可变的 `TextLayout`。结果包含尺寸、真实基线、行与 UTF-8 字节区间几何、保守字形边界及 `TextDrawResource`。节点保留最近结果；DrawOp 与 PublishedFrame 保留同一资源引用。候选 scene 复制只复制引用，发布后不改写结果。

布局请求、测得尺寸、最终分配矩形和绘制原点分别表示。最终宽度需要换行或省略时，在布局/绘制准备阶段解析正确请求；绘制原点和对齐不写进字形数组。单行非省略文本不依赖 viewport 宽度；已有换行仍适用于较窄分配区域时可以直接复用。`maxLines == 0` 不限行，显式空行及末尾换行均保留。

JUCE 后端统一使用固定 JUCE 版本的 `detail::ShapedText`，取得 fallback 字体、真实 shaping、簇范围及最终字形位置；这些内部类型仅封装在 `arrange_juce`，升级 JUCE 时须复核该适配器。准备阶段把字体、glyph 编号和位置保存为颜色无关的连续数组，paint 直接调用后端 glyph 重放。不会调用 TextLayout 创建、重新 shaping、修改共享 run 颜色或复制完整字形数组。core 的无后端近似实现仅供确定性测试，不能作为 JUCE paint 的兜底。

缓存分两级：

- 节点最近结果优先匹配，稳定重绘不查全局缓存。
- 每个文本服务具有 LRU，默认最多 256 项、估算保留 8 MiB；超预算单项不入缓存。字体/排版资源按引用共享，LRU 淘汰只释放自身引用。

## 字号与行高

`fontSize` 与 `lineHeight` 的单位是 SP，`fontSize` 的数值就是字体的 em 大小，对齐 CSS 的 `font-size` 与 Compose 的 `sp`；`DrawScope.drawText` 的 `fontSize` 是同一含义的 PX。JUCE 后端以 `FontOptions::withPointHeight` 建字体，不使用 JUCE 高度（上下行之和），所以同一字号下拉丁字体与中日文、emoji 回落字体的 em 相同，不随字体的上下行之和变化。未设置字号取 12，未设置行高取字号的 1.2 倍，小于 1 倍字号的行高按 1 倍字号处理。

`lineHeight` 是绝对行距，对齐 CSS 的 `line-height: <length>`，与字体的上下行之和无关，可以小于它。每一行的行盒由 `TextLayoutService` 的后端适配器自己定：行距恒为 `lineHeight`，基线取主字体的半行距（可为负）加上行；回落字体的字形画在同一条基线上，可略高或略低于行盒。排版结果中的行位置、行高、基线、总高，以及光标和选区矩形都按这一规则产生，后端的行盒（含回落字体撑高的部分）不参与，因此纯拉丁行、含中文的行与混排行的行距相同。

缓存键包括文本、字号、行高、有效宽度、单行/换行、行数与省略规则。颜色、透明度、对齐、原点、滚动偏移及纯 graphics transform 不参与排版键。字体环境代际变化使旧结果失效；调用者须同时请求必要布局。当前固定默认字体的度量使用 JUCE 逻辑单位，宿主像素缩放和图形变换不改变此排版输入；后续引入字体配置或后端度量环境变化时必须推进环境代际。

Input 正文、占位符、编辑内容与 IME 共用服务。`TextInputOverlayBuilder` 给出统一文字区域和原点，候选准备将编辑内容保存为 TextField 局部绘制命令；其在场景片段中的重放归属见[渲染设计](05-渲染设计.md)。JUCE 输入适配器只做坐标/平台类型转换；光标、选区和 point-to-index 从同一行/簇几何取得。视口移动与选区变化复用已准备资源。现有编辑仍不承诺完整 Unicode grapheme 编辑、双向文本选区或所有 emoji 序列的删除行为。

选区的横坐标在当前行内计算，不能重新通过全局字节位置选择另一行。自动换行的行尾/下一行行首共用字节位置时，光标归下一行行首；显式换行符之前的位置仍归上一行末尾。行宽保留真实空格的前进量，排除换行符。JUCE ligature placeholder 仅从绘制字形列表排除，其字符区间和分摊前进量仍参与输入几何；几何使用笔位置，字形偏移只用于实际绘制和墨迹边界。

节点删除、分支退出、KeepAlive 退休、HMR/reset 与 editor 销毁释放其引用；缓存以 runtime/editor 为作用域，reload 清除缓存引用，仍存活的旧帧可继续持有资源。最后一个节点/帧/缓存持有者释放后回收。候选准备失败不修改成功帧。诊断页、badge、toast 也在发布前准备文字，稳定条目延续上帧引用。

实际计数区分排版创建、节点复用、LRU 命中/未命中/淘汰、缓存保留字节及实际存活资源/估算字节。排版准备耗时与后端 glyph 提交耗时分别记录。估算不包含 JUCE/系统字体与栅格缓存；LRU 预算不是整个场景的内存上限。

# 不做

- 不把 Text 做成输入控件。
- 不把 Input 交给 JUCE 子控件树托管。
- 不把 Canvas 高频数据设计绑定到 Arrange 响应式大数组；高频数据走原生数据源。
- 不把布局和文本测量放进 JS。
- 不让 Input 绘制、光标、选区、IME bounds 各自维护不同测量模型。
