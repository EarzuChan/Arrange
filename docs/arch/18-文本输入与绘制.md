# 核心决策

Text、Input、Canvas 共享一套文本与绘制基础设施；各自职责分开，不互相污染。

# Foundation 与 Modifier 的组合

Text/Input 是普通 Arrangable，处理自己的 props，将显示或编辑元素追加到外部 Modifier 后，再把组合结果与 MinSizeMeasurePolicy 交给 Layout。正式元素构造遵守可由用户 SFA 组合使用的 UI 契约；具体构造器名称随 API 实现确定，不给予 FA 隐藏入口。

文本 Modifier 实例在自身链层的约束下调用 TextLayoutService，持有排版结果与 baseline，并为绘制、命中和输入提供同一坐标口径。内层 Layout 没有子内容时由 MinSizeMeasurePolicy 完成空内容测量；不再提供由 Layout 读取宿主文本字段的独立 TextMeasurePolicy，也不在 Policy 与 Modifier 两处重复排版。

显示与编辑元素共享文本服务，实例状态各有归属。编辑所需的焦点、选区、光标、滚动、输入连接和 IME 可以由职责明确的多个 Modifier 元素协作，全部遵守同一链条的实例协调与生命周期。业务文本状态由明确的状态对象或 value/onValueChange 持有；平台输入会话和挂接资源不能随描述对象被多受体共享。

共享的 TextPresentation 只保存排版与呈现配置。显示内容来自 TextModifier.text；编辑内容及空值占位来自 TextFieldModifier.value/placeholder，不在 presentation 内再保存一份文字。编辑会话同时绑定 LayoutNode 代际与 Modifier handle；同一节点更换编辑元素后，旧选区、IME 下划线、提交和回调均不得转给新受体。输入编辑经明确回调更新业务状态，不能直接写入已发布模型。

文字内容、字体或排版约束变化触发必要测量；仅颜色变化触发绘制；回调替换更新对应事件绑定。退休元素撤销输入资格、订阅和旧回调，迟到结果不能写入新实例。不得增加 capabilities、Layout 文本模式或直接写宿主文本属性作为第二条通道。

# Text

Text 是组合文本 Modifier 的纯显示 Arrangable。

- C++ 侧负责测量、换行、intrinsic、baseline 与绘制缓存。
- JS 侧只传文本与样式意图。
- 不处理输入。
- 用户优先只需设置字号、字重、颜色、对齐等基础参数。

# Input

Input 是组合编辑 Modifier 的自绘文本 Arrangable。

- Arrange 自己绘制文本、光标、选区、占位符。
- `ArrangeEditor` 负责对接 JUCE 文本输入能力。
- 不直接把 JUCE `TextEditor` 塞进树里。
- 当前正式入口使用 `value 与 onValueChange`；InputState 完整层及 commitMode 属于后续能力，不作为已经实现的公开契约。

# Canvas

Canvas 是自定义绘制节点。

- 默认采用 retained display list 思路。
- `onDraw` 生成绘制命令，由 C++/JUCE 执行。
- 不要求每次 paint 都进 JS。
- `invalidation` 分为 `auto`、`manual`、`frame`。
- 缓存失效以数据变更、尺寸变更、动画驱动或手动 invalidate 为准。

# 共享基础设施

- 字体解析。
- 文本测量缓存。
- baseline 计算。
- 文本颜色与排版参数。
- 绘制缓存。

# 文本语义约定

- `maxLines == 0` 表示不限行；在有宽度约束时 Text 应按宽度 soft wrap。
- `maxLines == 1` 才是单行文本；绘制分支不得把 `0` 当作单行。
- `overflow` 是 Text 自身策略，不是视图树 clipping 策略。
- `overflow: "clip"` 把文本裁在 Text rect 内。
- `overflow: "ellipsis"` 在有界宽度与行数限制下绘制省略；单行省略必须先可靠成立，多行省略后续也必须沿用同一 TextLayoutService 口径。
- `overflow: "visible"` 表示 Text 自身不裁剪超出内容；但祖先 `M.clip(...)`、scroll viewport、Lazy viewport 与宿主根窗口仍可裁剪它。
- 测量、布局、绘制、caret、selection、IME bounds、point-to-index 与长文本 viewport 必须共享同一 text rect / layout origin / viewport offset。
- 当前可以不是完整 shaping 终局，但新增文本几何能力不得另起一套估算模型。

二者不注入主题样式，基础文字颜色为黑色；Input 没有装饰性内边距、背景或边框。FA 的无样式边界见 [内建 Arrangable](12-内建Arrangable.md)。

# TextLayoutService

Text、Input、IME、selection、caret、hit-test 必须共用同一套文本布局模型。

```txt
text + style + width constraints
-> line metrics
-> glyph / cluster positions
-> caret rect
-> selection rects
-> point -> text index
-> draw plan
```

以下路径必须共用 `TextLayoutService`：

- Text 测量与绘制。
- Input 文本绘制。
- Input 光标绘制。
- Input 选区绘制。
- IME `getCaretRectangleForCharIndex(...)`。
- IME `getTextBounds(...)`。
- 鼠标点击定位。
- 拖拽选择。

禁止用 `fontSize * 常数` 作为长期 caret / selection 测量。中文、英文、组合字符、emoji 等必须通过真实字体测量与 glyph / cluster 边界逐步收口。

# 排版资源、复用与失效

`TextLayoutService` 是正式排版入口，返回共享、不可变的 `TextLayout`。结果包含尺寸、真实基线、行与 UTF-8 字节区间几何、保守字形边界及 `TextDrawResource`。节点保留最近结果；DrawOp 与 PublishedFrame 保留同一资源引用。候选 scene 复制只复制引用，发布后不改写结果。

布局请求、测得尺寸、最终分配矩形和绘制原点分别表示。最终宽度需要换行或省略时，在布局/绘制准备阶段解析正确请求；绘制原点和对齐不写进字形数组。单行非省略文本不依赖 viewport 宽度；已有换行仍适用于较窄分配区域时可以直接复用。`maxLines == 0` 不限行，显式空行及末尾换行均保留。

JUCE 后端统一使用固定 JUCE 版本的 `detail::ShapedText`，取得 fallback 字体、真实 shaping、簇范围及最终字形位置；这些内部类型仅封装在 `arrange_juce`，升级 JUCE 时须复核该适配器。准备阶段把字体、glyph 编号和位置保存为颜色无关的连续数组，paint 直接调用后端 glyph 重放。不会调用 TextLayout 创建、重新 shaping、修改共享 run 颜色或复制完整字形数组。core 的无后端近似实现仅供确定性测试，不能作为 JUCE paint 的兜底。

缓存分两级：

- 节点最近结果优先匹配，稳定重绘不查全局缓存。
- 每个文本服务具有 LRU，默认最多 256 项、估算保留 8 MiB；超预算单项不入缓存。字体/排版资源按引用共享，LRU 淘汰只释放自身引用。

缓存键包括文本、字号、行高、有效宽度、单行/换行、行数与省略规则。颜色、透明度、对齐、原点、滚动偏移及纯 graphics transform 不参与排版键。字体环境代际变化使旧结果失效；调用者须同时请求必要布局。当前固定默认字体的度量使用 JUCE 逻辑单位，宿主像素缩放和图形变换不改变此排版输入；后续引入字体配置或后端度量环境变化时必须推进环境代际。

Input 正文、占位符、覆盖层与 IME 共用服务。`TextInputOverlayBuilder` 给出统一文字区域和原点，JUCE 输入适配器只做坐标/平台类型转换；光标、选区和 point-to-index 从同一行/簇几何取得。视口移动与选区变化复用已准备资源。现有编辑仍不承诺完整 Unicode grapheme 编辑、双向文本选区或所有 emoji 序列的删除行为。

选区的横坐标在当前行内计算，不能重新通过全局字节位置选择另一行。自动换行的行尾/下一行行首共用字节位置时，光标归下一行行首；显式换行符之前的位置仍归上一行末尾。行宽保留真实空格的前进量，排除换行符。JUCE ligature placeholder 仅从绘制字形列表排除，其字符区间和分摊前进量仍参与输入几何；几何使用笔位置，字形偏移只用于实际绘制和墨迹边界。

节点删除、分支退出、KeepAlive 退休、HMR/reset 与 editor 销毁释放其引用；缓存以 runtime/editor 为作用域，reload 清除缓存引用，仍存活的旧帧可继续持有资源。最后一个节点/帧/缓存持有者释放后回收。候选准备失败不修改成功帧。诊断页、badge、toast 也在发布前准备文字，稳定条目延续上帧引用。

实际计数区分排版创建、节点复用、LRU 命中/未命中/淘汰、缓存保留字节及实际存活资源/估算字节。排版准备耗时与后端 glyph 提交耗时分别记录。估算不包含 JUCE/系统字体与栅格缓存；LRU 预算不是整个场景的内存上限。

# 标注文本

未来可考虑 `AnnotatedString` 式能力：文本本体仍是纯文本，但允许给区段附加 style、tag、annotation 或点击动作。

核心只提供注解数据能力，不默认提供 Link 样式、蓝色下划线样式或其他设计系统样式。样式解释由用户、主题或扩展包决定。

先不做富文本编辑。

# 不做

- 不把 Text 做成输入控件。
- 不把 Input 交给 JUCE 子控件树托管。
- 不把 Canvas 高频数据设计绑定到 Arrange 响应式大数组。
- 不把布局和文本测量放进 JS。
- 不让 Input 绘制、光标、选区、IME bounds 各自维护不同测量模型。
