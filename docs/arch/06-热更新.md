# 目标

开发期保存界面文件后，JUCE 界面快速更新，无需重启宿主。

# 通道

使用 Vite WebSocket HMR 通道。默认地址为 `http://127.0.0.1:9178`，可用 `ARRANGE_DEV_SERVER` 覆盖，也可由 `config.app.useLive(url)` 显式指定。

# 行为

- 接收 Vite HMR 更新通知。
- M1 统一走 native full reload，不做 Vue component-level hot replace。
- 每次 reload 都重新按 `live -> dist -> error` 链路加载。
- 早期允许整棵界面树重挂载。
- 失败进入错误屏，允许用户手动重试。

Debug 手动刷新：

- `F5`：按当前配置重新加载。
- `Ctrl+F5`：切换 live enabled 状态后重新加载。

# 当前 M1 实现口径

- Vite 插件保存 Arrange 源文件时发送 `arrange:reload` 自定义消息。
- Vite 插件同时提供 `/@arrange/app.mjs`，用当前 Vite/Vue/SFC 配置即时构建一个给 QuickJS 执行的单文件 ESM bundle。
- JUCE 侧 `ArrangeEditor` 在配置了 live source 时启动内部 WebSocket 客户端，连接显式 URL、`ARRANGE_DEV_SERVER` 或默认 dev server。
- native 客户端接收 Vite 的 reload 通知后，通过公开的 `ArrangeEditor::reload()` 走同一条重载路径，不暴露内部 Surface。
- dev server 可达时优先加载 `/@arrange/app.mjs`；dev server 未启动时，只要配置了 dist source，就回退加载 `ui/app.mjs`。
- reload / 错误页重试 / HMR reload / 手动 F5 必须共享同一条加载链路，不能初次加载和重试行为不一致。
- 这一切片先保证“开发期通知能到 JUCE Editor，并能拉到当前 SFC bundle”；更细的模块替换属于后续开发体验，不作为 M1 退出目标。

# 状态可见

Debug / Release 与实际加载 source 必须在 Editor 内可见：

- `Debug live`
- `Debug dist`
- `Release dist`
- 必要时显示 `Debug live failed -> dist`

HMR connected / disconnected / reload received 等短状态进入诊断 toast 与日志；具体样式、生命周期和开关见 `docs/arch/25-开发期诊断表层.md`。

# 发布模式

发布模式下禁用热更新连接，只加载发布产物。

# 原则

- 热更新只服务开发体验。
- 文件监听不作为主热更新设计。
