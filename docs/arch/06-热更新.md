# 目标

开发期保存界面文件后，JUCE 界面快速更新，无需重启宿主。

# 通道

使用 Vite WebSocket HMR 通道。默认地址为 `http://127.0.0.1:9178`，可用 `ARRANGE_DEV_SERVER` 覆盖，也可由 `config.app.useLive(url)` 显式指定。

# 行为

- 接收 Vite HMR 更新通知。
- 当前基础策略是 native full reload；未来可在不破坏语义的前提下加入更细粒度热替换。
- 每次 reload 都重新按 `live -> dist -> error` 链路加载。
- 失败进入错误屏，允许用户手动重试。

Debug 手动刷新：

- `F5`：按当前配置重新加载。
- `Ctrl+F5`：切换 live enabled 状态后重新加载。

# 实现约束

- Vite 插件保存 Arrange 源文件时发送 `arrange:reload` 自定义消息。
- Vite 插件提供可由 QuickJS 执行的 App bundle 入口。
- `ArrangeEditor` 在配置 live source 时启动 HMR 客户端，连接显式 URL、`ARRANGE_DEV_SERVER` 或默认 dev server。
- HMR 客户端收到 reload 通知后，通过公开 reload 入口走统一加载链路，不暴露内部 Surface。
- dev server 可达时优先加载 live App；dev server 未启动时，只要配置了 dist source，就回退加载 dist App。
- reload、错误页重试、HMR reload、手动 F5 必须共享同一条加载链路。

# 状态可见

Debug / Release 与实际加载 source 必须在 Editor 内可见：

- `Debug live`
- `Debug dist`
- `Release dist`
- 必要时显示 `Debug live failed -> dist`

HMR connected / disconnected / reload received 等短状态进入诊断 toast 与日志；具体样式、生命周期和开关见 [开发期诊断表层](25-开发期诊断表层.md)。

# 发布模式

发布模式下禁用热更新连接，只加载发布产物。

# 原则

- 热更新只服务开发体验。
- 文件监听不作为主热更新设计。
- 热更新不得改变核心布局、绘制、输入与 native transaction 语义。
