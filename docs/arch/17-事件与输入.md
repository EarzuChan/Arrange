# 目标

输入系统连接 JUCE 平台事件、Arrange 命中测试、Modifier 交互语义与 JS 回调。

输入系统的长期事实源是统一 intent 模型。JUCE pointer / key / IME、声明式状态变化、resize、reload / HMR、resource ready 与 diagnostics event 都必须进入 [调度线程与帧阶段](26-调度线程与帧阶段.md) 定义的 `InputIntent -> RuntimeStore / MutationTransaction -> InvalidationGraph -> FramePlan` 链路。

# 分层

- 高级语义：`M.clickable`、`M.hoverable`、`M.focusable`。
- 低级指针：`M.pointerInput`。
- Arrangable语义事件：例如 `Input value/onValueChange`。

# 派发原则

- 离散事件立即派发。
- 连续事件默认合并。
- 没有监听兴趣就不跨界。
- 高级语义尽量由 C++ 识别，JS 只收到必要回调。

“立即派发”只表示交互边界不被 frame 合并，不表示回调后立即执行 tree apply、layout 或 draw。JS 回调造成的 UI 变更进入 MutationTransaction queue，由 [调度线程与帧阶段](26-调度线程与帧阶段.md) 定义的 FramePlan / SceneFramePipeline 统一消费。

# 输入对象分工

输入相关命名与职责必须按层级收口：

- JUCE adapter：只把平台 pointer、wheel、key、text、IME 事件转为 internal intent 或平台文本输入回调，不做输出阶段决策。
- input processor：负责命中、pointer capture、scroll、click、hover、focus、text editing 等语义处理，并产出 typed state change / dirty。
- interaction state owner：持有 pressed / hover / focus / capture 等 native-first 状态，不直接 request repaint 或 layout。
- text input owner：持有 text editing、caret、selection、IME composition 等状态，并通过 typed invalidation 进入 FramePlan。

# 离散事件

立即进入 JS 或语义处理链：

- pointer down / up / cancel。
- key down / up。
- text input。
- focus / blur。
- gesture begin / end。

这些事件是交互边界，不能被 frame 合并。

# 连续事件

默认进入 C++ 队列并合并：

- pointer move。
- drag move。
- hover move。
- 高频 wheel / trackpad delta。

同一 `pointerId` 默认只保留最新状态；高级场景可附带 samples。

wheel / trackpad 的 delta 是增量，合并时必须累加，不能只保留最后一次。当前滚动回调按输入顺序排队，调度唤醒与同帧 UI 提交可以合并。

# JUCE 到 Arrange

```txt
JUCE mouse/key event
-> ArrangeEditor
-> Juce input adapter
-> InputIntent
-> input processor / hitTest
-> typed interaction state change
-> optional JS QuickJS callback
-> MutationTransaction / InvalidationGraph
-> FramePlan
```

# PointerEvent

```ts
interface PointerEvent {
  x: Dp
  y: Dp
  localX: Dp
  localY: Dp
  pointerId: number
  button: "left" | "right" | "middle"
  modifiers: KeyModifiers
  samples?: PointerSample[]
  consumed: boolean
  consume(): void
}
```

`pointerInput` 是低级指针事件入口，不是 `clickable`、`hoverable`、`scrollable` 的替代品。它只负责把节点声明为需要接收 typed pointer stream，并通过真实 event slot 传递 pointer down / move / up / cancel / wheel 等事件。

要求：

- pointer event payload 由 C++ 直接构造 JS object，不经过 JSON / string / binary 编码。
- 命中、zIndex、clip、transform 与 pointer capture 必须先在 native 侧判定，再决定是否调用 JS。
- `consume()` 只影响同一次输入派发中的后续语义处理，不得直接执行 layout、paint 或 mutation apply。
- callback 生命周期必须随 Modifier 替换、节点删除、unmount、reload / HMR 退休。
- 连续 move / drag 可合并，但 down / up / cancel 不得丢失。

# 事件兴趣

每个节点从 Modifier 编译出事件兴趣：

```txt
wantsClick
wantsHover
wantsPointerInput
wantsWheel
wantsKeyboard
wantsFocus
```

未声明兴趣的节点不会收到对应事件，也不会触发 JS 回调。

回调是 Arrangable 明确声明的普通 prop，由实现交付正式 Modifier 字段。原生只按类型化 Modifier 输入登记回调资源，没有节点直属事件 prop、事件绑定表或 `__arrangeEventSlot.*` 派生字段。TextField 的 onSubmit/onChange/onBlur/onValueChange 与 clickable、滚动等元素遵守同一实例及回调退休规则，详见 [Modifier](11-Modifier.md)。

# 高级语义

`M.clickable(onClick)` 不等于把所有鼠标事件交给 JS。初始策略：

```txt
pointer down -> C++ 标记 pressed 并捕获 pointer
pointer move -> C++ 更新 pressed / hover / hit 状态
pointer up -> 仍命中同一节点代际与 Modifier 受体时，通过当前已发布 callback 触发 onClick
cancel / lost capture -> 清理 pressed
```

点击捕获归属稳定节点代际及 Modifier 身份，回调资源本身仍遵守不可变 token 与退休规则。down 到 up 之间普通重渲染若只刷新同一受体的闭包，up 使用当前已发布的 callback；禁用、移除、更换受体或节点代际均取消点击，不调用退休 token。

`M.hoverable`、`M.focusable`、滚动类 Modifier 也优先在 C++ 侧维护基础状态。

# InteractionState

本节为后续设计；当前 Framework 不导出 createInteractionState，也不接受 interactionState 参数。

用户需要 hover / focus / pressed 样式时，显式创建并传入状态：

```sfa
const interaction = createInteractionState()

const modifier = computed(() =>
  M.background(interaction.hovered ? hoverBg : bg)
   .border(interaction.focused ? 2.dp : 1.dp, interaction.focused ? primary : outline)
   .clickable({ interactionState: interaction, onClick })
)
```

规则：

- 核心不绑定任何设计系统状态层；hover、pressed、focus 等视觉反馈由响应式交互状态、Modifier 与上层Arrangable库表达。
- 未传入 `InteractionState` 时，C++ 仍维护状态，但不必同步到 JS。
- `InteractionState` 是只读响应式对象；用户通过响应式计算拼 Modifier。
- 同一个 `InteractionState` 可同时传给 `hoverable`、`focusable`、`clickable`。

# Clickable

- 默认 `enabled=true`、`focusable=true`、左键触发。
- Pointer：down 命中后进入 pressed；up 仍在命中区域内触发 `onClick`。
- Keyboard：焦点在本节点时，Enter / Space 触发 `onClick`。
- Disabled：不触发点击，不进入 pressed，可从焦点遍历中移除。
- 后续 `onDoubleClick` 与 `onLongClick` 应基于同一 pressed 语义；当前不接受这两个参数。
- 高级拖拽、旋钮、滑杆不要滥用 `clickable`；使用后续专门 gesture 或 `pointerInput`。

# Hoverable

- 只表示 pointer 进入 / 离开与 hover 状态。
- 不默认监听连续 move；需要坐标流时用 `pointerInput`。
- 多层重叠时按 transform 后命中、zIndex 与绘制逆序确定最上层 hover target。

# Focus

每个 Owner 持有独立的通用焦点树与文本编辑会话。焦点受体以 `LayoutNode` 代际和 Modifier handle 标识；同节点内显式 `focusable`、`clickable` 与文本编辑语义组成一个焦点受体。祖先 `enabled=false`、受体禁用或 `canFocus=false` 均移除焦点资格；复用 node id 不继承旧焦点。

目标创建、恢复与成功提交的等待时机见 [调度线程与帧阶段](26-调度线程与帧阶段.md#authoring-更新完成的边界)。

```ts
const requester = createFocusRequester()
const manager = useFocusManager()

M.focusRequester(requester)
 .onFocusChanged((state) => {})
 .focusProperties({ next, previous, up, down, left, right, canFocus })
 .focusable()
```

规则：

- `focusable` 把节点加入焦点树；`onFocusChanged` 不自行创建焦点受体。Requester、方向配置和自身焦点观察者应放在受体之前。Input 自身提供编辑受体，可在传入的 Modifier 上配置它。
- `clickable` 默认隐含 `focusable`，以保证键盘可操作。
- `createFocusRequester()` 产生稳定身份；同一个请求器只能绑定一个存活受体。`requestFocus()` 的布尔值表示宿主已接受命令，不表示焦点已经落下。命令在成功发布目标后兑现；目标尚未出现时保留请求，作用域销毁取消未兑现请求。
- `useFocusManager()` 在 setup 内取得当前 Owner 的管理器，提供 `clearFocus()` 和 `moveFocus(direction)`。焦点请求进入独立的宿主待办并唤醒帧，即使没有其它视觉 dirty 也会消费。
- `onFocusChanged` 收到原生构造的 `{isFocused, hasFocus}`。自身受体获得焦点时两者为 true；普通父 Layout 或 focusGroup 的后代获得焦点时，仅 hasFocus 为 true。同一父级内切换后代不会产生假 blur；候选提交失败不发送候选焦点回调。退休 callback 随原有事件资源失效，不向新受体转交旧事件。
- Tab / Shift+Tab 按实际声明树的深度优先顺序移动，并在 Owner 根内循环；keyed 移动即时改变顺序。方向键先按 `focusProperties` 的 Requester，再按已发布的真实矩形搜索，同方向投影相交的候选优先，距离与声明顺序用于确定结果。
- `focusGroup` 优先在最内层组内做方向搜索，无合适目标后再逐层向外搜索。显式方向覆盖该规则；方向搜索不自动循环。
- Input 优先消费文本导航与编辑按键；Tab 交给通用焦点树。通用 clickable 的 Enter / Space 调用同一 onClick 事件槽。
- 焦点变化后从内到外以最小距离把受体滚入滚动祖先；变换使用同一 Modifier 坐标模型，滚动值通过标准事件槽回写 JS，再由后续成功帧发布几何。此程序化滚入不改变正在进行的 wheel/trackpad 会话落点。
- Lazy 的焦点和 pointer capture 项按稳定 key pin；滚动移出窗口不退休仍在编辑的 Input/IME 会话。Tab 按逻辑项顺序，列表沿主轴、网格按行与槽位继续方向搜索；尚未材料化的目标进入候选布局请求，成功发布后选该项首个或末个焦点受体。请求与 pins 在候选 Lazy 状态中按需复制，失败帧不转移焦点或改写成功帧索引。清空/转移焦点、释放 capture、删除 key 或更换节点代际均释放对应 pin。
- 焦点变化是离散事件，不合并。通过命令触发时先成功提交焦点状态，再把回调排入 message thread；`nextTick()` 不充当原生发布或焦点成功回执。

# 滚动输入

鼠标滚轮、触控板与系统惯性共享滚动会话：从初始命中确定滚动实例与轴，后续增量保持该落点，直到会话结束或取消。

- 会话开始时，沿初始命中的父链选择最近能消费该方向增量的滚动实例。同方向候选都阻塞时锁定最外层候选，避免后续反向增量扰动子容器。
- 交叉方向嵌套：按 delta 绝对值较大的轴选择，相等时选纵轴。主轴没有对应容器且另一轴有增量时才尝试另一轴；主轴已有容器但被边界阻塞时，不因次轴噪声改为另一方向滚动。
- 会话途中，指针移动、反向增量、到达边界与进入惯性阶段都不改变目标实例或轴，也不逐事件把剩余 delta 交给父容器。目标实例退休时取消会话。
- 有原生 phase 的输入按开始、结束与取消边界管理，接触阶段及其惯性保持同一落点；不能用静默超时提前切断仍在进行的触控板手势。无 phase 的普通滚轮按 300ms 静默间隔划分会话。
- Input 未消费的键盘 PageUp / PageDown / Home / End 交给当前焦点节点最近的可滚动祖先，使用一页视口距离或内容起止；仍通过 typed snapshot 回到 JS 状态，不提前改写已发布树。
- Lazy Arrangable自身就是滚动容器，不再叠加同方向 `verticalScroll` / `horizontalScroll`。

平台 adapter 保留精细位移、行与整页单位，再按滚动实例转换为 Arrange 逻辑距离。macOS 从 AppKit 原生事件取得 `phase` / `momentumPhase`，精细 `scrollingDelta` 使用逻辑 point，非精细值使用行单位；16 逻辑点是 Arrange 的默认行距，不是 AppKit 的系统默认。Windows 普通滚轮遵守 SPI 的纵向行数、横向字符数与整页设置；Precision Touchpad 通过 DirectManipulation 取得精细位移及接触、惯性阶段，当前 Windows 路径尚未完成实机验证。

保留小数位移，不设最小一步，不重复应用系统自然滚动方向，也不乘物理像素倍率。普通 Shift+纵向滚轮可转为横向输入，系统已产生横向增量时不再次转轴。系统惯性事件按同一会话消费，不额外生成惯性或平滑动画。

滚动交互期间，JS `ScrollState` 是声明式状态源，native 负责命中、消费、clamp 与回调派发：

```txt
JUCE wheel
-> Wheel InputIntent
-> C++ initial hit path / locked scroll session
-> C++ consume / clamp against compiled scroll semantics
-> invoke scroll EventSlot with typed snapshot
-> JS ScrollState update
-> Arrange 响应式 flush
-> native setModifier typed mutation
-> LayoutTree apply / ModifierCompiler / dirty attribution
-> FramePlan
```

native 不得通过 `SetProp("__arrangeVerticalScrollValue")` 或 `SetProp("__arrangeHorizontalScrollValue")` 直接写回滚动状态。滚动状态更新只能经由 event slot 回到 JS state，再由标准 `setModifier` payload 进入 LayoutTree。

滚动声明通过 QuickJS 直接读取 Modifier object，进入类型化描述并协调为原生 Modifier 实例。回调资源由注册表管理并被对应元素引用，不能通过 `__arrangeVerticalScrollEnabled`、`__arrangeVerticalScrollValue`、`__arrangeVerticalScrollEventSlot` 等 JS 层派生 prop 进入生产链路，也不能解析调试字符串决定行为。

native event callback 只能调用真实注册的 JS function。找不到真实 callback 或标准事件 prop 时，应视为无监听兴趣并跳过，不得根据 node id 与 kind 临时生成看似 valid 的假 slot。

# 回调与提交

事件在 message thread 进入 QuickJS。JS 回调中产生的状态变化先进入 batch，回调结束后统一 commit。

连续事件合并到 frame / 调度点后派发；离散事件回调结束后应完成必要的 JS microtask / Arrange 响应式冲刷，并把 native typed mutations 提交到 MutationTransaction queue。

native 交互触发 JS callback 后，如果 JS 产生 mounted batch 或增量 batch，必须进入 MutationTransaction queue，并 request frame planning。tree apply、layout 与 repaint intent 只能由 FramePlan / SceneFramePipeline 执行。不能只调用 callback 而遗漏回写后的 mutation，也不能在零散事件调用栈内绕过 FramePlan。

text input、IME、caret、selection 等 native editing state 的内部失效必须走 typed intent / invalidation，不得伪装成普通 prop。输入文本值本身仍可通过标准 model/value mutation 与 JS 事件回到声明式状态。

# 命中测试初始规则

- `zIndex` 影响绘制顺序和默认命中顺序。
- `clip` 默认裁剪绘制，不默认改变 bounds 命中。
- graphicsLayer 变换后的命中不能忽略。

# Transform 与命中

`graphicsLayer`、平移、缩放、旋转等 transform 会影响命中测试；hit-test 不能只看未变换 bounds。

# 无障碍

先以键盘可操作为目标：Tab / Shift+Tab 切换焦点，上下左右做基础方向导航，Enter / Space 激活，Escape 取消临时交互。

最小语义保留 `role`、`label`、`description`、`enabled`、`contentDescription`。完整语义树、讲述人联动和复杂 accessibility 系统先放后续。

# 暂缓细化

Canvas 的 DrawScope、缓存、失效与高频数据通路后续单独设计。

Input 的 IME、selection、cursor、copy/paste、undo/redo 可以继续细化，但底层方向固定为自绘文本编辑节点，不直接包 JUCE TextEditor；这些状态必须进入统一 text editing state 与 invalidation，不得作为 paint 或平台回调旁路状态。
