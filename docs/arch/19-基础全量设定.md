# 目的

这里冻结 Arrange 的基础公开设定。若与其他文档冲突，以本文件为准。

# 工程习惯：生产事实源

- 生产路径只认 typed protocol / typed props / native core model；debug JSON、日志文本、测试快照不得反向成为生产事实源。
- 同一 prop 的解释必须走统一 `PropValue` / `EncodedProp` 或后续等价入口；禁止 Layout / Paint / HitTest / Scroll / Input 各自私写 parser。
- 新增生产能力必须先回答：typed 字段、native model 字段、统一解码入口、是否不依赖 debug JSON、影响哪些阶段、测试在哪里。
- 基础链路未进入明确兼容期前，不接受“迁移中间态”作为生产代码理由；不得用临时 JSON body 中转、legacy fallback 或 debug fallback 支撑生产语义。
- 测试与 gate 必须防止事实源回流，尤其是 `modifierDebugJson`、ad-hoc prop parser 和文本几何重复估算。

# 基础类型

- `dp`：布局单位，直接对应 JUCE 逻辑坐标。
- `sp`：文本单位，默认接近 `dp`，用于字号与文本缩放。
- `px`：物理像素单位，对应物理屏幕像素，不经过系统和 JUCE 的缩放处理。
- `Color(0xAARRGGBB)`：颜色主写法。
- `Alignment` / `Arrangement`：对齐与排列。
- `rounded(...)`：常用圆角形状。

# App 模型

- 用户写标准 Node/Vite/Vue 项目。
- `createApp(...).mount()` 是入口。
- 不是裸 SFC 直接实例化。
- 正式 authoring 只走 Vue SFC / Vue render function + Vue custom renderer。
- `@arrange/runtime` 不公开自研 `h` 作为主 API；测试 helper 应放到 test/internal。
- `class` / `style` / `<style>` 不参与渲染。
- `div` / `span` / 原生 `input` / 原生 `canvas` 不是默认 DOM 语义。

# C++ App source

- `config.app.useLive()` 使用默认 `http://127.0.0.1:9178`。
- `config.app.useLive(url)` 使用自定义 dev server。
- `config.app.useDist()` 使用默认 `ui/` 产物包目录。
- `config.app.useDist(path)` 使用显式 dist 包目录。
- Debug 推荐 live + dist，按 live-first fallback 到 dist。
- Release 推荐只配置 dist。
- 未配置任何 source 时必须进入错误屏并给出明确诊断。

# 组件总则

- 组件只表达 Arrange 语义，不表达 DOM 语义。
- 所有组件都可受 `modifier` 影响。
- 组件默认参数要好用，用户先从简单参数开始，再逐步深入。
- 组件行为必须稳定、可测、可诊断。
- 核心内建组件无风格化或只有最低可用默认样式。
- Arrange 核心不绑定任何设计系统。

# 主题层

主题层沿用 Vue `provide/inject`，不重新发明一层树作用域上下文。

# 布局总则

- 遵循 `Constraints -> measure -> place -> draw`。
- 不采用 `margin` / `display` / `box model`。
- 仅允许明确的布局节点：`Box`、`Row`、`Column`、`Spacer`、`FlowRow`、`FlowColumn`、`Lazy*`。
- `IntrinsicSize` 与固有尺寸查询可用。
- `Text` 必须提供 baseline。
- 生产布局、绘制、命中、文本测量事实源在 C++ `arrange_core`，TS runtime 不维护第二套生产 engine。

# Modifier 总则

- Modifier 是顺序敏感的洋葱模型。
- runtime 必须发出 ordered typed modifier props；native 生产路径不得依赖 `modifierDebugJson`。
- `padding`、`background`、`border`、`clip`、`shadow`、`transform`、`clickable`、`focusable`、`pointerInput` 都是 Modifier。
- `align`、`weight`、`matchParentSize` 属于父布局数据。
- `graphicsLayer`、平移、缩放、旋转都要影响命中测试。
- `fillMax*`、`wrapContent*`、`required*`、`widthIn/heightIn/sizeIn` 都可用。

# Text

- `Text` 只显示，不输入。
- C++ 侧负责测量、换行、intrinsic、baseline、缓存与绘制。
- `maxLines == 0` 表示不限行并可按宽度换行；`maxLines == 1` 才表示单行。
- 用户优先只需设置字号、字重、颜色、对齐等基础参数。
- 默认可为 14sp 黑字等最低可用样式。
- `AnnotatedString` 可作为文本注解数据结构，但核心不内建 Link 等固定样式。
- 区段样式、链接样式、点击行为由用户或扩展包决定。

# Input

- `Input` 是自绘文本编辑节点。
- 通过 `ArrangeEditor` 对接 JUCE 文本输入能力。
- 支持 `v-model` 便捷层，也支持 `InputState` 完整层。
- `commitMode` 控制何时提交：`change`、`blur`、`submit`。
- 支持选区、光标、IME、复制粘贴、撤销重做的基础能力。
- 文本绘制、光标、选区、IME bounds、点击定位与长文本 viewport 必须共用 `TextLayoutService` 坐标系。
- 不直接把 JUCE `TextEditor` 塞进树里。

# Canvas

- `Canvas` 是自定义绘制节点。
- 默认采用 retained display list 思路。
- `onDraw` 不是每次 paint 都重新跑。
- 失效由数据变更、尺寸变更、动画驱动、手动 invalidate 触发。
- `invalidation` 分为 `auto`、`manual`、`frame`。
- Canvas 默认不绑定专门高频数据源，后续再扩展。

# 其他内建组件

- `Image`：位图或资源图片。
- `Icon`：小型符号或矢量图形。
- `FlowRow` / `FlowColumn`：普通流式布局。
- `LazyColumn` / `LazyRow` / `LazyVerticalGrid` / `LazyHorizontalGrid`：大规模列表与网格。

# Bridge

- 生产通信不采用 JSON。
- 使用简明 command buffer / handle / opcode。
- 一个 flush 是一个 batch。
- 只传变化，不传整树。
- JSON 仅用于 debug 镜像、trace、诊断与测试快照。
- callback、scroll、text style、input、resource、focus / hover / pointer interest 等生产语义必须进入 typed 字段或 native model。

# FrameClock / 动画

- JS runtime 负责动画语义、easing、插值、取消、重启和 Vue 生命周期。
- native host 负责 monotonic time、frame cadence、timer lifecycle 与 repaint scheduling。
- QuickJS host 必须提供 host `requestAnimationFrame` / `cancelAnimationFrame` / `performance.now` 或等价能力。
- Promise / microtask 不承担 frame 语义，不能用来伪造动画逐帧刷新。
- 每个动画 tick 必须能走完整链路：RAF callback -> Vue update -> Bridge 增量 -> RenderTree dirty -> Layout / PaintModel -> repaint。
- Canvas `frame` invalidation 与未来 UI-thread 高频显示复用同一 FrameClock。

# 开发期诊断表层

- Arrange 在正式 DevTools 前先提供最小开发期诊断表层：Debug/Release 状态 badge、Standalone 标题栏状态、错误屏、结构化日志与必要 overlay toast。
- 诊断表层由 `ArrangeEditor` / `arrange_juce` 托管，不进入用户 App tree，不参与用户 layout、zIndex、focus、hover 或 pointer 语义。
- 诊断数据必须先进入统一 `DiagnosticEvent` / `DiagnosticsState`，再分别渲染到 badge、错误屏、toast 与日志；不能各自临时拼状态。
- badge 和 toast 默认不拦截鼠标事件；错误屏是独占界面，可接收 Retry / Copy diagnostics。
- Debug 默认显示 badge/toast 与详细错误；Release 默认隐藏 badge/toast，错误屏保持克制但支持复制诊断。
- 用户通过 `EditorConfig.diagnostics` 与开发期环境变量控制诊断显示、日志级别和日志文件。具体实现、样式、行为、默认值与未来 DevTools 边界见 `docs/arch/25-开发期诊断表层.md`。

# 交互

- 离散事件立即派发。
- 连续事件默认合并。
- pointer capture、focus、无障碍语义要单独建模。
- `clickable` 不等于把所有鼠标事件交给 JS。
- `hoverable`、`focusable`、`scrollable` 等高级语义尽量由 C++ 识别。

# 无障碍

先保证基础键盘可操作：

- Tab / Shift+Tab 切换焦点。
- 上下左右做基础方向导航。
- Enter / Space 触发激活。
- Escape 取消临时交互。
- Input 获焦后接管文本输入。

最小语义只保留：

- `role`
- `label`
- `description`
- `enabled`
- `contentDescription`

完整语义树、讲述人联动和复杂 accessibility 系统先不进核心基础设定。

# 主题与上下文

- Arrange 核心不绑定设计系统。
- 用户主题系统优先沿用 Vue `provide/inject`。
- 核心不重新发明 CompositionLocal。
- 可通过 provide/inject 传递 colors、typography、spacing、shapes、density、locale 等 token。
- 官方设计系统、官方音频组件包未来作为扩展包提供，不耦合核心。

# 加载与产物

- 一个目录/包就是一个 UI 产物包。
- 默认产物包目录是 `ui/`。
- 不要求 manifest。
- 入口默认是 `app.mjs`。
- 资源引用走 Vite 的 ESM import 或 `new URL(..., import.meta.url)`。

# 互操作

- `useParameter` 读参数不产生 gesture。
- 单次设置自动 complete gesture。
- 连续编辑自动 begin/set/end。
- `useHost` / `useTransport` 读取宿主信息。
- 音频线程不直接碰 JS。
