# 外部消费入口

## @arrange/framework

用户唯一 npm 包。提供 `createApp`、Arrange Vue authoring API re-export、内建组件、Modifier、基础类型、动画 API、interop hooks、HMR runtime client、开发命令与构建命令。

## Arrange::framework

用户唯一 native target。包含 core、QuickJS-NG 接入与 JUCE 接入。

# JS 内部包

## @arrange/runtime

内部运行时与 authoring API 实现包。它不作为用户安装入口。

## @arrange/vite-plugin

内部开发与构建工具包。负责默认 dev server、HMR adapter、Arrange Vue SFC 编译入口、无 HTML 的 App bundle、资源产物处理、Arrange host target 诊断。

## create-arrange

可选脚手架。用于生成标准 UI 源码项目。

## @arrange/vue-*

Arrange Vue fork / specialization 包族。负责 compiler-core、compiler-sfc、runtime-core、reactivity 与 shared 基础能力的 Arrange host target 改造。

职责：host component lowering、phase-aware reactivity、Reactive Slot Runtime、JS Value Phase scheduler。

Arrange Vue 以 Vue 3.5.34 为 fork point；自此不再跟随官方主线版本演进，后续只按 Arrange 的 host target、phase-aware reactivity 与 runtime 需求独立维护。

若官方主线未来有写法（SFC、模板语法等）上的 Breaking Change，我们会按需引进/复刻。但 Arrange Vue 的内部实现按 Arrange 自己的 host target 演进。

# C++ 内部模块

## arrange_core

纯核心：scene state、layout tree / layout node、测量与布局、Modifier typed decode / compile、样式类型、dirty attribution、invalidation graph、hit test、DrawOps build。

## arrange_quickjs

JS 宿主：QuickJS runtime/context、模块加载、JS/C++ binding、event slot registry、slot update binding、生命周期。

## arrange_juce

JUCE 适配：

- `ArrangeEditor` 托管宿主生命周期、平台事件采样、VBlankSource 接入与 passive paint 转发。
- `EditorSceneHost` 承担 JUCE editor 内部 scene host / composition root 职责。
- `ArrangeRuntime` / `SceneRuntime` 统一接收 intent、event、transaction，驱动 FramePlan 与 frame phases，不负责 JUCE 绘制。
- `FramePlanner` 生成 FramePlan 并记录阶段执行 / 跳过 / fallback 原因。
- `SceneFramePipeline` / `FramePipeline` 执行 apply、measure、layout、DrawOps build、hit-test build、diagnostics build 与 publish frame，不是单纯 render helper。
- `RuntimePackageLoader` 负责 live/dist 包加载，不参与 frame planning。
- package binder、session、action、chrome、input、diagnostics 等对象只能作为 intent producer、state owner、adapter 或 view builder，不得成为第二调度中心。
- native event callback adapter 负责 native event slot 到 QuickJS callback 的调用边界。
- `JuceDrawOpsPainter` 只执行 DrawOps 到 JUCE Graphics 的平台绘制。
- `JuceTextServices` 提供平台文本测量。
- 文本输入相关对象持有 text editing state / caret / selection / IME bounds，并通过 typed invalidation 进入 FramePlan。
- `ImageResourceCache` 解析/缓存包内图片。
- `DiagnosticsScene` 负责开发期诊断视图构建并复用 core pipeline。

## arrange_audio / interop

音频互操作：参数绑定、APVTS adapter、host transport、meter/event adapter。可先并入 `arrange_juce`，边界保持独立。

# 运行时

职责：承接 Arrange Vue compiler / runtime 结果，产生 Composition mutations、Reactive slot updates 与 typed runtime state change。

不负责：JUCE 绘制、音频参数底层实现、平台输入细节，也不绕过 FramePlan 直接执行三件套。

# QuickJS 宿主

职责：启动脚本运行时、加载模块、暴露最小绑定、管理生命周期。

不负责：布局算法、绘制细节、业务组件语义。

# Native boundary

职责：定义脚本世界如何表达创建、更新、删除、事件回调与 reactive slot update。

不负责：把所有对象互相暴露成一团，也不能在生产中使用任何 JSON mirror、二进制 buffer 或任意 object serializer。QuickJS 同进程对象只能由明确 JSValue reader 读取并落到 typed native transaction / typed slot update。

# 核心布局

职责：约束、测量、放置、Modifier 链、dirty attribution、失效传播、DrawOps build 所需结构状态。

不负责：SFC 语法、热更新连接、音频处理。

# JUCE 适配

职责：`ArrangeEditor` 托管、输入 adapter、VBlankSource adapter、被动绘制转发；绘制、资源、诊断、输入会话按子模块聚合而非八股拆碎。

不负责：理解 Vue 逻辑组件、保存 UI 业务状态、绕过 intent / FramePlan 执行输出阶段，也不把诊断表层混入用户 App layout。

# 热更新

职责：连接开发服务器、接收更新、触发运行时重载。

不负责：核心布局算法、音频线程通信、发布资源打包策略。

# 错误屏

职责：承接加载、运行、热更新和协议错误，并提供重试。

不负责：吞掉错误或替用户修复业务逻辑。
