# 宿主模型

JUCE 侧主入口是 `ArrangeEditor`。它托管 Arrange scene host，由 Arrange 内部完成输入归一、状态变更、布局、绘制准备与事件处理。

# JUCE 知道什么

- Editor / 画布尺寸。
- 绘制回调。
- 鼠标与键盘事件。
- 来自 FramePlan / PublishedFrame 的被动重绘请求。

# JUCE 不知道什么

- SFA、逻辑Arrangable。
- 模板结构。
- 响应式状态。

# 职责

`arrange_core::DrawOpsBuilder` 把 layout tree / scene state 收敛为平台无关、不可变的绘制片段。`arrange_juce::JuceDrawOpsPainter` 直接重放 PublishedFrame 保留的片段与附属 DrawOps，直接使用 Painter 快照持有的已解码绘制内容。JUCE 平台事件进入 Arrange 后，先转换为 InputIntent，再由 Arrange 完成命中测试、语义处理、dirty attribution 与 FramePlan。

# 原则

JUCE 是舞台，不是导演。用户不需要接触内部 scene host、VBlankSource adapter 或 pipeline 细节。JUCE `paint()` 只读取 PublishedFrame 并绘制，不执行状态迁移、布局或 DrawOps 构建。

# 片段发布与重放

正式场景以 `PlacedPaintFragment` 发布：不可变 `PaintFragment` 保存本层命令、共享内容及子片段引用，位置保存在引用边。每个 Modifier 层构成完整的 before/content/after 状态作用域；节点内容与 Modifier 命令使用各自局部坐标。滚动、放置和 graphics transform 更新引用或相应层，稳定内容命令无需逐条改写。文字资源契约见 [文本输入与绘制](18-文本输入与绘制.md)。

`SceneFramePipeline` 不把片段树强制展平为完整 DrawOps 数组。诊断/测试的 `exportDrawOps` 与 `exportScene` 从同一片段模型遍历导出，导出副本不参与正式重放。后端只读取 PublishedFrame，不到可变 LayoutTree 补几何。用户场景、输入覆盖层、诊断页、badge、toast 的层次保持既有顺序。

Modifier 的透明度沿作用域相乘，按既有逐操作透明度语义提交；这不等于离屏整层合成。可见性优化不得改变半透明叠加结果。候选资源、片段和命中快照遵守 [统一发布与失败边界](26-调度线程与帧阶段.md)。

# 保守可见性剔除

每个绘制操作提供保守绘制边界：文本使用真实字形边界与对齐，文本自裁剪/输入 viewport 按本身区域限定；线条与描边包含线宽和保守边缘。普通节点的布局矩形不能替代全部绘制影响。片段边界合并自身内容和子片段，按所在 Modifier 变换投影，坐标系明确属于片段入口。边界与片段一起不可变发布。

重放有两级剔除：先判断完整片段是否在有效裁剪区外，确定不可见时不访问内部 DrawOps；局部可见时逐操作判断。操作判断使用当时 JUCE clip/transform 状态，包括祖先、scroll viewport 和宿主 clip。浮点边界向外扩展并向外取整。状态操作始终成对执行；片段自成作用域，可整体跳过而不影响后继片段。

`overflow: visible`、溢出的子节点及外扩效果必须计入边界。未知边界向祖先传播为不可可靠剔除；无法可靠转换的极端坐标同样保留绘制。非矩形裁剪允许保守多画，不允许错误漏画。剔除只减少绘制，不冻结屏外状态、删除节点、退休事件或改变命中。

普通 scroll 仍进行必要测量、布局、协调与脏状态传播；约束和内容稳定时复用测量、文本和绘制片段。完整 editor repaint 仍可请求。Lazy、脏区域合并、位图缓存、遮挡剔除与线程拆分属于独立能力。

实际计数区分内容命令新建/复用、片段新建/复用、片段访问/跳过、DrawOp 访问/跳过、文字实际提交及被动 paint。准备、排版、glyph 提交与整体 paint 分别计时。同一重放实现可关闭剔除进行图像对照，不能维护另一套旧 renderer 作为对照。
