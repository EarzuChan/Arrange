# 单位与 Density

`Dp`、`Sp`、`Px` 是 SFA 源码中的真实值壳，不是 number 类型别名。本文约定单位含义与真实数值参数；SFA 模板、脚本及独立 `.ts` 的写法边界见 [SFA 与模板写法](33-SFA与模板写法.md#sfa-与纯-typescript-的编译边界)。

| 单位 | 数值含义 | 转换职责 |
| --- | --- | --- |
| DP | 受 Density 影响的前端布局长度分量 | Layout 在依赖追踪中的值读取经 `Density.dpToPx` 转成 PX |
| SP | 受 Density 影响的前端字号及行高 | Layout 在依赖追踪中的值读取经 `Density.spToPx` 转成 PX |
| PX | 绘制器原生像素分量 | 直接传递，当前是 JUCE 逻辑像素 |

Arrange 不接管 JUCE 的设备像素缩放。故确切来说，PX 不一定是当前显示器的物理像素，而是我们交给 JUCE 侧的 JUCE-MANAGED PX。

接受 DP 或 PX 的长度 API 使用致密双通道 `(dp, px)`，因此一个长度可以混合单位：`114.dp + 514.px` 编译为 `width(114, 514)`，Layout 最后求 `density.dpToPx(dp) + px`。尺寸、间距、Padding、布局 offset、圆角和边框宽度属于这类长度。后端约束、测量结果、滚动位置和范围、命中及 IME 坐标、graphicsLayer 平移只接受 PX。比例、权重、数量、时间等保留各自意义，不当作长度。Painter 固有尺寸属于后端坐标，图像源像素适配不是 Density 转换。

长度表达式允许加减以及与无量纲数字相乘或相除；不允许长度乘长度、长度作除数或 DP/SP 混算。编译器会先合并同类项，例如 `1919.px + 114.dp * 2 + 810.px` 交付 `(228, 2729)`，不会在编译期读取 Density。

`Density` 与 `createDensity(dpScale = 1, spScale = 1)` 由 `@arrange/framework/ui` 导出。DP/SP 倍率独立且响应式；`dpToPx`、`spToPx`、`pxToDp`、`pxToSp` 明确表达方向，不提供猜测单位的 `toPx(number)`。默认 1∶1 也执行正式转换。

App 创建 provides 后立即注册默认 Density；用户 `app.provide(DensityKey, density)` 与局部 `provide` 沿既有上下文链覆盖。消费者注入环境对象后读取其响应式配置；替换 provides 中的对象不使既有实例重新注入。Density 不是主题，不改变 Foundation 的 styleless 约束。

Layout 独立解析自己的 Modifier 与 MeasurePolicy，不修改共享声明，不在构造 Modifier 时转换。解析在受追踪的值读取中进行，原生写入只消费 PX 输入；同一声明可被不同 Density 的 Layout 复用。只依赖 PX 的值不订阅倍率，等价结果不重复提交，停用恢复读取最新环境，失败仍保留旧帧。

编译后的数字在正式参数位置仍保留 DP、SP 或 PX 的意义；拆箱不承担 Density 转换。编译规则见 [SFA 与模板写法](33-SFA与模板写法.md#单位值编译)。

以下 `sfa` 代码块展示 SFA 脚本或模板绑定表达式片段；`ts` 代码块展示真实 TypeScript 声明或调用。

# 颜色

颜色 API 对齐 Compose：

```sfa
Color(0xFF000000) // 依次为透明度、红、绿、蓝通道
Color(0x00000000) // 这样则全透明
// 只传 0xFFFFFF 会导致透明度为零
Color({ red, green, blue, alpha }) // 使用0-1的浮点值
Color.hsl(hue, saturation, lightness, alpha) // 色相使用角度；其余参数为0..1，透明度可省略
```

主格式固定为 `0xAARRGGBB`。

颜色在运行期始终是 uint32 ARGB 数字，不保留颜色值对象或颜色转换 helper。SFA 构造及转换见 [SFA 与模板写法](33-SFA与模板写法.md#单位值编译)；真实 TS API 直接传 ARGB 数字。未指定颜色使用省略的字段，与透明色区分；基础呈现见 [内建 Arrangable](12-内建Arrangable.md)。

ARGB 输入必须是 0..0xffffffff 的有限整数，不通过位运算默默截断小数或越界值。`solidColor`、`colorToHex` 和颜色动画在各自入口校验，原生绘制事务仍独立拒绝非法输入。HSL 色相按 360° 周期归一化，饱和度、亮度及透明度范围为 0..1。

当前 Shape 支持矩形、圆和统一半径圆角；Brush 支持纯色。分角圆角、渐变属于后续设计，目前没有公开实现。

# Alignment

```ts
Alignment.TopStart
Alignment.TopCenter
Alignment.TopEnd
Alignment.CenterStart
Alignment.Center
Alignment.CenterEnd
Alignment.BottomStart
Alignment.BottomCenter
Alignment.BottomEnd

Alignment.Start
Alignment.CenterHorizontally
Alignment.End

Alignment.Top
Alignment.CenterVertically
Alignment.Bottom
Alignment.Baseline
```

`BoxAlignment` 是九种二维对齐；`HorizontalAlignment` 是 Start/Center/CenterHorizontally/End，`VerticalAlignment` 是 Top/Center/CenterVertically/Bottom。Baseline 用于 Row 子项的基线对齐。`ImageAlignment` 接受二维与单轴对齐，不含 Baseline；`AlignmentValue` 是 Modifier 使用的完整集合。

`ContentScaleValue` 为 Fit/Crop/FillBounds/Inside/None/FillWidth/FillHeight。`TextAlignment` 接受 left/start/Start、center/Center、right/end/End，分别表达左、中、右对齐。

# Arrangement

```sfa
Arrangement.Start
Arrangement.Center
Arrangement.End
Arrangement.Top
Arrangement.Bottom
Arrangement.SpaceBetween
Arrangement.SpaceAround
Arrangement.SpaceEvenly
Arrangement.spacedBy(8.dp)
Arrangement.spacedBy(8.dp, Alignment.Center)
```

`HorizontalArrangementProp` 使用 Start/Center/End 和三种 Space 排列；`VerticalArrangementProp` 使用 Top/Center/Bottom 和三种 Space 排列。`spacedBy` 的可选 alignment 必须属于对应轴的 Alignment，默认从主轴起点放置。

# TextStyle

```ts
interface TextStyleProp {
    fontSize?: number // 字号使用排版单位
    color?: number // 颜色使用四通道无符号整数
    lineHeight?: number // 行高使用排版单位
}
```

Text 的 prop 与文本 Modifier 选项使用 `style`，Input 与 TextFieldOptions 使用 `textStyle`；类型名称仍为 TextStyleProp。字体族、字重、字形与字距是尚未实现的能力，不进入当前公开类型或原生 schema。

上述是纯 `.ts` 的声明类型，字号及行高数字表示 SP，颜色数字表示 ARGB；对应的 SFA 源码写法见 [SFA 与模板写法](33-SFA与模板写法.md#单位值编译)。
