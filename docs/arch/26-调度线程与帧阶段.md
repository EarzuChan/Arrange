# 调度线程与帧阶段

本文是 Arrange UI runtime 的调度、线程归属、输入归一、帧计划与输出阶段母文档。历史背景见 [ADR 004](../adr/004-UIOwner线程与帧阶段调度.md)、[ADR 005](../adr/005-M1正规化链路与事件槽事务模型.md) 与 [ADR 006](../adr/006-第二期正规化统一输入状态与帧计划.md)。

# 核心模型

Arrange 使用单 UI Owner 线程模型。默认 UI owner 是 JUCE message thread。

UI owner 拥有：

```txt
QuickJS runtime / context
Vue App instance 与 reactive flush
QuickJS native transaction 捕获与 MutationTransaction queue
InputIntent queue / RuntimeStore
NativeScene 或 NativeSceneState / LayoutTree
MeasureAndLayoutEngine / TextLayoutService / DrawOpsBuilder
InvalidationGraph / FramePlan / PublishedFrame
输入、滚动、focus、hover、pressed、IME 等 UI 状态
JUCE Component 输入回调、timer 回调与 paint 回调
```

Arrange 不把 JS、layout tree 或布局系统拆到彼此并行的 OS 线程。辅助线程只能生产不可变事件或结果，并 post 回 UI owner。

# 统一输入模型

生产输入不允许直接决定输出阶段。所有生产输入必须先成为 `InputIntent` 或等价 typed event：

```txt
InputIntent
  JsCommit
  AnimationFrame
  Pointer
  Wheel
  Key
  TextInput
  ImeComposition
  Resize
  PackageLoad
  Reload
  HmrReload
  ResourceReady
  DiagnosticsEvent
```

允许离散输入立即进入语义处理或 JS callback，但“立即”只表示交互边界不被 frame 合并，不表示可以绕过 intent、state、transaction、dirty 或 FramePlan。

合法生产链路是：

```txt
Input
-> InputIntent
-> RuntimeStore / MutationTransaction
-> InvalidationGraph
-> FramePlan
-> SceneFramePipeline
-> PublishedFrame
-> PassivePaint
```

输入 adapter、package binder、diagnostics 入口和 runtime session 入口只能产生 intent、typed state change 或 transaction，不得直接 measure、layout、build DrawOps、清 dirty 或 request repaint。

# RuntimeStore 与 native-first 状态

JS / Vue composition 产生的界面树变化进入 `MutationTransaction`。native-first 状态允许存在，但必须纳入统一 store 与 invalidation：

- scroll value / viewport / content size。
- focus / hover / pressed / pointer capture。
- text editing、caret、selection、IME composition。
- diagnostics state。
- resource ready / failed state。

native-first 状态更新后必须产出 typed invalidation。它不得作为零散 prop hack、局部 repaint shortcut 或 paint 内临时判断存在。

native internal invalidation 不能伪装成普通 prop。例如 text input 的 caret、selection、IME composition、overlay paint state 等内部状态变化，必须通过 `InputIntent`、RuntimeStore reduction、明确 dirty API 或等价 typed native invalidation 进入 `InvalidationGraph`。严禁把 magic key 当作普通声明 prop 发送给 `LayoutTree`。

# 主 FrameClock

FrameClock 由 native host 提供，负责单调时间、帧节奏、RAF 推进、frame invalidation 与 repaint 调度。

当 native peer 与平台能力可用时，FrameClock 应优先使用 vblank / display-frame 机制。无 native peer、平台能力不可用或只存在 dev reload / diagnostics 等维护 tick 时，JUCE timer 可作为 fallback。FrameClock 的线程归属仍是 UI owner。

dev reload、diagnostics toast 等维护性 tick 不是显示帧语义；它们可以和 frame tick 共享宿主入口，但不得把 `paint` 或 SceneFramePipeline 变成随处可调用的业务入口。

FrameClock 驱动输入 drain、JS Composition Phase 与 FramePlan 生成：

```txt
InputIntent drain
JS Composition Phase
FramePlan / SceneFramePipeline
```

它们不是互相竞争的线程或计时器，而是同一 UI owner 上的顺序阶段。

# JS Composition Phase

JS Composition Phase 负责让 JS / Vue 世界达到稳定，并提交界面变更意图。

输入来源包括：

- native 输入事件派发到 JS callback。
- `requestAnimationFrame` callback。
- HMR / reload 等 UI 事件。
- 互操作层从 message thread 派发到 JS 的事件。
- 初次 mount、reload 或 HMR reload 后的新 App 执行。

阶段内执行：

```txt
deliver JS callbacks / RAF callbacks
-> drain 当前必须完成的 JS microtasks
-> Vue reactive flush / renderer patch
-> native transaction API 捕获 typed mutations
-> mutations 追加到 MutationTransaction queue
```

native transaction 提交只提交意图，不直接 apply layout tree，不执行 measure / layout / draw，不直接 repaint。

# MutationTransaction queue

`MutationTransaction` queue 是 JS Composition Phase 与 SceneFramePipeline 的边界。

规则：

- 同一 frame 或同一调度边界内多次 native transaction 提交应合并为 transaction 或按顺序进入 transaction queue。
- transaction 中保存 tree mutations、event slot updates、retired event slots，以及后续资源/dirty 意图。
- reload、unmount、错误恢复、source 切换、QuickJS context reset 必须清空旧 App 的 pending transactions 与 RAF callbacks。
- 初次 mount 和 reload 产生的 mount transaction 也进入同一 queue。实现可以为了启动体验在同一 UI owner 调度轮次内立即请求 frame plan，但不得绕过 SceneFramePipeline 的 apply / measure / layout 边界。
- queue 只能由 UI owner 访问。

# FramePlan

`FramePlan` 是输出阶段的唯一计划。它由 `FramePlanner` 根据 pending intent、MutationTransaction queue、RuntimeStore state、dirty attribution 与 frame clock 状态生成。

`FramePlan` 至少表达：

```txt
drainComposition
applyMutations
measure
layout / place
buildPaint
buildHitTest
buildDiagnostics
publishFrame
passivePaint
fullRepaint
```

要求：

- 每个阶段执行或跳过都必须能说明原因。
- full repaint / full layout 只能作为显式 fallback，并携带 fallback reason。
- controller、input adapter、diagnostics、package load、reload、resize 不得自行决定三件套执行。
- `waitForIdle` 以 FramePlan 无待处理阶段为准，而不是只看 JS idle。

Modifier diff、event slot 替换与 native-first state change 都必须能产出明确 dirty attribution。event slot dirty 应来自真实 event slot / input / scroll 字段比较；再不能用“其它 dirty 为 0 时保底标 event dirty”。纯 callback 替换不得无理由触发 measure、layout 或 paint。

# SceneFramePipeline

`SceneFramePipeline` 是生产输出阶段入口。它可以是聚合对象，但必须显式执行阶段，而不是黑盒 `run(...)`。

阶段内执行：

```txt
consume FramePlan
-> applyTransactions
-> resolveInvalidation
-> measureIfNeeded
-> layoutIfNeeded
-> buildPaintIfNeeded
-> buildHitTestIfNeeded
-> buildDiagnosticsIfNeeded
-> publishFrame
```

tree apply、measure、layout / place、DrawOps 构建、hit-test rebuild、diagnostics build 与 publish frame 应收敛到 SceneFramePipeline。输入、滚动、动画、resize、HMR、错误恢复等来源只产生 intent、typed state change、transaction 或 dirty。

无法证明局部 repaint 边界正确时，FramePlan 可以选择 full repaint。正确性优先于局部优化，但 full fallback 必须有原因，不得作为默认偷懒路径。

# PublishedFrame

`PublishedFrame` 是 paint 可读取的唯一绘制快照。它应包含用户 scene 与诊断 scene 已准备好的 DrawOps / display list、必要的输入绘制状态和 repaint bounds。

`PublishedFrame` 必须区分两类生命周期：

- `content`：跨帧保留的已发布内容，例如用户 DrawOps、overlay DrawOps、diagnostics DrawOps、focused input paint state。
- `changes`：只描述当前帧的变化集，例如 changed flag、repaint bounds、overlay repaint bounds、diagnostics repaint bounds。

调用方必须显式读取 `content.*` 或 `changes.*`。核心结构不得长期依赖引用成员别名假装旧字段仍在顶层。

发布规则：

- publish 发生在 SceneFramePipeline 内。
- publish 后，JUCE `paint()` 只能读 PublishedFrame。
- 如果当前 frame 构建失败，应在 publish 前产出 error frame 或保留上一帧；paint 不负责运行时决策。

# JUCE paint

JUCE `paint` 属于 UI owner。

目标语义：

```txt
read PublishedFrame
draw prepared DrawOps / display list
```

`paint` 禁止探测 dev server、读取文件、执行 JS、触发 Vue flush、apply mutation、measure、layout、build DrawOps、设置 diagnostics error、切换 loaded 状态、清 dirty 或 request repaint。必要的绘制数据必须在 SceneFramePipeline 或安全的 UI owner state reduction 中准备。

# 输入事件

离散事件立即进入语义处理或 JS 回调：

- pointer down / up / cancel。
- key down / up。
- text input。
- focus / blur。
- gesture begin / end。

“立即”只表示交互边界不被 frame 合并，不表示 JS callback 后立即 apply / layout / draw。JS callback 造成的 UI 变更必须先进入 MutationTransaction queue，再由 SceneFramePipeline 消费。

连续事件可以合并到 frame 或调度点：

- pointer move。
- drag move。
- hover move。
- 高频 wheel / trackpad delta。

# RAF 与动画

`requestAnimationFrame` 由 FrameClock 推进。RAF callback 是 JS Composition Phase 的输入，不是布局入口。

```txt
native frame tick
-> deliver RAF callbacks
-> JS animation state update
-> Vue flush / renderer patch
-> native typed mutations 进入 MutationTransaction queue
-> FramePlan
-> SceneFramePipeline 消费 mutations 并 publish frame
```

Promise / microtask 不能承担 frame 语义。动画下一帧必须回到 native FrameClock。

# 线程边界

允许的辅助线程：

- HMR websocket / socket pump。
- 文件读取。
- 网络请求。
- 资源解码。
- 日志写入。

辅助线程只允许向 UI owner post 不可变事件或结果。禁止直接访问：

- QuickJS runtime / context。
- Vue App / reactive state。
- MutationTransaction queue。
- layout tree。
- MeasureAndLayoutEngine / TextLayoutService / DrawOpsBuilder。
- JUCE Component。
- 输入与诊断 UI 状态。

音频线程同样不得访问 UI runtime。音频高频数据应通过原子、环形队列或快照转移到 UI owner，由 FrameClock 消费。

# Idle 与测试

测试中的 idle 不只是 JS idle。`waitForIdle` 应表示：

```txt
JS Composition Phase 无待处理 callback / microtask
MutationTransaction queue 为空
RuntimeStore 无待 reduce intent
InvalidationGraph 无待消费 dirty
FramePlan 无待执行阶段
SceneFramePipeline 无待 publish frame
必要的 diagnostics scene / HMR 状态已稳定
```

可控 test clock 应能推进 RAF、batch flush、FramePlan 与 SceneFramePipeline。

常规回归应优先使用 deterministic runtime / QuickJS / native harness 测试。自动化屏幕点击、滚动、输入不作为常规正确性证据；真实 standalone GUI 点击、滚动、IME 留给人工阶段性验收。

# 不做

- 不为 QuickJS 建立独立 UI 线程作为首期目标。
- 不让辅助线程持有 UI 状态。
- 不把 layout 或文本测量搬到 JS。
- 不让 native transaction 提交成为隐式 layout 入口。
- 不在 paint 内执行加载、重组或文件 I/O。
- 不让任何 controller 绕过 InputIntent / FramePlan 直接驱动三件套。
