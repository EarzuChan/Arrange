# 调度线程与帧阶段

本文是 Arrange UI runtime 的调度、线程归属、输入归一、阶段化响应式、VBlankSource、帧计划与输出阶段母文档。历史背景见 [ADR 004](../adr/004-UIOwner线程与帧阶段调度.md)、[ADR 005](../adr/005-M1正规化链路与事件槽事务模型.md)、[ADR 006](../adr/006-第二期正规化统一输入状态与帧计划.md)、[ADR 009](../adr/009-ArrangeVue阶段化响应式与ReactiveSlotRuntime.md) 与 [ADR 010](../adr/010-生产视觉帧源收束为VBlankSource.md)。

# 核心模型

Arrange 使用单 UI Owner 线程模型。默认 UI owner 是 JUCE message thread。

UI owner 拥有：

```txt
QuickJS runtime / context
Arrange Vue App instance 与 phase-aware reactivity
Composition queues / JS Value Phase queues
QuickJS native transaction 捕获与 MutationTransaction queue
Reactive Slot Runtime / SlotUpdateBatch
InputIntent queue / RuntimeStore
NativeScene 或 NativeSceneState / LayoutTree
MeasureAndLayoutEngine / TextLayoutService / DrawOpsBuilder
InvalidationGraph / FramePlan / PublishedFrame
输入、滚动、focus、hover、pressed、IME 等 UI 状态
JUCE Component 输入回调、VBlank 回调与 paint 回调
```

Arrange 不把 JS、layout tree 或布局系统拆到彼此并行的 OS 线程。辅助线程只能生产不可变事件或结果，并 post 回 UI owner。

# 统一输入模型

生产输入不允许直接决定输出阶段。所有生产输入必须先成为 `InputIntent` 或等价 typed event：

```txt
InputIntent
  JsCommit
  ValueFrame
  AnimationFrame
  Pointer
  Wheel
  Key
  TextInput
  ImeComposition
  Resize
  PackageLoad
  Reload
  HmrReload
  ResourceReady
  DiagnosticsEvent
```

允许离散输入立即进入语义处理或 JS callback，但“立即”只表示交互边界不被 frame 合并，不表示可以绕过 intent、state、transaction、slot update、dirty 或 FramePlan。

合法生产链路是：

```txt
Input
-> InputIntent
-> RuntimeStore / MutationTransaction / SlotUpdateBatch
-> InvalidationGraph
-> FramePlan
-> SceneFramePipeline
-> PublishedFrame
-> PassivePaint
```

输入 adapter、package binder、diagnostics 入口和 runtime session 入口只能产生 intent、typed state change、transaction 或 slot update，不得直接 measure、layout、build DrawOps、清 dirty 或 request repaint。

# RuntimeStore 与 native-first 状态

JS / Arrange Vue composition 产生的结构和离散界面变化进入 `MutationTransaction`。UI value 变化进入 `SlotUpdateBatch`。native-first 状态允许存在，但必须纳入统一 store 与 invalidation：

- scroll value / viewport / content size。
- focus / hover / pressed / pointer capture。
- text editing、caret、selection、IME composition。
- diagnostics state。
- resource ready / failed state。

native-first 状态更新后必须产出 typed invalidation 或 typed slot update。它不得作为零散 prop hack、局部 repaint shortcut 或 paint 内临时判断存在。

# VBlankSource 与 FrameScheduler

生产视觉帧源只有 `JuceVBlankSource`。它由 JUCE `VBlankAttachment` 或等价 platform display-frame source 驱动。不同平台底层如何产生回调由 JUCE 与平台负责；Arrange 只把它视为 VBlankSource。

`VBlankReady` 是 visible UI runtime ready 的必要条件。没有 `VBlankReady` 时，runtime 可以加载 App、接收输入、HMR、resource ready 或 diagnostics event，并建立 pending `MutationTransaction` / `SlotUpdateBatch`；但不得推进 visual frame、JS Value Phase animation tick、SceneFramePipeline visual publish 或 repaint pump。

生产路径不存在 animation timer fallback、visual frame timer fallback、maintenance timer pretending to be frame 或 synthetic production frame source。

FrameScheduler 状态：

```txt
NoPeer
PeerAttached
VBlankReady
Running
Suspended
```

FrameScheduler 不产生帧源，也不拥有备用时钟。它只消费 `VBlankSource` 产生的 `VBlankTick`，并据此组织 Composition Phase、JS Value Phase、FramePlan 与 SceneFramePipeline。

VBlank tick 驱动：

```txt
InputIntent drain
Composition Phase if needed
JS Value Phase if needed
FramePlan / SceneFramePipeline
```

reload、HMR、diagnostics、resource ready 等非视觉事件只入队 work 或请求 visual frame；视觉输出等待 `VBlankReady` 后的 VBlank tick。`paint` 或 SceneFramePipeline 不得变成维护事件的直接业务入口。

# Composition Phase

Composition Phase 负责让 Arrange Vue 的结构和语义状态达到稳定，并提交离散界面变更意图。

输入来源包括：

- 初次 mount、reload 或 HMR reload 后的新 App 执行。
- native 输入事件派发到 JS callback 后产生的业务状态变化。
- 条件分支、列表、slots、dynamic component 等结构变化。
- props / emits / provide / inject 等 composition 语义。
- 互操作层从 message thread 派发到 JS 的事件。

阶段内执行：

```txt
deliver JS callbacks
-> drain 当前必须完成的 JS microtasks
-> Arrange Vue composition flush
-> host target lowering / renderer op
-> native transaction API 捕获 typed mutations
-> mutations 追加到 MutationTransaction queue
```

MutationTransaction 提交只提交意图，不直接 apply layout tree，不执行 measure / layout / draw，不直接 repaint。

# JS Value Phase

JS Value Phase 负责推进 UI value、动画、transition、computed UI value 与 reactive slot dirty。

输入来源包括：

- VBlankTick。
- animated refs / transitions。
- resource state 被 JS value 依赖消费。
- diagnostics value 更新。
- phase-aware dependency 中 layout / draw / event / resource slot 的变化。

阶段内执行：

```txt
advance animated refs / transitions
-> recompute dirty UI values
-> collect typed UI slot updates
-> append SlotUpdateBatch
```

JS Value Phase 不默认触发 component render、VNode diff 或 generic prop patch。它只对绑定到 layout、draw、event、resource 等 UI slot 的值生成 typed slot update。

# MutationTransaction queue

`MutationTransaction` queue 是 Composition Phase 与 SceneFramePipeline 的 typed 边界。

规则：

- 同一 frame 或同一调度边界内多次 native transaction 提交应合并为 transaction 或按顺序进入 transaction queue。
- transaction 中保存 tree mutations、text / prop / modifier mutations、event slot updates、retired event slots，以及后续资源/dirty 意图。
- reload、unmount、错误恢复、source 切换、QuickJS context reset 必须清空旧 App 的 pending transactions。
- 初次 mount 和 reload 产生的 mount transaction 也进入同一 queue。
- queue 只能由 UI owner 访问。

# SlotUpdateBatch

`SlotUpdateBatch` 是 Reactive Slot Runtime 与 SceneFramePipeline 的 typed 边界。

slot update 至少表达：

```txt
scene / node id
slot kind
field path
value kind
current typed value
dirty role
source / reason
```

典型 slot kind：

```txt
LayoutSlot
DrawSlot
TransformSlot
HitTestSlot
EventSlot
ResourceSlot
AccessibilitySlot
```

规则：

- slot update 不表达结构增删；结构变化使用 MutationTransaction。
- paint-only slot 不得触发布局。
- layout slot 必须进入必要 layout dirty，不得默认 full layout。
- event slot update 不得触发无理由 measure / layout / paint。
- reload、unmount、错误恢复、source 切换、QuickJS context reset 必须退休旧 App 的 slot binding 与 pending slot updates。
- SlotUpdateBatch 只能由 UI owner 访问。

# FramePlan

`FramePlan` 是输出阶段的唯一计划。它由 `FramePlanner` 根据 pending intent、MutationTransaction queue、SlotUpdateBatch、RuntimeStore state、dirty attribution 与 VBlankSource 状态生成。

`FramePlan` 至少表达：

```txt
drainComposition
runJsValuePhase
applyMutations
applySlotUpdates
measure
layout / place
buildPaint
buildHitTest
buildDiagnostics
publishFrame
passivePaint
fullRepaint
```

要求：

- 每个阶段执行或跳过都必须能说明原因。
- full repaint / full layout 只能作为显式 fallback，并携带 fallback reason。
- controller、input adapter、diagnostics、package load、reload、resize 不得自行决定三件套执行。
- `waitForIdle` 以 Composition、JS Value Phase、FramePlan 与 SceneFramePipeline 都稳定为准。

Modifier diff、prop schema、reactive slot update、event slot 替换与 native-first state change 都必须能产出明确 dirty attribution。纯 callback 替换不得无理由触发 measure、layout 或 paint。

# SceneFramePipeline

`SceneFramePipeline` 是生产输出阶段入口。它必须显式执行阶段，而不是黑盒 `run(...)`。

阶段内执行：

```txt
consume FramePlan
-> applyTransactions
-> applySlotUpdates
-> resolveInvalidation
-> measureIfNeeded
-> layoutIfNeeded
-> buildPaintIfNeeded
-> buildHitTestIfNeeded
-> buildDiagnosticsIfNeeded
-> publishFrame
```

tree apply、slot apply、measure、layout / place、DrawOps 构建、hit-test rebuild、diagnostics build 与 publish frame 应收敛到 SceneFramePipeline。输入、滚动、动画、resize、HMR、错误恢复等来源只产生 intent、typed state change、transaction、slot update 或 dirty。

无法证明局部 repaint 边界正确时，FramePlan 可以选择 full repaint。正确性优先于局部优化，但 full fallback 必须有原因，不得作为默认路径。

# PublishedFrame

`PublishedFrame` 是 paint 可读取的唯一绘制快照。它应包含用户 scene 与诊断 scene 已准备好的 DrawOps / display list、必要的输入绘制状态和 repaint bounds。

`PublishedFrame` 必须区分两类生命周期：

- `content`：跨帧保留的已发布内容，例如用户 DrawOps、overlay DrawOps、diagnostics DrawOps、focused input paint state。
- `changes`：只描述当前帧的变化集，例如 changed flag、repaint bounds、overlay repaint bounds、diagnostics repaint bounds。

调用方必须显式读取 `content.*` 或 `changes.*`。核心结构不得长期依赖引用成员别名假装旧字段仍在顶层。

发布规则：

- publish 发生在 SceneFramePipeline 内。
- publish 后，JUCE `paint()` 只能读 PublishedFrame。
- 如果当前 frame 构建失败，应在 publish 前产出 error frame 或保留上一帧；paint 不负责运行时决策。

# JUCE paint

JUCE `paint` 属于 UI owner。

目标语义：

```txt
read PublishedFrame
draw prepared DrawOps / display list
```

`paint` 禁止探测 dev server、读取文件、执行 JS、触发 Arrange Vue flush、apply mutation、apply slot update、measure、layout、build DrawOps、设置 diagnostics error、切换 loaded 状态、清 dirty 或 request repaint。必要的绘制数据必须在 SceneFramePipeline 或安全的 UI owner state reduction 中准备。

# 输入事件

离散事件立即进入语义处理或 JS 回调：

- pointer down / up / cancel。
- key down / up。
- text input。
- focus / blur。
- gesture begin / end。

“立即”只表示交互边界不被 frame 合并，不表示 JS callback 后立即 apply / layout / draw。JS callback 造成的 UI 变更必须先进入 RuntimeStore、MutationTransaction 或 SlotUpdateBatch，再由 SceneFramePipeline 消费。

连续事件可以合并到 frame 或调度点：

- pointer move。
- drag move。
- hover move。
- 高频 wheel / trackpad delta。

# 动画

动画由 VBlankSource 推进 JS Value Phase：

```txt
VBlank tick
-> JS Value Phase
-> animated refs / transitions advance
-> SlotUpdateBatch
-> FramePlan
-> SceneFramePipeline 消费 slot updates 并 publish frame
```

Promise / microtask、JS timer 或 production timer fallback 不能承担 frame 语义。动画下一帧必须回到 VBlankSource。动画过程值变化不得默认触发 component render、VNode diff 或 generic patchProp。

# 线程边界

允许的辅助线程：

- HMR websocket / socket pump。
- 文件读取。
- 网络请求。
- 资源解码。
- 日志写入。

辅助线程只允许向 UI owner post 不可变事件或结果。禁止直接访问：

- QuickJS runtime / context。
- Arrange Vue App / reactive state。
- MutationTransaction queue。
- SlotUpdateBatch。
- layout tree。
- MeasureAndLayoutEngine / TextLayoutService / DrawOpsBuilder。
- JUCE Component。
- 输入与诊断 UI 状态。

音频线程同样不得访问 UI runtime。音频高频数据应通过原子、环形队列或快照转移到 UI owner，由 VBlankSource 消费。

# Idle 与测试

测试中的 idle 不只是 JS idle。`waitForIdle` 应表示：

```txt
Composition Phase 无待处理 callback / microtask
JS Value Phase 无待推进 value
MutationTransaction queue 为空
SlotUpdateBatch 为空
RuntimeStore 无待 reduce intent
InvalidationGraph 无待消费 dirty
FramePlan 无待执行阶段
SceneFramePipeline 无待 publish frame
必要的 diagnostics scene / HMR 状态已稳定
```

测试 harness 可以注入 `ManualVBlankSource`。`ManualVBlankSource` 不是 timer，不自动推进时间，不后台 tick；它只在 native test harness 显式调用 `advanceFrame(timestamp)` 时，向同一条生产 FrameScheduler / FramePlan 路径注入一个 VBlank frame event。测试必须通过该手动 VBlank 事件推进 Composition Phase、JS Value Phase、FramePlan 与 SceneFramePipeline。

常规回归应优先使用 deterministic runtime / QuickJS / native harness 测试。自动化屏幕点击、滚动、输入不作为常规正确性证据；真实 standalone GUI 点击、滚动、IME 留给人工阶段性验收。

# 不做

- 不为 QuickJS 建立独立 UI 线程作为首期目标。
- 不让辅助线程持有 UI 状态。
- 不把 layout 或文本测量搬到 JS。
- 不让 native transaction 或 slot update 提交成为隐式 layout 入口。
- 不在生产路径引入 animation timer、visual frame timer 或 synthetic frame source。
- 不在 paint 内执行加载、重组、slot apply 或文件 I/O。
- 不让任何 controller 绕过 InputIntent / FramePlan 直接驱动三件套。
