# 目标

JS 侧需要感知、读取、设置 Arrange / JUCE / 插件 / 音频 / 宿主数据。C++ 侧需要向 UI 派发事件，但不能让音频线程触碰 JS。

# 基本原则

- JS 不接触音频线程。
- C++ 不向 JS 暴露裸指针。
- 跨界调用经过受控 native binding。
- 高频音频数据通过原子、队列或快照转到 message thread。

# 参数读取

```ts
const gain = useParameter("gain")

gain.value // 只读反应式值
gain.normalizedValue // 只读反应式标准化值
```

读取参数是反应式状态，不产生 host automation gesture。

# 参数一次性设置

```ts
gain.set(0.5)
gain.setNormalized(0.5)
```

一次性设置默认作为 complete gesture：内部等价于 begin、set、end 的完整用户操作。

# 参数连续编辑

连续拖拽需要 gesture 生命周期。

参数绑定组件或 helper 自动处理：

```txt
pointer down -> beginChangeGesture
pointer drag -> setValueNotifyingHost
pointer up/cancel -> endChangeGesture
```

高级自定义控件可使用：

```ts
const cutoff = useParameter("cutoff")
const drag = cutoff.gesture()

drag.begin()
drag.set(value)
drag.end()
```

# 专用组件

Slider、Knob、Meter 等可放入扩展包。参数编辑类组件必须自动管理 gesture，不能要求用户在 `v-model` 前后手写 begin/end。

# Host / transport

```ts
const host = useHost()
const transport = useTransport()

transport.playing
transport.bpm
transport.positionPpq
```

宿主不一定提供所有字段，JS API 应允许 nullable / optional。

# C++ 到 JS

C++ 可向 UI 派发事件：

```cpp
editor.emit("meter", payload);
```

音频线程不得直接调用 JS。正确路径：

```txt
audio thread -> atomic/ring buffer -> message thread drain -> QuickJS dispatch
```

# JS 到 C++

JS 通过 `@arrange/runtime` 暴露的 typed API 调用 C++ 能力。底层 native binding 隐藏在 runtime 内，不作为用户 API。
