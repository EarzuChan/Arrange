# 互操作

本文是 Arrange 与插件、宿主、音频世界之间数据往来的母文档：参数、宿主快照、音频观测流、消息与调用，以及它们的线程、批处理与生命周期规则。

# 目标与边界

Arrange 是音频产品的 UI 框架，TS 侧负责控制面与观察面：读写参数、联动多处界面、换预设、得知宿主与走带状态、观测电平、波形和频谱。

TS 侧不参与音频处理。QuickJS 运行在 UI owner（JUCE message thread）上，有 GC 停顿且没有实时保证，任何音频合成或逐样本处理都不进入 JS。

基本原则：

- JS 不接触音频线程；音频线程不调用 JS，也不等待 UI。
- C++ 不向 JS 暴露裸指针或宿主对象，JS 只看到 typed 值与受控函数。
- 跨界数据直接读写 JSValue，不经过 JSON、字符串或二进制序列化边界（见[开发约束](../proj/5：具体开发的额外约束.md)）。原生直接构造的 `Float32Array` 是 JS 值，不属于序列化边界。
- 音频线程到 UI 的数据只经原子量、无锁环形缓冲或三缓冲快照；UI owner 在语义检查点收取。
- 所有宿主来的变化都在语义检查点进入 JS，变为响应式状态，再按[调度与帧阶段](26-调度线程与帧阶段.md)的正常链路产生结构事务或 slot 更新。互操作不另开刷新通道。

# 四类数据流

| 类别 | 典型用途 | 方向 | 节奏 |
| :--- | :--- | :--- | :--- |
| 参数 | APVTS 参数、旋钮、自动化、预设切换后的值 | 双向，宿主可见 | 变化驱动，按检查点合并 |
| 宿主快照 | 宿主名、封装格式、采样率、走带 | 原生到 JS | 最新值，变化驱动；走带播放中按帧 |
| 音频观测流 | 电平表、波形、频谱 | 音频线程到 JS | 最新值，订阅期间按帧 |
| 消息与调用 | 预设管理、读写文件、自定义业务 | C++ 到 JS 的事件；JS 到 C++ 的调用 | 离散 |

预设与插件状态不另立机制：APVTS 等状态的存取由 C++ 负责，界面通过参数与调用完成联动。

# 原生侧

## Interop 对象

插件 processor 持有一个 `arrange::juce::Interop`，在 Editor 配置中交给界面：

```cpp
class MyProcessor : public juce::AudioProcessor {
    juce::AudioProcessorValueTreeState state;
    arrange::juce::Interop interop{*this};
    arrange::juce::Meter& outputMeter = interop.meter("output");
};

juce::AudioProcessorEditor* MyProcessor::createEditor() {
    arrange::juce::EditorConfig config;
    config.interop = &interop;
    return new arrange::juce::ArrangeEditor(*this, std::move(config));
}
```

`Interop` 的寿命跟随 processor，长于任何 Editor 与脚本会话。界面重载、HMR、Editor 关闭再打开都只是在同一 `Interop` 上换会话；同一时刻只有一个脚本会话连接，新会话接入时旧会话断开。

`Interop` 构造时登记 processor 的全部参数，参数须为 `juce::AudioProcessorParameterWithID`（APVTS 参数均满足），以 `paramID` 为 JS 侧的身份。参数在构造之后再增删属于未定义行为，JUCE 本身也不支持参数集合变化。

## 音频线程入口

音频线程只调用以下实时安全入口，它们不分配内存、不加锁、不投递消息、不调用 JS，数据只写原子量与无锁缓冲：

```cpp
void prepareToPlay(double sampleRate, int blockSize) override {
    interop.prepare(sampleRate, blockSize);
}

void processBlock(juce::AudioBuffer<float>& buffer, juce::MidiBuffer&) override {
    interop.process(getPlayHead());
    // ...
    outputMeter.push(buffer.getMagnitude(0, buffer.getNumSamples()));
}
```

- `prepare` 记录采样率与块大小。
- `process` 采样 `AudioPlayHead` 的走带信息写入原子快照。
- `Meter::push` 记录电平，UI 收取前保持峰值。
- `Waveform::push` 把样本写入单生产者环形缓冲。
- `Spectrum::publish` 发布一份定长数组（如 FFT 幅度），三缓冲交换，UI 总读到完整的最新一份。

音频线程只在状态边沿（走带启停、速度或拍号改变）置唤醒标记；连续变化（播放位置、电平、波形）由 UI 在订阅期间逐帧拉取。音频线程不向 message 队列投递任何消息：投递频率会跟随音频块与宿主行为，Windows 上投递消息优先于输入事件，持续投递会挤占宿主与插件窗口的交互。

## C++ 到 JS 的消息

```cpp
interop.emit("presetLoaded", arrange::juce::InteropValue::object({{"name", "Warm Pad"}}));
```

`emit` 只能在 message thread 调用，消息排队后在下一个语义检查点交给 JS。值类型为 `InteropValue`：null、布尔、数字、字符串、数组与字符串键对象，在边界上直接构造为 JSValue。

## JS 到 C++ 的调用

```cpp
interop.handle("savePreset", [this](const arrange::juce::InteropValue& args) {
    return arrange::juce::InteropValue(savePreset(args[0].asString()));
});

interop.handleAsync("scanPresets", [this](const arrange::juce::InteropValue&, arrange::juce::InteropReply reply) {
    // 可在后台完成后回到 message thread 再 reply
});
```

处理函数在 message thread 执行。同步处理函数立即得到结果；异步处理函数持有 `InteropReply`，在 message thread 调用一次 `resolve` 或 `reject`。JS 侧一律得到 Promise，结果在语义检查点交付。会话结束时未完成的调用被丢弃，迟到的 reply 不触达新会话。处理函数抛出的异常转为 Promise 拒绝。

# JS 侧

公开入口为 `@arrange/framework/interop`。各 API 须在宿主提供 Interop 时使用；未连接 Interop 的宿主上调用会明确报错。预览、测试夹具等没有插件宿主的场景用 `hasInterop()` 判断后降级。

## 参数即 ref

```ts
const gain = useParameter('gain')

gain.value             // 实际值（按参数范围反标准化），可读可写
gain.normalized        // 0..1 标准化值，可读可写
gain.text              // 宿主文本，如 "-6.0 dB"
gain.descriptor        // id、name、label、范围、步数、默认值等只读描述
```

`useParameter` 返回的对象像 ref 一样以属性读写并被依赖追踪，但它不是 ref 本身，模板中照常写 `gain.value`、`gain.text`。模板、computed、watch 中读取会被依赖追踪；宿主自动化、预设切换或其它界面的修改到达后，所有读取处自动更新。只被 draw slot 读取时，变化只触发重绘，不触发重排，与其它响应式源一致（见[运行时](04-运行时.md#reactive-slot-runtime)）。

同一参数在一个会话内只有一份状态，多处 `useParameter('gain')` 共享。

写入：

- 赋值 `gain.value = x` 或 `gain.normalized = x` 是一次完整的用户操作，内部依次执行 begin、set、end，宿主记录为一次自动化编辑。
- 连续编辑使用 gesture：

```ts
const drag = gain.gesture()
drag.begin()
drag.set(value)            // 或 drag.setNormalized(n)
drag.end()
```

gesture 期间多次写入只对应一对 begin/end。参数编辑类 Arrangable 与 helper 必须自动管理 gesture，不能要求用户在拖动前后手写 begin/end。

一致性规则：

- 写入后本地状态立即更新；宿主回传的同值通知不再触发依赖。
- 本会话 gesture 进行中，宿主送来的该参数值不覆盖本地值，gesture 结束后以宿主当前值对齐。
- 同一检查点内多次宿主变化只交付最后一次。
- gesture 未结束时 scope 销毁、Arrangable 卸载、HMR、重载或 QuickJS 重置，原生侧代为结束 gesture，宿主不会停留在编辑状态。

`gain.reset()` 写回默认值，按完整操作处理。`gain.textFor(normalized)` 与 `gain.parseText(text)` 调用参数自身的文本转换。

控件接入：

- `gain.editable()` 返回读写归一化值的 `EditableValue`，begin / set / end 对应本参数的 gesture，供 [数值拖动状态](37-拖动与数值控件.md#可编辑值) 使用；默认值与离散参数的步长由它从参数描述中提供。
- `gain.showHostMenu({xDp, yDp})` 请求宿主在该位置弹出本参数的上下文菜单（自动化、MIDI learn 等，对应 JUCE `getHostContextMenuForParameter`）。宿主不提供菜单时返回 `false`，调用方可改用自定义菜单。

## 宿主与走带

```ts
const host = useHost()
host.name          // 宿主名，未知时为 null
host.format        // 'standalone' | 'vst3' | 'au' | 'aax' | 'lv2' | 'unknown'
host.sampleRate    // 未 prepare 时为 null
host.blockSize

const transport = useTransport()
transport.playing
transport.recording
transport.bpm            // 宿主未提供时为 null
transport.timeSignature  // { numerator, denominator } | null
transport.positionPpq
transport.positionSeconds
transport.looping
```

两者均为只读响应式对象。宿主不一定提供全部字段，缺失字段为 null。走带对象被使用期间，播放中的位置按帧更新；停止时只在状态变化时更新。

## 音频观测流

```ts
const level = useMeter('output')                     // Readonly<Ref<number>>，自上次交付以来的峰值
const scope = useWaveform('input', { size: 1024 })   // Readonly<ShallowRef<Float32Array>>，最近 size 个样本
const bins = useSpectrum('spectrum')                 // Readonly<ShallowRef<Float32Array>>，最新一份数组
```

订阅从调用开始，到所在 scope 销毁为止；没有订阅时原生侧不向 JS 交付。订阅期间每帧最多交付一次，数据未变化不触发依赖。数组为新对象或在同一对象上原位更新后显式触发，使用方不得长期持有并假设内容不变。名称未在 `Interop` 登记时报错。

# 会话与生命周期

脚本会话是一个 QuickJS context 的生命期。会话结束（卸载、HMR、手动重载、错误恢复、源切换、QuickJS 重置）时：

- 结束该会话的所有未完成 gesture；
- 取消全部观测订阅与消息订阅；
- 丢弃未完成的调用；
- 停止唤醒轮询，之后的音频线程边沿不再触达已结束的会话。

新会话接入时，参数与宿主快照以当前值整体交付一次，不重放历史消息。

# 线程与调度

```txt
音频线程 -> 原子量 / 环形缓冲 / 三缓冲 -> VBlank 视觉帧的语义检查点拉取
音频线程边沿、宿主参数通知（任意线程） -> 原子标记 -> message thread 定时轮询 -> 唤醒 -> 语义检查点
message thread emit / reply -> 队列 -> 语义检查点
语义检查点 -> JS 响应式状态 -> 正常的 Rearrange / JS Value Phase / FramePlan
```

参数通知可能来自音频线程或宿主任意线程，处理时只写原子值和变化标记。会话连接期间，message thread 以低频定时器检查标记并唤醒 UI owner，唤醒频率与音频块和宿主通知频率无关；VBlank 帧期间检查点本身也会收取参数变化。

参数、宿主信息、消息与调用回执在每个语义检查点交付；走带与观测流只在 VBlank 视觉帧的检查点交付，事件或唤醒触发的检查点不交付它们，交付频率不超过帧率。存在观测订阅、走带播放中或走带有未交付的变化时，Interop 向帧调度声明帧需求；无订阅且走带静止时不产生帧需求。

# 模块落位

- `arrange_core`：`Interop.h` 定义 `InteropValue`、参数描述、宿主与走带快照，以及脚本会话所面对的抽象 `InteropHost`，不依赖 JUCE 或 QuickJS。
- `arrange_quickjs`：会话桥接，把 `InteropHost` 安装为原生对象上的受控函数，负责交付批次、gesture 记账、订阅与调用回执。
- `arrange_juce`：`arrange::juce::Interop` 以 JUCE processor 实现 `InteropHost`，并提供 `Meter`、`Waveform`、`Spectrum` 等音频线程端对象。
- `@arrange/framework/interop`：TS 公开 API。

# 暂不提供

- 宿主 program 列表与切换；需要时通过调用自行实现。
- MIDI 收发与可视化。
- 多个 Editor 同时连接同一 `Interop`。
- 运行期增删参数。
