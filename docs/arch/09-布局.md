# 模型

采用 Compose 风格的 `约束 -> 测量 -> 放置 -> 绘制`。

```txt
Constraints -> measure -> place -> draw
```

# 约束

父节点向子节点传入：

```txt
minWidth / maxWidth / minHeight / maxHeight
```

内部使用 JUCE 逻辑坐标。`1.dp` 在默认 Density 下对应 1 个 Arrange/JUCE 逻辑单位，不额外乘系统缩放。

四个值必须非负，最小值必须有限且不超过对应最大值。最大值为 `Constraints.Infinity`（正无穷）才表示无界；`maxWidth=0` 或 `maxHeight=0` 是真实的零尺寸上界，不能改写成无界。`fillMax*` 只填满有界轴，滚动内容才沿滚动轴收到无界最大值。

# 测量规则

- 父节点传约束。
- 子节点在约束内返回尺寸。
- 父节点决定子节点位置。
- 绘制不改变布局结果。
- 默认不允许子节点被同一父节点多次正式测量；需要额外信息时使用固有尺寸。

# 尺寸修正

普通尺寸 Modifier 尊重父约束。`required*` 系列表达强制尺寸意图，但父节点看到的尺寸仍会被安全约束修正；真实绘制位置由该 Modifier 的放置语义决定。

# 固有尺寸

支持四类查询：

- `minIntrinsicWidth(height)`
- `maxIntrinsicWidth(height)`
- `minIntrinsicHeight(width)`
- `maxIntrinsicHeight(width)`

对应：

```ts
M.width(IntrinsicSize.Min)
M.width(IntrinsicSize.Max)
M.height(IntrinsicSize.Min)
M.height(IntrinsicSize.Max)
```

固有尺寸用于文本、分割线、表单、等高行等场景。固有尺寸查询不能产生副作用。

查询沿当前 Modifier 顺序和 MeasurePolicy 递归计算，不能改变正式测量缓存、bounds、放置状态或动画进度。另一轴可传非负有限数值或正无穷。固定尺寸、范围和 padding 参与查询；`IntrinsicSize` 先查询内层，再在父约束内将该轴约束为所得尺寸，随后仅正式测量一次。

文本的最小固有宽度为最长不可继续断开的片段宽度，最大固有宽度为不软换行的最长行；单行文本两者相同。固有高度按给定宽度换行，遵守行数限制，零宽度仍产生逐片段换行而非无限宽文本。Painter 在 `sizeToIntrinsics=true` 时提供自然尺寸下限。Box 忽略 `matchParentSize` 子项，Row/Column 在主轴按 weight 比例求所需空间，在交叉轴按可分配的主轴空间查询子项。

Lazy 的测量依赖受控物化，四类固有查询明确拒绝，不能遍历并实例化全部项目来取得答案。外层固定所查询轴的尺寸 Modifier 可直接回答该轴查询；需要将 Lazy 放进固有尺寸父布局时，应显式给出相应轴尺寸。

# Box

- 子节点叠放。
- 默认按 `contentAlignment` 放置。
- 子节点 `M.align(...)` 优先于父级默认对齐。
- `propagateMinConstraints=false` 时，普通子节点测量时最小约束为 0。
- `M.matchParentSize()` 子节点不参与 Box 自身尺寸计算；Box 尺寸确定后再匹配父尺寸。

# Row

主轴排列在测量之后消费实际子项尺寸：Center/End 或 Bottom 使用剩余空间偏移；SpaceBetween 将余量分配到相邻间隔，SpaceAround 在首尾保留半个间隔，SpaceEvenly 保留相同首尾间隔。`spacedBy` 保留固定间距，并以指定主轴对齐放置整组子项。Column 使用同一规则的垂直方向。

- 主轴水平，交叉轴垂直。
- 先测量非 `weight` 子节点。
- 有界主轴按顺序分配扣除固定间距后的剩余空间；无界主轴按自然尺寸测量，weight 不产生填满无限空间的份额。
- 再把剩余主轴空间分配给 `weight` 子节点。
- `weight(fill=true)` 时，子节点占满分配空间。
- `weight(fill=false)` 时，子节点最多使用分配空间。
- `horizontalArrangement` 处理主轴剩余空间与间距。
- `verticalAlignment` 处理交叉轴对齐。

# Column

与 Row 对称：主轴垂直，交叉轴水平。

# FlowRow / FlowColumn

普通流式布局，不是 Lazy。适合 tag、chip、小按钮组。子节点数量不宜巨大。

FlowRow 的 `horizontalArrangement` 组织每行主轴，`verticalArrangement` 组织各行，`itemVerticalAlignment` 组织同一行内子项；FlowColumn 对称使用列主轴和 `itemHorizontalAlignment`。默认主轴/交叉轴从 Start/Top 开始。`maxItemsInEachRow` / `maxItemsInEachColumn` 为正整数，未提供时只按可用空间换行。

保持内容顺序，下一子项的自然主轴尺寸加固定间距超过该行最大主轴空间或达到数量上限时换行。过大的单项独占一行并接受该轴父约束。非 weight 子项只正式测量一次；weight 子项先查询最小固有主轴尺寸以决定所属行，然后只在该行分配剩余空间，并遵守 `fill`。每行分别计算 weight，不能把全部子项作为一组分配。无界主轴只按数量上限换行，并以自然尺寸测量 weight 子项。

各行交叉轴尺寸取该行子项最大值，各行间消费交叉轴间距；容器尺寸再遵守父约束。`M.align` 覆盖所在行默认子项对齐。Flow 的固有交叉尺寸按给定主轴空间模拟换行；最大固有主轴尺寸按数量上限分组，最小固有主轴尺寸搜索能在给定交叉空间容纳内容的最窄结果，查询过程不正式测量子项。

# Lazy 布局

Lazy Arrangable 通过普通 Foundation 调用同一 Layout 的受控内容入口，原生 LazyMeasurePolicy 按视口决定物化范围；定义与普通 props 契约见[内建 Arrangable](12-内建Arrangable.md)，候选继续执行见[运行时](04-运行时.md)。

测量流程：

```txt
viewport constraints
-> 根据 LazyState 和滚动 offset 估算首个可见 item
-> 物化可见范围 + beyondBounds 范围
-> 测量 item
-> 更新 visibleItemsInfo / maxScroll
-> 放置可见 item
```

规则：

- Lazy 只创建可视范围、预取范围、焦点保持所需项目。
- `itemKey` 表示稳定业务身份，并参与重排锚点与有限缓存中的状态保留；index key 只适合静态列表。活动范围之外最多保留 32 个逻辑 item 作用域，普通 Ref 随该作用域一起淘汰，不承诺像 Compose saveable-state 一样恢复全部离屏状态。
- `contentType` 用于测量缓存兼容性判断；不同业务 key 的局部状态不能因类型相同而互换。
- item 可变高/宽；测量结果按 key、contentType、约束缓存。
- 两轴 viewport 必须有界；无界约束下诊断。
- Lazy 自身负责裁剪与滚动，不叠加同方向普通滚动。
- sticky header、分页、瀑布流属于集合布局扩展能力，不属于 Lazy 基础语义。

默认保留窗口为可视区域前半屏、后面一屏，焦点、输入会话和指针捕获额外固定相应稳定 key。每帧最多新预取 4 个离屏项；未完成工作通过同一候选提交后的反馈请求下一帧。连续未知零尺寸项每帧最多测量 64 个，并提交已知尺寸索引后继续，避免空 item 堵住 Owner。可见和固定项合计超过 4096 时明确诊断；该上限不会限制正常大小项目的集合总量。

几何索引账本按集合规模保存每项标量尺寸、行尺寸和前缀增量，属于 O(n) 索引，不能把它称作 1024 项缓存。数据集 key、type、span、行与 key 索引不可变共享；数值账本以 256 项分块写时复制，候选只复制块指针与本帧修改的块。另有按 key/type/交叉轴约束保留的富测量记录：所有活动项不被淘汰，离屏部分最多 1024 项，按 LRU 淘汰。兼容记录可在重排时恢复标量几何并帮助范围定位；新建测量根仍正式测量以准备文本、Painter 和基线，不能沿用已退休原生节点的内部测量结果。

测量期子组合的候选延续和修改范围见[运行时](04-运行时.md)。

# Scope 规则

- `BoxScope`：`align`、`matchParentSize`。
- `RowScope`：`weight`、垂直 `align`。
- `ColumnScope`：`weight`、水平 `align`。
- `FlowRowScope` / `FlowColumnScope`：对应方向的 `weight`、交叉轴 `align`，weight 作用于当前行或列。

错误使用在开发期给出诊断。

# 文本对齐

Text 需要提供 baseline 结果，以支持行内对齐与后续的 `FirstBaseline` / `LastBaseline` 语义。
