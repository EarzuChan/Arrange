# 原则

测试要轻量、到位、可长期维护。

核心口径：

```txt
TS 写真实 Arrange UI
-> 中立 TestTree 脱离 Bridge
-> 布局测 snapshot
-> 绘制测 DrawOps
-> 事件用 TestRule
-> 动画 / HMR 用 test clock
-> intent / dirty / FramePlan / pipeline 测执行记录
-> 截图做人眼 artifact
-> 真插件做验收
```

手工测试只判断体验；正确性与回归尽量自动化。

真实宿主验收发现问题后，以下场景必须从人工报告沉淀为自动或半自动回归：

- live 可达 / 不可达 / 半路关闭 / 半路启动下的 reload 行为。
- Debug badge、Standalone 标题、toast 与日志事件符合诊断表层约束。
- 错误屏恢复后不得残影或叠画。
- 滚动视口内 wheel 不得报错，并能同步 `ScrollState`。
- Input 文本、光标、选区、IME bounds 对齐真实字体测量。
- Standalone resize 后 layout / repaint 正确。

# 架构防回流测试

以下不是一次性测试，而是长期 gate：

- no-debugJson modifier smoke：证明核心 modifier 不依赖 `modifierDebugJson`。
- no-expanded-field modifier smoke：证明核心 modifier 不依赖 `__arrangeModifier.N.*` 展开字段或局部专项 prop hack。
- Prop 解码测试：覆盖 number / bool / string / handle / color / nested object / fallback。
- BridgeWriter 统一入口测试：Vue renderer、headless test、smoke fixture 必须复用同一 typed BridgeWriter。
- FramePlan 测试：每个生产输入都必须能追踪到 intent、state / transaction、dirty attribution、FramePlan 与阶段执行记录。
- Paint purity 静态检查：禁止 `paint()` 调用 JS、apply mutation、layout、DrawOps build、request repaint、清 dirty 或设置 diagnostics error。
- DiagnosticsScene 测试：诊断 UI 不进入用户 App tree，但必须复用 core layout / paint / DrawOps pipeline。
- TextLayoutService 几何测试：覆盖测量、换行、caret、selection、point-to-index、长文本 viewport。
- 静态检查：禁止生产模块重新直接访问 `modifierDebugJson`、`element.body` 或手写 encoded prop parser。

# 分层

```txt
大量：纯逻辑测试
  layout / modifier / dirty / bridge / renderer / frame plan

中量：集成测试
  Vue renderer / QuickJS / HMR / error screen / app loading / diagnostics scene

少量：冒烟与真实宿主
  screenshots / test plugin / host verification
```

# TS Authoring 测试

布局与组件测试优先在 TS 侧写真实 authoring，不在 C++ 复制一套 authoring API。

```tsx
const ui = await renderArrange(() => (
  <Row modifier={m.size(dp(300), dp(100))}>
    <Box modifier={m.width(dp(100)).testTag("fixed")} />
    <Box modifier={m.weight(1).testTag("weighted")} />
  </Row>
))

expect(ui.node("fixed").bounds()).toEqualRect(0, 0, 100, 100)
expect(ui.node("weighted").bounds()).toEqualRect(100, 0, 200, 100)
```

测试专用 `m.testTag(name)` 不影响布局、绘制和生产语义，只服务测试、Inspector 与诊断。

# TestTree

大多数测试不直接依赖生产 Bridge，而使用中立测试树：

```txt
Vue/SFC/TS
-> Arrange test renderer
-> TestTreeSnapshot
-> headless layout / draw / hit-test
-> snapshot / matcher
```

这样 Bridge 协议变化不会炸掉全部布局测试。

TestTree 是测试模型，不是生产布局、绘制、命中或文本测量事实源。生产事实源必须在 `arrange_core`。

# 布局测试

布局测试断言结构化数据：

- constraints。
- measured size。
- placed bounds。
- baseline。
- children order。
- visible item range。

重点覆盖：

- Box / Row / Column / Spacer。
- padding / size / required / fill / wrapContent / aspectRatio。
- align / weight / matchParentSize。
- IntrinsicSize。
- Flow / Lazy。
- transform 后命中边界。

# Modifier 测试

Modifier 必须测顺序。

```ts
m.background(red).padding(dp(8))
m.padding(dp(8)).background(red)
```

每类 Modifier 至少判断：

- 是否改变 constraints。
- 是否改变 measured size。
- 是否改变 placement。
- 是否改变 draw ops。
- 是否改变 hit-test / focus / dirty。

# DrawOps 测试

绘制优先测命令，不先测图片。

  ["strokeRoundRect", 0, 0, 100, 40, 8, 1, "0xFF606060"],

- background / border / clip / shadow。
- drawBehind / drawWithContent / drawWithCache。
- Canvas display list。
- Text 绘制命令。

# 时间与 HMR 测试

提供可控 test clock：

```ts
ui.mainClock.autoAdvance = false
ui.mainClock.advanceBy(16)
ui.mainClock.advanceUntilIdle()
```

用于：

- 动画中间值。
- animateContentSize。
- batch / frame flush。
- HMR 等待稳定。
- 错误屏恢复。

动画测试必须覆盖真实帧链路，不能只断言 JS ref 值：

```txt
host frame clock tick
-> QuickJS requestAnimationFrame callback
-> Vue reactive update
-> Bridge incremental batch
-> MutationTransaction queue
-> FramePlan
-> SceneFramePipeline apply
-> DrawOps / PublishedFrame
```

`animateColorAsState` 至少要断言中间 tick 的 DrawOps 或等价绘制意图包含中间色；最终 tick 包含目标色。QuickJS 测试不得用 Promise / microtask 作为 frame 替代品。

`waitForIdle` 必须覆盖：JS Composition Phase 无待处理 callback / microtask，MutationTransaction queue 为空，RuntimeStore 无待 reduce intent，InvalidationGraph 无待消费 dirty，FramePlan 无待执行阶段，SceneFramePipeline 无待 publish frame。旧“只看 JS idle”不构成通过证据。详见 [调度线程与帧阶段](26-调度线程与帧阶段.md)。

HMR smoke：

```txt
启动测试 dev server
-> 加载 App.vue
-> 断言 text=A
-> 修改文件 text=B
-> waitForIdle
-> 断言 text=B
-> 写坏文件
-> 断言错误屏
-> 修复
-> 断言恢复
```

reload smoke 还必须覆盖同一入口的 live-first fallback：

```txt
live 可达 -> 加载 live
live 关闭 -> F5 -> fallback dist
live 启动 -> F5 -> 回到 live
错误页点击 -> 仍走同一链路
```

# Invalidation 测试

重绘测试不只看首次截图，还要覆盖状态切换：

- loaded -> error。
- error -> loaded。
- live -> dist。
- dist -> live。
- resize。
- scroll / clip / transform 后 repaint。
- 纯 paint dirty 不得触发布局。
- layout dirty 必须触发测量 / 布局 / 绘制。
- event slot 替换不得触发无理由 layout / paint。
- 无法证明局部边界时必须出现显式 full fallback reason。

早期可以用截图 artifact 与窗口 dump 辅助；稳定后再收敛到小范围 golden diff。

# DiagnosticsScene 测试

诊断表层测试覆盖：

- Debug 默认显示 badge。
- Release 默认隐藏 badge / toast。
- live / dist / fallback / no app 文案正确。
- toast 同类合并、自动消失、最多 3 条。
- 错误屏 Copy diagnostics 包含 source、URL/path、错误摘要。
- diagnostics scene 不参与用户 layout，不改变 hit-test / focus / zIndex。
- diagnostics scene 复用 core layout / paint / DrawOps pipeline。
- paint 不生成 diagnostics error、不切换 loaded 状态、不临时绘制错误屏。

# Text / Input 测试

Input 测试必须覆盖同一文本模型：

- 文本绘制位置。
- caret rect。
- selection rects。
- IME `getCaretRectangleForCharIndex(...)`。
- IME `getTextBounds(...)`。
- point -> index。
- 中英文混排与真实 OS IME commit。

禁止只用 ASCII 等宽假设证明 Input 正确。

# Canvas 测试

# 冒烟测试

冒烟测试少而完整，不追求数量。

建议：

- `smoke-basic-editor`。
- `smoke-lazy`。
- `smoke-canvas`。
- `smoke-interop`。

每个 smoke 覆盖完整链路，并产出 artifact。
