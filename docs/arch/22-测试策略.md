# 原则

测试要轻量、到位、可长期维护，但：绝不能维护另一套或多套生产语义，严重违法违纪。

测试按行为契约保留。可以合并重复准备过程和重复断言，但不能为减少数量删除生命周期、失败恢复、身份复用或原生阶段覆盖。纯响应式算法直接测试生产实现；记录型原生目标只验证 TS 提交与调度，不作为布局、绘制或真实宿主正确性的证据。

已删除能力以实现、类型、出口和消费者的消失为依据，不保留针对旧词汇或旧 API 的专门 guard、黑名单及拒绝测试。测试验证 Arrange 当前的正向契约和实际不变量；未声明参数、错误类型、无效身份等仍由统一声明与生命周期边界校验。

覆盖率用于定位未执行的生产分支，必须注明统计范围和运行环境。不得用总百分比替代真实 QuickJS/native 回归，或为提高比例新增没有行为断言的调用测试。上游来源与许可证应保留，已退出的兼容路径和无人调用的工具按实际引用删除。

平台相关行为各在对应平台实测：Windows 分支只在 Windows 上运行，用真实的 MSVC、资源编译器和系统命令；macOS 分支只在 macOS 上运行，用真实的 Xcode 工具链与签名工具。不伪造平台变量、编译宏、系统命令或工具成功输出，不在一台机器上切换身份来断定另一平台可运行。对方平台的用例注明“不适用”，不计入本机通过数；本平台缺少工具链、权限或必要系统设置时必须失败并说明未完成验证，不能跳过后宣称通过。两个平台共有的行为（路径分隔符、换行等）按平台归一化后断言；面向用户的路径与文本保持平台原生形式。

CLI 三层依赖通过源码导入约束检查：功能与终端不得直接互相依赖，业务只接触语义接口。终端会话的纯模型用例验证线性历史、精确矩形命中、无焦点嵌套滚动、完成后控制台、ANSI/回车解析、长原行、大输出、输入分包、提示和恢复状态机；xterm.js 无头版回放整屏帧与任务终端缓冲，证明屏幕模型和嵌套视口行为。真实 raw mode、备用屏幕、鼠标、触控板、resize、信号和正式入口生命周期仍属于平台实测：Windows 经 ConPTY 与主人使用的 Windows Terminal/PowerShell 验证，macOS 在 Terminal 与 iTerm 验证。自动化测试不替代主人实际操作确认。

流程区块验证稳定身份、嵌套替换、重试撤下错误、最终答案收束、旧代异步写入拒绝、输入撤销及任务收尾边界。屏幕和退出拍扁必须读取同一定稿内容，已替换状态及其控制台不复现；保留式完成的任务维持身份、完整原行和独立滚动，不受后续决策区块替换影响。版本循环使用会产生子控制台的预检和真实 Git 源码获取覆盖完整区块撤下，避免无输出替代服务遗漏实际行为；CONFIG／SETUP 重扫使用真实会话及业务适配器验证，不另外模拟一套区块语义。

划分口径：只有确实平台无关且要求两端一致的契约共跑。涉及平台分歧的路径身份、可执行格式、产物布局、签名策略、进程清理、窗口与输入，各用当前平台身份执行对应分支；不以“只是传一个 platform 参数”为理由跨平台验证它们。纯格式解析、数据校验、状态机和故障恢复可使用受控输入与故障注入，但结果只证明该契约；失败注入不能代替真实系统工具的成功链路。平台无关的枚举支持范围判断不创建或驱动另一平台服务。

框架的测试工具复用 CLI 已有本机工具链发现适配，不引入第二套平台探测规则；框架生产代码不依赖 CLI。`pnpm verify:platform` 在当前系统顺序运行框架 Node 测试、CLI 测试和框架 native CTest，生成 `.arrange/verification/<平台>-<架构>/framework.json`、`cli.json`、`native-debug.xml`（Release 为 `native-release.xml`）。Node 报告分开记录通过、失败、对方平台排除和本机未验证项；任何本机未验证跳过都会使验收失败。CTest 的原生程序使用真实平台宏，测试缺少系统前提时返回失败，不在程序内部跳过关键断言后返回成功。

`pnpm test:native` 准备真实 Demo UI、配置并构建全部 C++ 测试，再串行运行完整 CTest；`ARRANGE_NATIVE_TEST_FLAVOR=Release` 选择 Release，`ARRANGE_NATIVE_TEST_BUILD_DIR` 可显式选择构建树。`pnpm test:quickjs` 另跑真实宿主的严格 Modifier 与脚本诊断分支。CMake、Ninja 和 Developer Prompt 允许以 `CMAKE_EXE`、`NINJA_EXE`、`VSDEVCMD` 显式指定，默认通过本机发现；原生源码覆盖遵守[依赖约束](../proj/5：具体开发的额外约束.md#原生依赖约束)。工具脚本通过统一 TS loader 运行，不依赖单机硬编码安装目录。

每次新增或修改平台分歧能力，都记录本机已验范围和另一平台待验项；由主人在对应设备确认后才能标为双平台通过。发布前分别保存 Windows 与 macOS 的完整验收结果，不能用一份总通过数代替另一平台结果。自动化中的 xterm 绘屏夹具、手动 VBlank 驱动、进程故障注入和小型本机编译产物各证明自身契约，不冒充系统终端、真实输入设备或 JUCE 插件宿主验收。

核心口径：

```txt
TS 写真实 Arrange UI
-> native QuickJS test harness
-> 真实 @arrange/framework / Arrange Ts runtime
-> QuickJS native transaction API / typed slot update API
-> 真实 LayoutTree / SceneFramePipeline
-> 断言 layout / DrawOps / hit-test / dirty / callback
-> 主人来跑真插件做验收，这点绝不可AI用自动化代劳：不可靠，不可复现！
```

手工测试只判断体验；正确性与回归尽量自动化。自动化测试必须尽量压到真实 QuickJS + native pipeline 上，不能用 TS headless layout、serialization encode/decode 或 fixture 协议保护旧链路。

真实宿主验收发现问题后，以下场景必须从人工报告沉淀为自动或半自动回归：

- live 可达 / 不可达 / 半路关闭 / 半路启动下的 reload 行为。
- Debug badge、Standalone 标题、toast 与日志事件符合诊断表层约束。
- 错误屏恢复后不得残影或叠画。
- 滚动视口内 wheel 不得报错，并能同步 `ScrollState`。
- Input 文本、光标、选区、IME bounds 对齐真实字体测量。
- Standalone resize 后 layout / repaint 正确。

# 生产链路契约验证

以下验证当前生产链路的行为与阶段职责：

- JSValue reader 测试：QuickJS host 直接读取 prop / modifier / callback JSValue，并构造 typed native mutation。
- NativeTransaction 测试：Rearrange mutations 必须进入同一 native typed transaction queue。
- SlotUpdateBatch 测试：Reactive slot updates 必须进入 typed slot update batch，并由 FramePlan 消费。
- Phase-aware reactivity 测试：animated ref / UI prop ref 的高频变化不得默认触发结构重排。
- Dirty role 测试：paint slot 不触发布局，layout slot 进入必要 layout dirty，event slot 不触发无理由 layout / paint。
- FramePlan 测试：每个生产输入都必须能追踪到 intent、state / transaction、dirty attribution、FramePlan 与阶段执行记录。
- Paint 阶段检查：`paint()` 只消费已发布绘制结果，场景执行与发布属于正式帧阶段。
- DiagnosticsScene 测试：诊断 UI 不进入用户 App tree，但必须复用 core layout / paint / DrawOps pipeline。
- TextLayoutService 几何测试：覆盖测量、换行、caret、selection、point-to-index、长文本 viewport。

# 重排与 Layout 边界验证

对象模型以 [运行时](04-运行时.md) 为准。验证真实 SFA 与等价代码定义经过同一调用和 Layout 链路，不以两套 mock 结果相同代替生产一致性。

- 普通包装、条件、列表、Slot 和 Template 不增加 RearrangeNode；只有实际 Layout 调用产生节点，零根和多根具有正确布局父子关系
- 初始化一次、定义替换、keyed 移动、退出退休、重复内容调用与失败清理分别验证实例、RearrangeNode、LayoutNode 和 Modifier handle
- Text/Input 的 Modifier 参数更新、链层约束、绘制、输入资格和 IME 共享几何，退休元素后旧输入和回调失效；同一描述多受体的状态独立
- 结构和值的计数分开，纯值更新不无故重排；颜色变化不重新排版，布局输入变化保留必要的父子失效传播
- VNode 构造、diff/patch、旧 renderer 和编译 helper 没有生产或测试专用保留路径；用新调用机制或真实模板编写夹具

# SFA Authoring 测试

布局与 Arrangable 测试使用真实 .sfa 夹具，经正式编译器进入 native QuickJS harness，不在 TS 侧复制布局、绘制或命中实现，也不为测试保留 JSX/render/VNode 构造路线。

```sfa
<template>
    <Row :modifier="M.size(300.dp, 100.dp)">
        <Box :modifier="M.width(100.dp)"/>

        <Box :modifier="M.weight(1)"/>
    </Row>
</template>

<script>
import { Row, Box } from '@arrange/framework/foundation'
import { M } from '@arrange/framework/ui'
</script>
```

harness 从真实布局结果读取子项顺序与 bounds，分别断言首项宽度 100、次项填满剩余 200。测试查询不向用户返回内部实例或原生节点引用。

未来测试标签若采用 M.testTag(name)，必须走正式语义/诊断元数据通道；不能改变布局、绘制或输入，不借 prop map 绕过声明。这是测试能力设计，不声明当前已经公开实现。

# 时间与 HMR 测试

提供 native harness `ManualVBlankSource`：

```ts
ui.manualVBlank.advanceFrame(16.666)
ui.waitForIdle()
```

用于：

- 动画中间值。
- animateContentSize。
- transaction / slot update / frame flush。
- HMR 等待稳定。
- 错误屏恢复。

动画测试必须覆盖真实阶段链路，不能只断言 JS ref 值：

```txt
manual VBlank frame event
-> JS Value Phase
-> animated refs / transitions advance
-> SlotUpdateBatch
-> FramePlan
-> SceneFramePipeline applySlotUpdates
-> DrawOps / PublishedFrame
```

`animatedColorAsRef` 至少要断言中间 tick 的 DrawOps 或等价绘制意图包含中间色，且该 tick 不触发结构重排。QuickJS 测试不得用 Promise、microtask、JS timer 或自动运行 test timer 作为 frame 替代品。

`waitForIdle` 必须覆盖：Rearrange Phase 无待处理 callback / microtask，JS Value Phase 无待推进 value，MutationTransaction queue 为空，SlotUpdateBatch 为空，RuntimeStore 无待 reduce intent，InvalidationGraph 无待消费 dirty，FramePlan 无待执行阶段，SceneFramePipeline 无待 publish frame。旧“只看 JS idle”不构成通过证据。详见 [调度线程与帧阶段](26-调度线程与帧阶段.md)。

HMR smoke：

```txt
启动测试 dev server
-> 加载 App.sfa
-> 断言 text=A
-> 修改文件 text=B
-> waitForIdle
-> 断言 text=B
-> 写坏文件
-> 断言错误屏
-> 修复
-> 断言恢复
```

reload smoke 还必须覆盖同一入口的 live-first fallback：

```txt
live 可达 -> 加载 live
live 关闭 -> F5 -> fallback dist
live 启动 -> F5 -> 回到 live
错误页点击 -> 仍走同一链路
```

# Invalidation 测试

- loaded -> error。
- error -> loaded。
- live -> dist。
- dist -> live。

## 验收构建与打包夹具复用

原生验收构建树记录归属与配置身份；相同身份增量 configure，身份变化或显式 `--clean` 核验归属后重建整个生成树，不以 --fresh 保证嵌套缓存清理。普通源码修改交给 CMake/Ninja。依赖源码复用既有用户缓存。

macOS 验收树的外部父目录允许系统或用户别名，先解析父目录物理路径，再检查受管树自身；目标链接不能授权写入或清理，路径身份不能替代归属校验。编译器使用本机发现并验证的调用路径，macOS 的 `clang++` 调用名必须保留，不以其指向的 `clang` 替代 C++ 驱动。

打包文件契约在每个测试文件真实编译一次种子，各用例复制独立产物并重定位真实 File API 模型路径；副本不作为有效构建树使用。构建改名、资源变化和重新链接继续独立真实构建。种子只在一次测试执行内有效，不用硬链接共享可写内容，不跨平台复用。

`pnpm test:native --clean` 或 `pnpm verify:platform --clean` 请求完整原生生成树重建。验收树必须有当前归属记录，未知非空目录不自动清理；通过 ARRANGE_NATIVE_TEST_BUILD_DIR 选择新的空目录。源码选择显式覆盖优先，否则读取当前依赖清单复用 SourceCache。完整 configure 成功后完成身份记录；后续相同配置通过 CMake/Ninja 增量判断。
