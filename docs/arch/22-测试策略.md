# 原则

测试要轻量、到位、可长期维护，但：绝不能维护另一套或多套生产语义，严重违法违纪。

核心口径：

```txt
TS 写真实 Arrange UI
-> native QuickJS test harness
-> 真实 @arrange/framework / Arrange Vue runtime
-> QuickJS native transaction API / typed slot update API
-> 真实 LayoutTree / SceneFramePipeline
-> 断言 layout / DrawOps / hit-test / dirty / callback
-> 主人来跑真插件做验收，这点绝不可AI用自动化代劳：不可靠，不可复现！
```

手工测试只判断体验；正确性与回归尽量自动化。自动化测试必须尽量压到真实 QuickJS + native pipeline 上，不能用 TS headless layout、serialization encode/decode 或 fixture 协议保护旧链路。

真实宿主验收发现问题后，以下场景必须从人工报告沉淀为自动或半自动回归：

- live 可达 / 不可达 / 半路关闭 / 半路启动下的 reload 行为。
- Debug badge、Standalone 标题、toast 与日志事件符合诊断表层约束。
- 错误屏恢复后不得残影或叠画。
- 滚动视口内 wheel 不得报错，并能同步 `ScrollState`。
- Input 文本、光标、选区、IME bounds 对齐真实字体测量。
- Standalone resize 后 layout / repaint 正确。

# 架构防回流测试

以下不是一次性测试，而是长期 gate：

- no-debugJson modifier smoke：证明核心 modifier 不依赖 `modifierDebugJson`。
- no-expanded-field modifier smoke：证明核心 modifier 不依赖 `__arrangeModifier.N.*` 展开字段或局部专项 prop hack。
- no-serialization-boundary smoke：生产源码不得通过 JSON/string/binary buffer 提交 UI mutation。
- JSValue reader 测试：QuickJS host 直接读取 prop / modifier / callback JSValue，并构造 typed native mutation。
- NativeTransaction 测试：Composition mutations 必须进入同一 native typed transaction queue。
- SlotUpdateBatch 测试：Reactive slot updates 必须进入 typed slot update batch，并由 FramePlan 消费。
- Phase-aware reactivity 测试：animated ref / UI prop ref 的高频变化不得默认触发 component render / VNode diff。
- Dirty role 测试：paint slot 不触发布局，layout slot 进入必要 layout dirty，event slot 不触发无理由 layout / paint。
- FramePlan 测试：每个生产输入都必须能追踪到 intent、state / transaction、dirty attribution、FramePlan 与阶段执行记录。
- Paint purity 静态检查：禁止 `paint()` 调用 JS、apply mutation、layout、DrawOps build、request repaint、清 dirty 或设置 diagnostics error。
- DiagnosticsScene 测试：诊断 UI 不进入用户 App tree，但必须复用 core layout / paint / DrawOps pipeline。
- TextLayoutService 几何测试：覆盖测量、换行、caret、selection、point-to-index、长文本 viewport。
- 静态检查：禁止生产模块重新直接访问 `modifierDebugJson`、`element.body`、手写 encoded prop parser、SerializedBatch / SerializedOp / EncodedAnyValue / EncodedProp / modifierPayload。

# 分层

```txt
大量：纯逻辑测试
  modifier / dirty / prop schema / frame plan / core layout algorithm

中量：真实 QuickJS/native 集成测试
  Arrange Vue / QuickJS / HMR / error screen / app loading / diagnostics scene / NativeTransaction / SlotUpdateBatch

少量：冒烟与真实宿主
  screenshots / test plugin / host verification
```

# TS Authoring 测试

布局与组件测试优先在 TS 侧写真实 authoring，但执行必须尽量进入 native QuickJS test harness，不在 TS 侧复制生产 layout / draw / hit-test。

```tsx
const ui = await renderArrange(() => (
  <Row modifier={m.size(dp(300), dp(100))}>
    <Box modifier={m.width(dp(100)).testTag("fixed")} />
    <Box modifier={m.weight(1).testTag("weighted")} />
  </Row>
))

expect(ui.node("fixed").bounds()).toEqualRect(0, 0, 100, 100)
expect(ui.node("weighted").bounds()).toEqualRect(100, 0, 200, 100)
```

测试专用 `m.testTag(name)` 不影响布局、绘制和生产语义，只服务测试、Inspector 与诊断。

`testTag` 必须走正规的 semantics / inspector metadata 通道。测试框架可以用 tag 查询节点，但 tag 不能作为 layout、paint、hit-test 或 input Modifier hack，也不能通过普通 prop map 绕过 schema。

# Native QuickJS Test Harness

长期测试基础设施应提供类似 `rengotest` （新术语，意味：联合测试）的能力：

```txt
Node / TS test runner
-> 启动 native test harness
-> harness 内创建 QuickJS runtime/context
-> 加载真实 runtime bundle 与测试 App
-> 通过 QuickJS native transaction API 与 typed slot update API 驱动真实 LayoutTree
-> 从 native 读取 layout / DrawOps / hit-test / dirty / diagnostics snapshot
```

要求：

- 不维护 TS layout 第二实现。
- 不维护 serialization encode/decode 第二协议。
- 不维护 TS 侧 slot update 第二实现。
- 不用 fixture 保护旧 command buffer。
- 测试 snapshot 可以是 JSON 文件格式，但 JSON 只承载 native pipeline 输出结果，不定义生产语义。

# 时间与 HMR 测试

提供 native harness `ManualVBlankSource`：

```ts
ui.manualVBlank.advanceFrame(16.666)
ui.waitForIdle()
```

用于：

- 动画中间值。
- animateContentSize。
- transaction / slot update / frame flush。
- HMR 等待稳定。
- 错误屏恢复。

动画测试必须覆盖真实阶段链路，不能只断言 JS ref 值：

```txt
manual VBlank frame event
-> JS Value Phase
-> animated refs / transitions advance
-> SlotUpdateBatch
-> FramePlan
-> SceneFramePipeline applySlotUpdates
-> DrawOps / PublishedFrame
```

`animatedColorAsRef` 至少要断言中间 tick 的 DrawOps 或等价绘制意图包含中间色，且该 tick 不触发 component render / VNode diff。QuickJS 测试不得用 Promise、microtask、JS timer 或自动运行 test timer 作为 frame 替代品。

`waitForIdle` 必须覆盖：Composition Phase 无待处理 callback / microtask，JS Value Phase 无待推进 value，MutationTransaction queue 为空，SlotUpdateBatch 为空，RuntimeStore 无待 reduce intent，InvalidationGraph 无待消费 dirty，FramePlan 无待执行阶段，SceneFramePipeline 无待 publish frame。旧“只看 JS idle”不构成通过证据。详见 [调度线程与帧阶段](26-调度线程与帧阶段.md)。

HMR smoke：

```txt
启动测试 dev server
-> 加载 App.vue
-> 断言 text=A
-> 修改文件 text=B
-> waitForIdle
-> 断言 text=B
-> 写坏文件
-> 断言错误屏
-> 修复
-> 断言恢复
```

reload smoke 还必须覆盖同一入口的 live-first fallback：

```txt
live 可达 -> 加载 live
live 关闭 -> F5 -> fallback dist
live 启动 -> F5 -> 回到 live
错误页点击 -> 仍走同一链路
```

# Invalidation 测试

重绘测试不只看首次截图，还要覆盖状态切换：

- loaded -> error。
- error -> loaded。
- live -> dist。
- dist -> live。
- resize。
- scroll / clip / transform 后 repaint。
- 纯 paint dirty 不得触发布局。
- layout dirty 必须触发测量 / 布局 / 绘制。
- event slot 替换不得触发无理由 layout / paint。
- pure callback / event slot metadata change 必须只产生 event slot / input 相关 dirty。
- native internal invalidation 不得通过普通声明 prop 进入 LayoutTree。
- 无法证明局部边界时必须出现显式 full fallback reason。

早期可以用截图 artifact 与窗口 dump 辅助；稳定后再收敛到小范围 golden diff。

# DiagnosticsScene 测试

诊断表层测试覆盖：

- Debug 默认显示 badge。
- Release 默认隐藏 badge / toast。
- live / dist / fallback / no app 文案正确。
- toast 同类合并、自动消失、最多 3 条。
- 错误屏 Copy diagnostics 包含 source、URL/path、错误摘要。
- diagnostics scene 不参与用户 layout，不改变 hit-test / focus / zIndex。
- diagnostics scene 复用 core layout / paint / DrawOps pipeline。
- paint 不生成 diagnostics error、不切换 loaded 状态、不临时绘制错误屏。

# Text / Input 测试

Input 测试必须覆盖同一文本模型：

- 文本绘制位置。
- caret rect。
- selection rects。
- IME `getCaretRectangleForCharIndex(...)`。
- IME `getTextBounds(...)`。
- point -> index。
- 中英文混排与真实 OS IME commit。

禁止只用 ASCII 等宽假设证明 Input 正确。

Input / IME 还必须覆盖 native internal invalidation 入口：caret、selection、IME composition 与 overlay paint state 的变化应进入 intent / dirty / FramePlan，不得依赖 `__arrangeNativeInput...` 普通 SetProp。

# 协议与内部通道防回流测试

以下必须作为长期 gate：

- 生产源码不得发送无定义内部 prop，例如 `__arrangeSubtreeReplaced` 这类刷新意图必须改为结构 mutation 或 typed invalidation。
- `LayoutTree` 事件 prop 判定必须基于明确 schema，不得用任意 `on*` 或包含 `EventSlot` 的字符串作为长期归类规则。
- Paint semantics 应验证 typed paint op；Paint 阶段不得重新用自由字符串补丁决定 padding / background / border / clip 顺序。
- 生产源码不得出现旧 SerializedBatch / SerializedOp / command buffer / encoded prop 作为提交路径。
