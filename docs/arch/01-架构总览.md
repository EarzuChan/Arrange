# 核心思路：Arrange UI Pipeline

`Arrange UI Pipeline` 是 Arrange 的声明式 UI 主链路：

```txt
Vue SFC authoring
-> InputIntent / JS Composition
-> RuntimeStore / MutationTransaction
-> InvalidationGraph
-> FramePlan
-> SceneFramePipeline
-> PublishedFrame
-> JUCE passive paint
```

开发者编写标准 Vue/Vite 项目，并在 C++ 侧返回 `ArrangeEditor`。QuickJS 执行 App，Vue 自定义渲染器生成 Arrange 界面树。JUCE 只作为宿主生命周期、平台输入、frame clock 与最终绘制 API 来源，不作为状态机或布局事实源。

# 分层

1. 开发层：Vue/Vite、SFC、入口脚本、HMR。
2. 运行时层：Vue 自定义渲染、组件创建、属性更新。
3. QuickJS native boundary：同进程 QuickJS host 直接读取 JSValue / primitive / callback function，并构造 native typed transaction。
4. 调度层：单 UI owner、主 FrameClock、InputIntent、RuntimeStore、MutationTransaction queue、InvalidationGraph、FramePlan。
5. 核心层：scene state、layout tree、layout node、布局、Modifier、事件、dirty schema、DrawOps 构建。
6. JUCE 层：Editor 托管、frame clock adapter、平台输入 adapter、被动绘制 API。
7. 诊断场景：badge、错误屏、toast、日志，为未来 DevTools 提供结构化模型；诊断 UI 不进入用户 App tree，但复用 core layout / paint / DrawOps pipeline。

生产事实源在 C++ `arrange_core`：

```txt
NativeScene 或 NativeSceneState
LayoutTree / LayoutNode
MeasureAndLayoutEngine / TextLayoutService
DrawOpsBuilder
HitTester / PointerInputProcessor / Scroll / InputEditing
InvalidationGraph / dirty attribution
```

命名允许因代码演进保留兼容别名，但职责必须符合上述层级。TS runtime 负责 Vue/SFC authoring、响应式状态与 native transaction 提交。同一套核心的逻辑只能存在于一处，严禁弄出多套重复的生产布局、绘制、命中或文本测量 engine。

# 约束

- Vue/JS 不处理音频线程。
- JUCE 不知道 Vue 逻辑组件。
- QuickJS 不承担布局职责。
- HMR 不侵入核心渲染模型。
- 错误屏独立于用户 App。
- 诊断场景独立于用户 App，不参与用户 layout / zIndex / reactive state，但必须复用 core layout / paint / DrawOps pipeline。
- QuickJS 与 C++ 是同进程 native boundary，不建立 JSON / binary / string bridge；生产提交必须收敛到 JSValue 直读与 typed native transaction。
- 动画语义在 JS runtime，帧时钟在 native host；Promise / microtask 不承担 frame 语义。
- UI runtime 采用单 UI owner 线程模型；QuickJS、Vue、MutationTransaction queue、NativeScene、布局与绘制状态同属 JUCE message thread。
- 所有生产输入必须进入统一 InputIntent / scheduler；所有生产输出必须由 FramePlan 决定。
- native transaction 提交只表达 JS Composition Phase 产生的 mutation 意图；tree apply、measure、layout、DrawOps build 与 publish frame 收敛到 SceneFramePipeline。
- JUCE `paint()` 只读取 PublishedFrame 并绘制，不执行 JS、不 apply mutation、不 layout、不 build DrawOps、不清 dirty、不决定 repaint。

# 用户侧模块

JS 侧安装 `@arrange/runtime` 与 `@arrange/vite-plugin`。C++ 侧引入 Arrange C++ 库或 JUCE module，并通过 `ArrangeEditor` 接入。

# 核心数据流

```txt
Vue App
-> Vue custom renderer
-> QuickJS native transaction API
-> MutationTransaction
-> NativeScene / scene state
-> InvalidationGraph
-> FramePlan
-> SceneFramePipeline
-> PublishedFrame
-> JUCE Graphics passive paint
```
