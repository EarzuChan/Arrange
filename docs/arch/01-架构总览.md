# 核心思路：Arrange UI Pipeline

`Arrange UI Pipeline` 是 Arrange 的声明式 UI 主链路：

```txt
Vue SFC authoring -> Arrange Runtime -> Bridge Commit -> C++ RenderTree -> Measure / Layout / Paint / Input -> JUCE Surface
```

开发者编写标准 Vue/Vite 项目，并在 C++ 侧返回 `ArrangeEditor`。QuickJS 执行 App，Vue 自定义渲染器生成 Arrange 界面树，JUCE 只作为画布与输入来源。

# 分层

1. 开发层：Vue/Vite、SFC、入口脚本、HMR。
2. 运行时层：Vue 自定义渲染、组件创建、属性更新。
3. 桥接层：JS 世界与 C++ 世界通信。
4. 核心层：界面树、布局、Modifier、事件、失效调度。
5. JUCE 层：Editor 托管、绘制 API、平台输入。
6. FrameClock 层：native timer、QuickJS RAF pump、动画 tick 与 repaint 调度。
7. 诊断表层：badge、错误屏、toast、日志，为未来 DevTools 提供结构化模型。

生产事实源在 C++ `arrange_core`：

```txt
RenderTree / LayoutEngine / TextLayoutService / PaintModel / HitTester / ScrollDispatcher / InputEditing / Invalidation
```

TS runtime 负责 Vue/SFC authoring、响应式状态与 Bridge 提交，不维护第二套生产布局、绘制、命中或文本测量 engine。

# 约束

- Vue/JS 不处理音频线程。
- JUCE 不知道 Vue 逻辑组件。
- QuickJS 不承担布局职责。
- HMR 不侵入核心渲染模型。
- 错误屏独立于用户 App。
- 诊断表层独立于用户 App，不参与用户 layout / zIndex / reactive state。
- 生产协议优先 typed bridge 字段；JSON 只在诊断与测试快照时使用。
- 动画语义在 JS runtime，帧时钟在 native host；Promise / microtask 不承担 frame 语义。

# 用户侧模块

JS 侧安装 `@arrange/runtime` 与 `@arrange/vite-plugin`。C++ 侧引入 Arrange C++ 库或 JUCE module，并通过 `ArrangeEditor` 接入。

# 核心数据流

```txt
Vue App -> Vue custom renderer -> Bridge op batch -> C++ RenderTree -> layout / hit-test / paint -> JUCE Graphics
```
