# 核心思路：Arrange UI Pipeline

`Arrange UI Pipeline` 是 Arrange 的声明式 UI 主链路。它由 Arrange Vue、Reactive Slot Runtime、native FramePlan 与 JUCE passive paint 组成：

```txt
Vue-like SFC authoring
-> Arrange Vue compiler / runtime
-> Composition mutations + Reactive slot updates
-> RuntimeStore / MutationTransaction / SlotUpdateBatch
-> InvalidationGraph
-> FramePlan
-> SceneFramePipeline
-> PublishedFrame
-> JUCE passive paint
```

Arrange Vue 是面向 Arrange host target 的 authoring、composition 与 scheduling 前端。它提供 SFC、template、`<script setup>`、`ref` / `computed` / `watch`、组件组织和 HMR authoring 体验；它的 compiler、runtime、scheduler 与 reactivity 服务 Arrange 的阶段化 UI runtime。

JUCE 只作为宿主生命周期、平台输入、VBlankSource 与最终绘制 API 来源，不管理我们框架内部的任何状态机、composition、layout 或 draw。

# 分层

1. Authoring 层：SFC、template、`<script setup>`、入口脚本、HMR 与用户模块。
2. Arrange Vue 层：host target lowering、phase-aware reactivity、composition、typed UI slot binding、JS value phase、slot update batch。
3. QuickJS native boundary：同进程 QuickJS host 直接读取 JSValue / primitive / callback function，并构造 native typed mutation、event slot update 与 slot update batch。
4. 调度层：单 UI owner、VBlankSource、InputIntent、RuntimeStore、MutationTransaction queue、SlotUpdateBatch、InvalidationGraph、FramePlan。
5. 核心层：NativeScene、LayoutTree、LayoutNode、布局、Modifier、事件、dirty schema、DrawOps 构建、hit-test、文本与资源状态。
6. JUCE 层：Editor 托管、VBlankSource adapter、平台输入 adapter、被动绘制 API。
7. 诊断场景：badge、错误屏、toast、日志与未来 DevTools 结构化模型；诊断 UI 不进入用户 App tree，但复用 core layout / paint / DrawOps pipeline。

生产事实源在 C++ `arrange_core` 与 Arrange Vue runtime 的明确边界内：

```txt
Arrange Vue compiler / runtime
Reactive Slot Runtime
NativeScene 或 NativeSceneState
LayoutTree / LayoutNode
MeasureAndLayoutEngine / TextLayoutService
DrawOpsBuilder
HitTester / PointerInputProcessor / Scroll / InputEditing
InvalidationGraph / dirty attribution
FramePlan / PublishedFrame
```

开发的规矩：同一套核心逻辑只能存在于一处，严禁弄出多套重复的生产布局、绘制、命中、文本测量、slot 更新或 frame planning engine 等。

# 阶段化响应式原则

Arrange 的响应式不把所有 `Ref` 变化都弄 Recomposition。状态变化依据读取、绑定和消费位置进入不同失效域：

```txt
业务 / 结构状态 -> Composition dirty
尺寸 / 约束 / 度量 -> Layout dirty
颜色 / alpha / tint  -> Draw / Paint dirty
事件回调 -> Event slot update
资源状态 -> Resource / Draw dirty
```

`Ref` 是用户 authoring 的核心心智。`Ref` 的影响情况决定它的失效阶段。

# 约束

- JS 不处理音频线程。
- JUCE 不知道我们框架的逻辑组件。
- JS 不承担本机代码职责（如具体的Layout, Draw phase）。
- HMR 不侵入核心渲染模型。
- 错误屏独立于用户 App。
- 诊断场景独立于用户 App，不参与用户 layout / zIndex / reactive state，但必须复用 core layout / paint / DrawOps pipeline。
- QuickJS 与 C++ 是同进程 native boundary，不建立 JSON / binary / string serialization boundary；生产提交必须收敛到 JSValue 直读与 typed native mutation / typed slot update。
- 动画、transition 与 UI value 计算归属 JS Value Phase；生产视觉帧源唯一归属 VBlankSource；Promise / microtask、JS timer 或 production timer fallback 不承担 frame 语义。
- UI runtime 采用单 UI owner 线程模型；QuickJS、Arrange Vue runtime、MutationTransaction queue、SlotUpdateBatch、NativeScene、布局与绘制状态同属 UI owner。
- 所有生产输入必须进入统一 InputIntent / scheduler；所有生产输出必须由 FramePlan 决定。
- native transaction 与 slot update 只表达 Arrange Vue 产生的界面变更意图；tree apply、measure、layout、DrawOps build 与 publish frame 收敛到 SceneFramePipeline。
- JUCE `paint()` 只读取 PublishedFrame 并绘制，不执行 JS、不 apply mutation、不 layout、不 build DrawOps、不清 dirty、不决定 repaint。

# 用户侧模块

JS 侧安装 `@arrange/runtime` 与 `@arrange/vite-plugin`。`@arrange/runtime` 是用户导入 `createApp`、Arrange 组件、Modifier、基础类型、动画 API、`ref` / `computed` / `watch` 与 lifecycle API 的主入口。C++ 侧引入 Arrange C++ 库或 JUCE module，并通过 `ArrangeEditor` 接入。

# 核心数据流

```txt
SFC / template / script setup
-> Arrange Vue compiler / runtime
-> Composition mutations + Reactive slot updates
-> QuickJS native boundary
-> MutationTransaction / SlotUpdateBatch
-> NativeScene / scene state
-> InvalidationGraph
-> FramePlan -> SceneFramePipeline
-> PublishedFrame
-> JUCE Graphics passive paint
```
