# 目标

任何无法继续显示用户 UI 的错误，都进入 Arrange 错误屏，而不是崩溃、黑屏或静默失败。

# 进入错误屏的情况

- 找不到开发服务器。
- 找不到发布产物。
- 没有配置任何可加载 App source。
- JS 加载失败。
- JS 侧未处理异常。
- Vue 错误未被用户处理。
- HMR 更新失败。
- 协议版本不匹配。
- 使用未知原生标签。

# 展示内容

- 错误来源。
- 简短说明。
- 关键路径或 URL。
- 堆栈摘要。
- 重试按钮。
- 复制诊断信息按钮。

错误屏属于开发期诊断表层的强状态。样式、日志、toast、copy diagnostics 与用户可配置项见 [开发期诊断表层](25-开发期诊断表层.md)。

# 重试行为

重试会重新发现入口、重建运行时、重新加载 App，并重新挂载界面树。

重试、`F5`、HMR reload 必须走同一条加载链路：

```txt
if live enabled:
  try live
  if success return
if dist enabled:
  try dist
  if success return
show error
```

因此 Debug 下：

- live 可达时进入 live。
- live 不可达但 dist 可用时进入 dist。
- 半路关闭 live 后，下一次重试应自然 fallback 到 dist。
- 半路启动 live 后，下一次重试应自然进入 live。
- 只配置 live 且 live 不通时，错误屏显示 live 不可达。
- 什么 source 都没配置时，错误屏明确说明没有可加载 App。

# 重绘要求

错误屏进入和退出必须 full repaint。

以下场景不得只依赖局部 dirty repaint：

- loaded -> error。
- error -> loaded。
- reload / HMR reload。
- root tree 重建。
- dev / dist source 切换。

局部 repaint 优化不得牺牲正确性；无法证明局部边界正确时，必须 full repaint。

# 原则

- 错误必须可见。
- 重试不触碰音频线程。
- Debug 显示更多诊断，Release 保持克制。
