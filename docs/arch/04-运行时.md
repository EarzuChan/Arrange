# 目标

让 Vue 模板与响应式能力驱动 Arrange 原生界面树，而不是 DOM。

# 输入

- 编译后的 App 入口脚本与 SFC。
- Arrange 内建组件与 Modifier API。
- 运行时更新指令。

# 输出

- native typed transaction。
- MutationTransaction。
- typed runtime state change。
- typed invalidation。
- FramePlan 所需输入。

# 组件约束

用户可以使用 Arrange 内建组件和自定义 Vue 组件。最终落到渲染器的未知原生标签视为错误，不会当 DOM 处理。

# FrameClock 与动画刷新

QuickJS 运行时必须使用 native host 提供的帧时钟，而不是用 Promise / microtask 模拟 frame。

分工：

```txt
JS runtime:
  animate*AsState / updateTransition / easing / interpolation

QuickJS host:
  requestAnimationFrame / cancelAnimationFrame / performance.now
  pending RAF callback 队列

SceneRuntime / ArrangeRuntime:
  接收 InputIntent / transaction / typed state change
  驱动 JS Composition Phase 与 FramePlan

ArrangeEditor / scene host:
  提供 host FrameClock
  作为 UI owner 事件来源
  转发 passive paint
```

帧更新链路固定为统一输入、composition 与 frame plan：

```txt
native frame tick / host event
-> InputIntent
-> JS Composition Phase:
     JS RAF callback
     Vue reactive update / renderer patch
     native typed mutations 进入 MutationTransaction queue
-> FramePlan:
     apply mutations
     resolve invalidation
     measure / layout / place
     DrawOps / hit-test / diagnostics build
     publish frame
-> passive paint
```

Promise 只表示 microtask，不表示 frame。动画下一帧必须回到 native FrameClock。

native transaction 提交只把 typed mutations 追加到 MutationTransaction queue，不直接执行 tree apply、layout 或 repaint。reload、HMR reload、unmount、错误恢复和 source 切换必须清理 pending RAF callback 与旧 App 的 pending transactions。

运行时不得把 JS callback、RAF callback、reload、resize、diagnostics 或 package load 直接转成输出阶段。它们必须先进入 InputIntent / RuntimeStore / MutationTransaction，再由 FramePlan 决定输出。
