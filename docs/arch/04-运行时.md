# 目标

让 Vue 模板与响应式能力驱动 Arrange 原生界面树，而不是 DOM。

# 输入

- 编译后的 App 入口脚本与 SFC。
- Arrange 内建组件与 Modifier API。
- 运行时更新指令。

# 输出

- 创建节点。
- 更新属性。
- 插入与移除子节点。
- 绑定事件回调。
- 标记布局或绘制失效。

# 组件约束

用户可以使用 Arrange 内建组件和自定义 Vue 组件。最终落到渲染器的未知原生标签视为错误，不会当 DOM 处理。

# FrameClock 与动画刷新

QuickJS 运行时必须使用 native host 提供的帧时钟，而不是用 Promise / microtask 模拟 frame。

分工：

```txt
JS runtime:
  animate*AsState / updateTransition / easing / interpolation

QuickJS host:
  requestAnimationFrame / cancelAnimationFrame / performance.now
  pending RAF callback 队列

ArrangeEditor:
  native timer tick
  pumpAnimationFrame(now)
  apply incremental Bridge batch
  layout / repaint
```

帧更新链路固定为：

```txt
native tick
-> JS RAF callback
-> Vue reactive update
-> Bridge incremental ops
-> C++ RenderTree apply
-> Layout / PaintModel / repaint
```

Promise 只表示 microtask，不表示 frame。动画下一帧必须回到 native frame pump。reload、HMR reload、unmount、错误恢复和 source 切换必须清理 pending RAF callback。
