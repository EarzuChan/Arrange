# 用户拿到什么

# 工程入口

用户安装 Arrange CLI：

```bash
npm install -g @arrange/cli
```

创建、开发、构建与打包都通过 Arrange CLI：

```bash
arrange create
arrange dev
arrange build
arrange package
```

标准工程形态与 CLI 权责见 [Arrange CLI 与工程模式](31-ArrangeCLI与工程模式.md)。

# UI 侧

Arrange CLI 在 `ui/package.json` 中配置 `@arrange/framework`。用户 UI 代码从 `@arrange/framework` 获得 authoring API：

```ts
import {
  createApp,
  Box,
  Row,
  Column,
  Text,
  Input,
  Image,
  Canvas,
  m,
  dp,
  sp,
  Color,
  Alignment,
  Arrangement,
  useParameter,
  useHost,
} from "@arrange/framework"
```

# C++ / JUCE 侧

Arrange CLI 在 native CMake 中接入公开 target：

```cmake
target_link_libraries(MyPlugin PRIVATE Arrange::framework)
```

C++ 入口、`EditorConfig`、`useLive`、`useDist` 与 Debug / Release 加载规则见 [App入口](02-App入口.md)，native 外部消费约定见 [Native包消费与FetchContent契约](30-Native包消费与FetchContent契约.md)。

# Authoring 流程

1. `arrange create` 创建标准工程，或 `arrange adopt` 收编已有工程。
2. 用户在 `ui/` 中编写 Arrange App。
3. 用户在 `native/` 中编写 JUCE 插件。
4. `arrange dev` 启动开发环境。
5. `arrange build` 构建并默认整理 artifacts。
6. `arrange package` 可单独整理已有构建产物。

# 涉及模块

用户显式使用：

- `arrange`。
- `@arrange/framework`。
- `Arrange::framework`。

内部模块边界见 [模块边界](03-模块边界.md)。
