# 目标

Arrange 从一开始就同等支持 Windows / macOS 双平台（用户可在这二平台使用 Arrange 为这二平台开发插件，维护者也可以在这二平台上开发和构建 Arrange）。
目标不是后期移植，而是让 native 代码默认就是跨平台代码。

# 首批平台

- Windows：Visual Studio 2022 / MSVC。
- macOS：Xcode clang，macOS 11+。

Linux 属于可评估平台，不进入 Windows / macOS 首批发布矩阵。

# 构建原则

内部 native 构建统一使用 CMake。

建议提供：

```txt
CMakePresets.json
  windows-msvc-debug
  windows-msvc-release
  macos-debug
  macos-release
```

IDE 工程由 CMake 生成，不维护手写 Visual Studio / Xcode 工程。

# Native 分层

```txt
arrange_core       纯核心：scene state、layout tree、布局、Modifier、dirty attribution、hit-test、DrawOps build
arrange_quickjs    JS 宿主：QuickJS-NG、模块加载、binding、event slot registry、slot update binding
arrange_juce       JUCE 适配：Editor scene host、VBlankSource adapter、Graphics passive paint、输入 adapter、字体、资源、DiagnosticsScene
```

原则：

- `arrange_core` 不直接碰 OS API。
- `arrange_core` 不依赖 VST3 / AU / Standalone 具体格式。
- 平台差异收口到 `arrange_juce` 或极小 platform adapter。
- 不在核心代码里散落平台 `#ifdef`。

# Platform Services

核心需要平台能力时，通过接口注入：

```cpp
TextMeasurer
ImageLoader
ResourceResolver
VBlankSource
TaskRunner
Clipboard
ImeAdapter
```

JUCE 实现放在 `arrange_juce`。

# UI owner 线程

Arrange UI runtime 采用单 UI owner 线程模型。默认 UI owner 是 JUCE message thread。QuickJS、Arrange Vue runtime、InputIntent queue、RuntimeStore、MutationTransaction queue、SlotUpdateBatch、NativeScene / scene state、layout tree、FramePlan、PublishedFrame、VBlankSource 状态和 JUCE Component 状态都归 UI owner。

辅助线程只能执行 HMR socket、文件读取、资源解码、日志写入等后台工作，并把不可变事件或结果 post 回 UI owner。跨平台实现不得直接从辅助线程访问 QuickJS、Arrange Vue runtime、SlotUpdateBatch、layout tree、MeasureAndLayoutEngine、DrawOpsBuilder、FramePlan、PublishedFrame、VBlankSource 状态或 JUCE Component。

线程与帧阶段的长期规则见 [调度线程与帧阶段](26-调度线程与帧阶段.md)。

# QuickJS-NG

Arrange 首选 QuickJS-NG 作为 JS 引擎。

策略：

- QuickJS-NG 作为私有 third_party 依赖。
- 固定 release tag，不追 main。
- 静态编译进 Arrange native。
- 本地 patch 尽量为 0。
- 升级通过专门任务和回归测试完成。
- Release 插件不依赖系统 QuickJS 或外部 QuickJS 动态库。

边界：

- 只有 `arrange_quickjs` 可以 include QuickJS-NG 头文件。
- 其他模块只依赖 Arrange 自己的 JS 宿主接口。
- QuickJS-NG C API 不进入公开 API。

# 路径与资源

路径解析统一经过 `AppResolver`。

原则：

- 不依赖进程当前工作目录。
- `config.app.useDist(path)` 由运行期 Resolver 按发布包根解析；缺省就是 `ui/`。
- 旧静态工厂 `App::fromHere/fromPath/defaultApp` 不再作为 API 存在。
- Windows / macOS 路径差异由统一 resolver 吃掉。
- Release 默认加载运行时 `ui/` 产物包目录。
- Windows 可执行文件同级目录、macOS bundle 的 `Contents/Resources`、VST3 bundle 的资源目录，都由 `AppResolver` 统一发现。
- Debug 是否启用 live，不改变 dist 的打包位置和运行期发现。
- 显式路径优先于默认路径。

# 脚本

跨平台脚本优先使用 Node：

```json
{
  "scripts": {
    "build:native": "node scripts/build-native.ts",
    "test:native": "node scripts/test-native.ts",
    "dev:demo": "node scripts/dev-demo.ts"
  }
}
```

Node 脚本调用 `cmake --preset`、`cmake --build`、`ctest` 等命令。

避免维护 bash / PowerShell 双份脚本。

# 平台差异清单

需要重点约束：

- 字体与文本测量：布局测结构数据，截图只做人眼 artifact。
- HiDPI / 缩放：`dp` 是逻辑坐标（已经过平台缩放处理），`px` 是实机物理像素。
- IME：平台文本输入能力通过 `ImeAdapter` 进入 TextLayoutService、Input state 与 FramePlan 链路。
- 鼠标滚轮 / 触控板：进入 Arrange 后统一成滚动事件。
- 插件 bundle 路径：Standalone / VST3 / macOS bundle 均由 `AppResolver` 处理。
- macOS codesign / quarantine：发布期处理，不污染核心链路。

# 测试矩阵

快速测试至少覆盖：

```txt
Windows:
  configure native
  build native tests
  run native tests
  build demo Standalone
  build demo VST3
  pnpm test

macOS:
  configure native
  build native tests
  run native tests
  build demo Standalone
  build demo VST3
  pnpm test
```

真实宿主测试不进快速 CI，作为手工或夜间验收：

- JUCE AudioPluginHost。
- VST3 测试宿主。
- Ableton 等真实宿主。

# 禁止事项

- 不在 `arrange_core` 里散落平台判断。
- 不在 audio thread 调 JS。
- 不跨线程直接碰 QuickJS-NG。
- 不在公开 header 泄露 QuickJS-NG 类型。
- 不依赖系统安装的 QuickJS。
- 不要求用户手写平台分支才能接入 Arrange。

# 重大提醒

写 C++ 一定要按照Google风格 + 缩进为4 + 赋值、单句if/for 等情况，不可折行（即使不折行，该行会太长）。
如果 native 有大量变更，必须 cmake 彻底 clean configure + clean build，而不是增量编译，不然 cmake 的构建产物会有严重问题
