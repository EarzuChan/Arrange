# macOS 路径与编译器整改验收

本轮仅整改主人批准的两项：验收树误拒绝 `/var` 系统别名，以及原生验收脚本把 `clang++` 解析为 `clang`。QuickJS 执行预算与 Koffi 安装策略未修改，显示重做仍按后续安排处理。

## 修改与回归边界

- NativeBuildTree 在 macOS 只解析验收树外部父目录的物理路径，再检查验收树自身；后续归属记录、删除事务与恢复使用该物理目录。不解析目标链接来获得删除权限，没有 `/var` 特例。Windows 保留原有路径处理与检查顺序。
- 新增真实 macOS 文件系统回归：父目录别名与物理路径共享增量和源码引用；尚未创建的中间目录；身份变化和显式 clean；删除隔离后未记录进度的恢复。目标链接、文件、未知非空目录、错误源码归属、源码祖先拒绝处理，并断言用户内容保留；清理树内文件链接不会删除外部文件。
- native-toolchain 在 macOS 保留平台发现的 `clang++` 调用路径，C 编译器仍为同目录 `clang`；Windows 的编译器 realpath、MSVC 环境及参数未改。配置身份变化沿用现有完整验收树重建机制。
- 既有 FetchContent 消费者夹具增加标准库字符串与异常处理依赖，实际编译、链接和运行覆盖 C++ 驱动契约，不另造平台发现逻辑。
