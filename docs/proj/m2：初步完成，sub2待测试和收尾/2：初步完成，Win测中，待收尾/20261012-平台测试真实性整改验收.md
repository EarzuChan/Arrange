# 平台测试真实性整改验收

日期：2026-10-12。环境：Windows x64、Node 24.16.0、VS Build Tools 2026 / MSVC 19.50、Windows SDK 10.0.26100、CMake 4.2.3、Ninja 1.12.1。规则唯一依据为[测试策略](../../../arch/22-测试策略.md)，进度与主人双端验收待办见[M2.2 最后工作](M2.2的最后工作中.md#主人后续验收)。

## 本轮实现

- 删除 CMake 测试中的平台变量覆盖、假 attrib、shell helper，以及对方平台服务和虚构产物的执行。平台分歧采用当前宿主，Mac 用例在 Windows 明确标为不适用。
- Windows 真实编译 ICO/RC，读取 EXE 的 icon 资源数量及内容摘要；同路径图标更新改变资源，移除后受管资源不存在，手工资源保留。VST3 的 desktop.ini、目录属性和清理使用真实 attrib。中文与空格路径保留。
- VST3 manifest helper 使用本机 C++ 编译产物；真实执行特殊路径、UTF-8 JSON 输出、退出码 7 传播，不通过假 shell 脚本验证。
- Windows 大小写与 configure 取消恢复使用真实 CMake 进程、缓存和 File API；普通参数编排、受控输入与事务失败注入只证明对应契约。
- 打包夹具生成本机实际 exe/bundle、DLL 和 File API。Windows DLL 实际编译、定位和复制，打包后的 Standalone 实际执行成功；产品改名由真实 CMake 重建与 native receipt 产生。文件清理与事务回退沿用完整行为覆盖。
- Mac 签名测试改为真实 codesign 正常链路，覆盖 ad-hoc、unsigned、identifier/entitlements 保持、签后损坏和逐阶段取消。身份签名不降级是独立纯策略判断，不冒充真实 Developer ID 身份签名验收。
- 框架测试及消费者验证复用本机工具发现，移除 common.ts 的硬编码安装路径和 Windows shell 字符串编排。test:native 构建全部测试并串行执行 CTest；Windows 滚轮断言缺少系统设置前提时失败，不再内部跳过后报成功。
- 新增统一平台验收入口与 JSON/JUnit 证据；本机未验证跳过使正式验收失败，报告不把对方平台排除计为本机通过。报告器有真实子进程回归。
- 终端算法测试适配实际 ASCII/Unicode 输出，不设置虚假的宿主平台；xterm 仍只验证绘屏与输入语义。根 TS 工具入口统一使用 tsx loader，修复 Windows build:packages 旧入口问题。

## GeldBlacqMan

通过本机全局 arrange 的真实 PTY，执行 `arrange build --flavor debug --product standalone vst3`，UI、native、打包均成功。实际交付为 Windows x64：Standalone 约 29.1 MB，VST3 约 26.8 MB；真实 JUCE helper 生成 moduleinfo.json，名称 GeldBlacqMan、版本 1.0.0、厂商 Bach，交付清单包含匹配的 UI/native 构建记录。

这证明正式 CLI 的本机编排与实际 JUCE 构建整理；VST3 在宿主中加载、鼠标与精密触控板、IME、窗口体验仍由主人实机验收，不与自动化结论混同。

## Mac 与其它待验边界

本轮没有 Mac 实机运行，9 个 Mac 专属用例全部在 Windows 排除。Mac 需运行统一入口、Release native、QuickJS 分支；逐项检查 bundle、ICNS 系统解码、codesign、可执行产物、工具发现、进程清理与取消恢复，然后在 Terminal/iTerm 和真实项目验证交互。历史 Mac 结果不替代本轮改动验证。

Windows arm64 未验。Developer ID 证书、notarization 和公开远端发布仍属于其它议程；不通过伪造签名或本地源码宣称它们已通过。框架测试目前仍借用 Demo 源码生成 UI，这是已有夹具输入，Demo 离体与私有构建脚本退役继续按既定待办推进。
