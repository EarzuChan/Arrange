# 正规化描述

第二期正规化整改已进入最终验收阶段。Arrange 已从“阶段性修正”进化为“架构级闭环”，核心成果如下：

1.  **确立唯一生产主链路**：成功构建了 `InputIntent -> RuntimeStore/MutationTransaction -> InvalidationGraph -> FramePlan -> SceneFramePipeline -> PublishedFrame -> PassivePaint` 的确定性流水线。所有生产输入（含事件、RAF、Resize、HMR、资源就绪等）均已转换为统一 Intent，不再允许绕过状态机直接触发布局或重绘。
2.  **执行精准阶段化**：`SceneFramePipeline` 现由 `FramePlan` 驱动，支持 `measure`、`layout`、`buildPaint`、`publish` 等阶段的精准执行或跳过。彻底废弃了“全量 Render”作为默认路径的苟且实现，所有 fallback 均需显式记录 reason。
3.  **职责边界收口与命名去模糊化**：完成了大规模的命名整改（如 `NativeRenderController` -> `ScenePipelineState`, `RepaintController` -> `JuceRepaintAdapter` 等），通过命名和职责约束，消除了第二生产事实源。
4.  **消除 Paint/Repaint 副作用**：`paint()` 已实现纯消费路径化，禁止在绘制期间执行状态迁移、资源加载或构建 DrawOps。资源准备（Resource Prepare）与诊断视图构建（Diagnostics Scene）已前移至帧阶段（Frame Phase），并作为 `PublishedFrame` 的一部分输出。
5.  **生产协议事实源归一**：Bridge 与 Modifier 的生产语义已完全迁移至 Typed Payload。删除了 `modifierDebugJson` 和 JS 侧的展开字段逻辑，确保 C++ 编译路径与 JS 写入路径共享唯一 Schema。
6.  **TypeScript 与自动化验收基线**：源码层级实现 Strict Typecheck。建立了 headless deterministic 验收机制，通过静态扫描、单元测试与 Native Smoke 证明了主链路的合规性。

# 简要工作日志

1.  **架构文档与 ADR 落地**：修订长期文档，新增 `ADR 006` 确立统一输入/状态/帧计划模型。
2.  **TS 正规化深水区**：补齐核心 runtime 类型，将 `renderer.ts` 升级为 Typed `BridgeOpWriter`，废弃 JS 侧 Modifier 展开逻辑。
3.  **Bridge/Modifier 协议收口**：C++ 引入 `parseModifierPayload` 直接编译，生产代码中彻底清除对 `modifierDebugJson` 及 `__arrangeModifier.N.*` 展开字段的依赖。
4.  **精准 Pipeline 改造**：重构 `SceneFramePipeline`。`hasTransaction` 不再盲目推导布局，增加 `EventSlot`、`PaintOnly` 等精准失效路径，并在 `FramePlan` 中记录阶段决策。
5.  **Paint 纯消费化与资源前移**：禁止在 `paint()` 中构造错误屏或加载资源。`ImageResourceCache` IO 逻辑前移至帧阶段，缺失资源通过诊断状态上报。
6.  **Diagnostics 真视图化**：建立 `DiagnosticsScene` 独立场景，错误屏/Badge/Toast 均复用统一流水线生成 DrawOps，并作为 `PublishedFrame` 的产物供 Paint 消费。
7.  **命名与职责大洗牌**：批量重命名 `NativeRenderController`、`PointerDispatcher`、`InputController` 等对象，将职责收缩为 Adapter、State 或 Owner，消除其调度中心属性。
8.  **Input Intent 全覆盖**：将 Pointer、Wheel、Key、IME、Resize、HMR、PackageLoad 等全部纳入 `InputIntent`。
9.  **最终验收与静态扫描**：通过自动化测试及静态扫描，确认生产代码中已无 `full repaint latch`、`side-paint resource loading` 等硬性红线违规。当前代码侧已符合第二期验收标准，后续仅需主人进行 GUI/Demo 人工体验确认。
