# 正规化描述

本轮正规化旨在清理 M1 阶段遗留的结构性债务，将 Arrange Runtime 调整为符合 Compose-like 思想的确定性模型：

*   **唯一主链路**：建立“事件/RAF → JS Composition → MutationTransaction → Native Apply → Render Pipeline → Passive Paint”的统一调度逻辑。
*   **职责重构**：彻底拆除上帝对象 `ArrangeEditor::Surface`，将逻辑下沉至 `CompositionHost`、`NativeRenderController`、`FrameCoordinator`、`InputController` 等独立职责边界，Editor 退化为 JUCE 壳层。
*   **原子化与稳定性**：引入 `MutationTransaction` 和 `EventSlotId`，根治了生命周期不一致导致的随机崩溃；输入事件与回调替换现在受原子事务边界保护。
*   **显式驱动**：建立 `FrameCoordinator` 与 `EditorFrameClockController` (支持 vblank)，取代分散的定时器；所有输入、动画、重组均进入统一事件队列调度。
*   **工程纪律**：全库移除 `mjs` 残留，全面 `TS` 化；禁止通过不稳定的屏幕自动化进行回归测试，统一使用确定性的 headless runtime smoke 覆盖核心链路。

# 简要工作日志

*   **阶段 0-1 (架构解耦)**：引入 `NativeScene` 与 `MutationTransaction`；将编辑器逻辑拆分为 20+ 个功能控制器（Paint, Input, Interaction, Package 等），消除 `Surface` 对业务逻辑的直接耦合。
*   **阶段 2-3 (驱动正规化)**：实现显式 `FrameCoordinator`，将事件分发（Event Queue）与帧驱动（Render Pump）下沉至 RuntimeFacade，实现 `paint()` 的完全被动化。
*   **阶段 4 (TypeScript 化)**：清理全库 `.mjs` 和 `callbackHandle` 遗留，定义严谨的类型约束接口；完成生产环境代码与测试脚本的 TypeScript 重构。
*   **阶段 5-6 (驱动与交互)**：建立 vblank-aware 帧驱动机制；引入 Deterministic Smoke 测试集（覆盖连点、滚动、输入提交），替代不可靠的 GUI 自动化。
*   **阶段 7 (收尾与审计)**：更新 ADR 005 与架构文档；完成 completion audit，确认主链路符合正规化质量红线，代码风格及职责边界已固化。

**结论**：本期正规化目标已达成，系统初步具备了正规的 Compose-like 执行模型，遗留的结构性崩溃根源已消除。
