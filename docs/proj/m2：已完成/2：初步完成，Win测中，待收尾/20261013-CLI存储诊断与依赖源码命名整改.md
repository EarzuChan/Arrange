# CLI 存储诊断与依赖源码命名整改

日期：2026-10-13。平台：Windows x64。macOS 本轮待实机验收；不提供 Windows arm64 或 Linux 验收结论。

## 实现与边界

存储库存改为结构化检查事实。工程、构建与依赖源码检查各自负责本领域，展示集中在 StorageReport；清理、修复依据检查结果与操作资源判断，不解析中文状态。共用记录读取器先读格式版本，再验证唯一支持结构。owner 身份、验收记录、准备结构与生产写入端共用契约。

用户级共享依赖源码唯一目录改为 deps-src，Getter 为 dependencySources；工程执行、原生验收、缓存获取、维护和恢复的资源根一致。旧路径不探测、不迁移，source: 不再是条目别名；设备上的旧目录没有删除。工程登记升为 schema 2，解决之前增加字段却未升级版本导致的误报。

inspect 输出自身记录与内容、所属工程、归属、准备状态、引用和操作占用。失联路径与无法访问设备分开；语法/身份/内容损坏与显式版本不兼容分开；引用不足保留具体阻断路径。依赖源码请求索引参与丢失条目发现。clean 扫描同时给出候选和排除原因；repair 扫描展示影响及是否可修复。未完成用户事务提示独立恢复入口。

长期规则见[存储检查](../../../arch/35-Arrange用户目录与源码缓存.md#存储检查事实与清理判定)、[维护命令](../../../arch/31-ArrangeCLI与工程模式.md#工程与用户级维护命令)、[资源协议](../../../arch/36-ArrangeCLI资源占用与进程生命周期.md#维护资源协议)。命令流程见[命令定义](命令定义.md#维护命令执行规格)。

## Windows 验收

| 范围 | 结果 |
|---|---|
| 新增库存场景 | 9/9：旧格式、字段/JSON/YAML 损坏、工程丢失/替换、设备身份不符、孤儿清理、引用保护、真实 Git 修改、链接保护、真实工作进程占用、事务阻断 |
| 最终整套 CLI | 385 项，376 通过、0 失败、9 项仅 Mac 不适用 |
| 本轮完整平台入口 | 框架 Node 221/221、当时 CLI 383 项中 374 通过/0 失败/9 项 Mac 不适用、Debug CTest 24/24；新增两个用例与展示调整后另跑最终整套 CLI |
| 实际工具链 | MSVC/CMake/Ninja；显式本机 JUCE/QuickJS 源码，独立用户目录；未宣称公网首次获取通过 |
| 正式全局 ConPTY | inspect、storage clean --scan、选择阶段 Ctrl+C 均正常退出；仅扫描和取消，未删除本机内容 |
| 静态检查 | 根/CLI 类型检查、CLI build、32 个 TS 文件格式与 git diff --check 通过 |

首轮整套回归暴露大小显示测试仍期待旧二进制单位，以及新增 CMake 诊断在 native 工具未配置时二次计算路径抛错。两者已修复，后续整套通过。设备身份用例还发现短路径与真实路径会绕过已登记的设备信息，现以资源真实路径识别并回归通过。

本机证据在仓库 .arrange/verification/：storage-facts-regression-final.txt（9 项）、storage-facts-cli-final.txt（最终整套）、storage-facts-platform.txt（完整平台）、storage-facts-cmake.txt（真实 CMake 定点）、storage-facts-pty-inspect.log、storage-facts-pty-scan.log、storage-facts-pty-cancel.log（正式 ConPTY）。主人日后谈原文在本轮修改前后逐字节比较一致。
