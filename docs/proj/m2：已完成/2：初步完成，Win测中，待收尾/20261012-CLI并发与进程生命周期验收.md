# CLI 并发与进程生命周期验收

2026-10-12，Windows x64/MSVC 本机实现与验收。长期契约见 [CLI 资源占用与进程生命周期](../../../arch/36-ArrangeCLI资源占用与进程生命周期.md)。

## 实现

- 正式 create/adopt、sync、build、pack、dev 共用命令资源计划，整组授予，不持有部分资源等待另一部分；配置变化和 SETUP 修改 buildRoot 后重新规划。
- UI 工作区、各 native 构建树、交付目录和 Live 地址分开声明，路径别名及大小写统一；pack 持续保护输入和交付提交，dev 保留占用直至工具退出。
- 系统锁与外部工具由随命令存活的工作进程持有。Windows 文件句柄锁及 Job Object 实机验证，客户端断开先清理工具和后代，再释放占用。macOS 使用 flock 与受管进程组，当前没有 Mac 真机验证。
- 源码锁纳入同一协议，移除 proper-lockfile、心跳配置与 DirectoryLock。没有超时夺锁、旧 receipt 名称回退或后台常驻服务。
- native receipt 按平台、架构与配置隔离，并采用原子写入；日志目录附 PID 和随机身份，清理不删除存活 CLI 的日志。

## 边界

当前 sync 在整个命令期间独占配置，包含交互等待，采用保守粒度。其它工程和独立 native 树可并行；同一 UI 工作区被 dev 使用时，会阻止安装、构建和依赖读取操作。

Mac 真机、Windows arm64 未验。工作进程在未知 PID 启动窗口被杀时保留占用，需要确认环境后处理；PID 重用会保守阻塞。外部手工 CMake/pnpm 和主动逃逸进程组的程序不受 Arrange 协议强制约束。
