# CLI 存储维护与验收优化

日期：2026-10-13。环境：Windows x64、Node 24.16.0、真实 MSVC/CMake/Ninja。macOS 本轮未验；Windows arm64 和 Linux 不列为支持或待验目标。

## 实现

- 原生验收统一记录源码归属和配置身份，相同身份增量；切换源码/工具链或显式 --clean 重建整个生成树，嵌套缓存同时清理。使用统一持久删除事务，未知非空目录拒绝删除。验收会话在开始前一次声明全部构建树和源码生命周期占用，CMake/CTest/原生冒烟经正式工作进程执行
- 打包文件测试使用一次本机真实编译种子，每例复制独立产物与真实 File API 模型；模型路径有明确重定位边界，副本不用于构建。产品改名仍真实重编译
- 新增工程路径登记，保存操作时间和构建根发现线索；default/custom/verification 构建可发现，YAML/owner/源码身份各保留唯一职责
- 新增 clean、storage inspect/clean/repair、recover 与 storage recover。修改前展示计划、确认后整组申请资源并重读。清理受管交付入口而保留用户额外内容；保护依赖、源码、runtime、日志与恢复材料
- configure 启动前保存新旧源码引用并集，成功后收缩。引用不完整、归属未知或资源繁忙时阻止源码清理。修复使用记录中的确切 commit，先获取核验再事务替换，影响准备凭据失效
- 文件写入、初始化、打包、删除与源码维护共用当前事务记录，领域恢复处理器独立。删除开始后只允许继续；用户修改冲突拒绝，初始化回退保留新增内容。没有旧 initializations 路径、旧 writing 状态映射或缓存格式迁移

长期规则见 [CLI 命令](../../../arch/31-ArrangeCLI与工程模式.md#工程与用户级维护命令)、[用户目录](../../../arch/35-Arrange用户目录与源码缓存.md#工程登记与维护)、[资源协议](../../../arch/36-ArrangeCLI资源占用与进程生命周期.md#维护资源协议)、[事务恢复](../../../arch/32-ArrangeCLI托管与同步模型.md#持久事务与独立恢复)和[测试策略](../../../arch/22-测试策略.md#验收构建与打包夹具复用)。命令步骤见 [命令定义](命令定义.md#维护命令执行规格)。

实机补验发现并修复两项路径问题：记录中的 Windows 短路径与终端展开的长路径误判身份；工程根 junction 下排他创建临时文件误报 EEXIST。目录身份按 realpath 比较，原子写入使用已核验父目录的真实路径；均已形成真实文件系统回归。

## 证据与边界

本机证据位于仓库 `.arrange/verification/`：

- `maintenance-platform-final.txt`、`win32-x64/framework.json`、`cli.json`、`native-debug.xml`：最终完整平台入口，已核对全部结果
- `maintenance-all-final.txt`：375 项 CLI 整套结果
- `maintenance-integration.txt`、`maintenance-complete-regression.txt`、`maintenance-storage-guards-final.txt`、`maintenance-alias-second.txt`、`maintenance-transaction-unified.txt`：维护、真实强杀、清理与路径/事务回归
- `20261013-maintenance-platform.txt`、`maintenance-native-final.txt`、`20261013-maintenance-incremental.txt`：真实原生完整及增量执行
- `maintenance-quickjs.txt`：真实 QuickJS 专门分支
- `maintenance-default-cache.txt`：公网 JUCE 首次获取失败，GitHub fetch 返回 curl 56 / SSL_ERROR_SYSCALL、early EOF，未发布半成品；不计作默认远端获取通过

原生完整入口使用独立用户目录和构建树，显式 JUCE/QuickJS 源码覆盖指向本机真实缓存。默认缓存路径的公网首次获取本轮未通过网络验证；本地真实 Git 的获取、tag/commit 核对、复用、修复、相对子模块和多进程获取已通过。不能用本地 Git 结果冒充 GitHub 或正式发布验证。

源码 schema 2 增加净化的来源与确切 commit，工程登记、事务和 ownedEntries 使用当前格式；旧缓存记录、旧清单和未知目录不自动迁移或猜测清理。主人设备的旧布局不由本轮清理。全局 CLI 仍通过工作区 junction 使用本次新 dist。
