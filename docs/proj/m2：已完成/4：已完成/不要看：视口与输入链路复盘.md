# 视口与输入链路复盘

2026-09-21，针对 Live Debug 缩放后画面和滚动范围未及时更新的实测反馈。本轮修正执行链路及其回归测试，不作为 M2.4 第三趴整体完成的声明。

## 断点与修正

1. **约束变化漏掉放置失效**：宿主已入队 Resize，流水线也会重新测量；但 LayoutEngine 仅在节点带 Layout/Structure dirty 时废弃放置缓存。视口约束变化不必带节点 dirty，导致尺寸已经重算，Modifier bounds、内容位置及后续绘制/命中仍可能复用旧结果。现在所有实际重测都会使对应放置缓存失效，测量命中缓存的无关节点仍可复用。
2. **滚动范围只随滚轮回传**：此前缺少布局完成后的范围反馈，放置也直接采用请求偏移。现在横纵向共享 ScrollSnapshot，放置立即限制偏移并记录变化；候选成功发布后才通过原有 typed 回调交付 ScrollState，失败候选不泄漏状态。首次布局、视口变化、内容变化和代码请求越界都走同一规则。
3. **反馈顺序与冗余依赖**：布局反馈在本次发布后、后续输入与挂载回调前交付，避免旧范围反馈排在新滚轮输入之前形成额外滞后；回调造成的视觉提交仍留给下一候选。范围和内容尺寸已从 Modifier 输入快照移除，避免布局输出重新唤醒无关输入求值。ScrollState 成组通知同步观察者。
4. **事件消费与帧需求混用**：键盘、拖动、滚轮及 IME 入口现在都按实际待处理工作同步帧时钟；未改变状态的指针拖动不再凭空入队。没有直接在输入回调或 paint 内调用布局。
5. **测试遗漏**：原局部工作量测试的“完整计算”副本仍可命中测量与放置缓存，现已显式使副本失效。新增真实 SFA/QuickJS/宿主回归，验证状态文本与新区域像素，不能只看发布版本号递增。
6. **反应式观察返回值误判**：新增 Modifier 观察测试发现错误处理器把具有 then 方法的 Modifier 当作 Promise。已复用 shared 的 Promise 判定，保留对异步错误的处理。

## 链路核对

| 输入或阶段 | 当前链路与验收 |
| --- | --- |
| 右下角、窗口边缘、代码设置尺寸 | 均由 ArrangeEditor::resized 读取实际尺寸，经 EditorSceneHost、RuntimeSessionState 入队 |
| 帧需求 | Resize 唤醒空闲宿主；相同尺寸无新工作；连续尺寸变化在一个帧内使用最终约束 |
| 原生布局、绘制与命中 | 重测结果驱动放置，几何进入共享绘制片段和命中快照；横纵滚动均与禁用缓存后的完整计算比较 |
| 滚轮 | 已发布几何决定目标与范围，连续滚轮保留待处理偏移，typed 回调进入响应式更新；原真实列表身份和缓存测试继续通过 |
| 内容变化与 scrollTo | 经过 Modifier/结构提交进入相同布局链路，合法偏移立即用于本帧几何，范围回传不等待额外滚轮 |
| 发布与错误 | 反馈只来自成功候选；失败保留旧帧，重试交付新范围；成功反馈不会在当前帧重新发布 |
| 键盘、文本、选区与 IME | 保留正式事件槽与原生输入失效链路，帧时钟同步与返回的消费布尔值分离 |
| 被动绘制 | JuceRepaintAdapter 消费帧计划，paint 只画已发布内容；宿主像素测试验证扩展后的区域可绘制 |

## 验证边界

- `arrange_modifier_runtime`：横纵视口扩大、缩小、越界、实例保留、完整布局对照、绘制/命中一致性、失败与重试
- `arrange_viewport_runtime`：真实 SFA 初始范围、连续 resize 合并、首帧偏移修正、反应式文本回传、内容缩短、scrollTo 越界、空闲宿主唤醒和放大区域像素
- `state.test.ts`：同步观察者读取完整快照，范围变化不重新求值滚动 Modifier
- Debug 原生 CTest 12/12、TS 测试 106/106；TS 与 SFA 类型检查通过。日志见 [原生构建与回归](不要看/第二趴/viewport-native.txt)、[TS 回归](不要看/第二趴/viewport-ts.txt)

平台鼠标拖动与程序 setSize 共用的 JUCE resized 路径已核对，自动化测试从宿主尺寸通知边界验证流水线；没有把自动化宿主测试冒充各操作系统或 DAW 的边框拖动实测。第三趴的全量帧授权、隐藏状态、事件预算及 rAF 退出仍按原待办推进。
