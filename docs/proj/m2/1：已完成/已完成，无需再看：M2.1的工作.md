# M2 第一期任务的描述

M2.1 任务的核心目标是**“外部消费体验统一化”**。通过将零散的模块统一化，将 Arrange 打造为一个开箱即用的框架整体，以降低用户的集成与配置成本。

1.  **Native 消费归一化**：废弃了 `Arrange::core` / `quickjs` / `juce` 的散装目标，统一合并为唯一的 `Arrange::framework`。移除了外部的 Feature Toggles，默认自动拉取并集成 JUCE 与 QuickJS-NG，用户只需一行 `target_link_libraries` 即可完成对接。
2.  **NPM 单包分发**：废弃了 `@arrange/runtime` 与 `@arrange/vite-plugin` 的双包模式，收束为统一的 `@arrange/framework`。该包通过 `bundledDependencies` 物理隔离并捆绑了 Arrange Vue 的运行时与编译器，对外部提供 TS-first 的单一契约。
3.  **零配置 CLI（Zero-Config CLI）**：引入了 `arrange dev` 与 `arrange build` 命令，内置了所有 Vite 插件与环境转换逻辑。用户 UI 项目不再需要手动维护 `vite.config.ts` 或安装 `tsx` 等零散依赖。
4.  **Demo 项目离体化**：彻底解除了 Demo 项目与根 CMake 的物理粘连。Demo 现在作为独立的用户工程样板存在，通过 Git Tag 或本地 Tarball 消费 `Arrange::framework` 与 `@arrange/framework`，验证了框架的生产分发能力。

# 简要工作日志

1.  **版本与协议对齐**：全仓版本升级至 `0.0.0-m.2.1`；新增 ADR 012 记录“收束为 Framework”的决策；修订了分发、消费、工具链及用户模块等母文档。
2.  **Native 侧收束**：重写了根 CMake 逻辑，默认引入 JUCE 与 QuickJS-NG；创建了 `Arrange::framework` 的大一统目标；肃清了 `ARRANGE_BUILD_DEMO` 等过时的内部开关。
3.  **NPM 侧收束**：新建并发布了 `@arrange/framework`；将 Runtime、Vite Plugin 及内部 Vue 源码进行物理打包封装；实现了 `arrange` CLI 以收拢开发与构建命令。
4.  **Demo 样板升级**：Demo UI 删除了 `vite.config.ts`，改为依赖 CLI 驱动；Demo Native 改为纯粹的离体 CMake 配置，通过路径映射消费框架。
5.  **自动化验证升级**：
    *   `verify-native-fetchcontent`：验证了通过 `Arrange::framework` 进行 FetchContent 链接的闭环。
    *   `verify-npm-package`：验证了在无配置文件环境下，CLI 构建 UI 产物的宏清理效果。
    *   `verify-npm-registry-package`：验证了注册表包的真实安装与可用性。
6.  **发布与交付**：全量通过所有 Native/QuickJS/TS 测试；正式发布 `@arrange/framework@0.0.0-m.2.1`；本地及远程 Git Tag 验证均通过。旧有分包已通过文档与标签引导停止消费。
