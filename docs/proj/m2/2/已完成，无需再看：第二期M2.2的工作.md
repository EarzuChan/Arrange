# 第二弹 M2 第二期任务的描述

M2.2 第二弹任务的核心目标是**“确立 CLI 应用层架构与工程化提效”**。通过将零散的命令脚本升级为标准化、高鲁棒性的系统架构，肃清交互层、配置层、版本筛选与错误诊断等方面的临时方案，使 CLI 的工程可维护性迈上新台阶。

1.  **地道交互与地道美式英语**：全面将 CLI 提示语言统一为纯正的美式英语。交互层废弃了字符输入（如 `y/n` 或数字编号），引入 `@inquirer/prompts` 实现了现代化的上下键选择与回车确认机制；清理了脚手架默认字段中的个人凭证信息，新增输入字段的类型与格式约束。
2.  **正规配置底层**：引入标准 `yaml` 库替换了历史的手写解析器。基于稳定的配置基础设施，实现了 `arrange.config.yaml` 与 `arrange.local.yaml` 的强类型字段校验，确保任何未知或嵌套非法字段均能精确定位并给出修复指引。
3.  **Framework 版本交互筛选**：重构了 Framework 候选版本查询机制。按最新 Tag、发布时间前五的版本进行降序排列展示，并提供“自定义版本”动态校验。不可选版本（无兼容码、兼容码不一致）会高亮标识并标注原因，且整体过程完全基于交互式方向键选择。
4.  **工程维护与产物分发正规化**：
    *   **开发时重构**：`arrange dev` 运行时若检测到调试目标 Standalone 不存在，会自动、正式地走 CMake 流程构建所需产物，避免无端挂起或报错。
    *   **发布产物布局**：规范了 VST3 与 Standalone 的分派规则，在 VST3 平台下将 UI Dist 产物精准移入 `Contents/Resources/ui` 目录，并清晰报告产物复制详情。
5.  **诊断错误输出标准化**：`renderError` 日志系统完成了去重优化。当 Stack 存在时仅保留完整的 Callstack 展示，不额外拼接重复的 Name 和 Message，并支持输出工作目录、参数、退出码及外部日志路径。
6.  **编译后发包策略**：将 `@arrange/cli` 包从“TS-first 源码分发”改为“构建后可执行 dist 分发”，`bin` 字段指向 `dist/index.js`，移除了伪 bin 包装脚本，彻底解决了隔离环境下 CLI 的 Bootstrap 引导问题。
