# 实现

## CLI 包与唯一命令入口

- 新建 `@arrange/cli`，由它独占 `arrange` 命令。
- 移除 `@arrange/framework` 的对外 CLI、bin 或命令入口。
- 建立 `arrange --version` 与 `arrange --help`。
- 建立 `@arrange/cli` 与 `@arrange/framework` 的打包验证。

## 工程模式与配置

- 实现 `arrange.config.yaml` 读取、默认值填充、严格校验和错误报告。
- 实现 `arrange.local.yaml` 读取、默认值填充、严格校验、写入和 `.gitignore` 维护。
- 将 CMake generator、本机 CMake 参数、工具路径、MSVC 环境从工程配置移入本机配置。
- 实现当前目录工程根规则：既有工程命令只读取当前目录的 `arrange.config.yaml` 与 `arrange.local.yaml`。
- 实现 CLI 与工程 Arrange 版本的兼容性检查。
- 实现 `@arrange/framework` metadata 读取，用于版本候选与 `cliCompatibility` 检查。

## 版本

- CLI 版本同步到 `@arrange/cli` package metadata 与 CLI 运行时常量。

## create / adopt

- 实现 `arrange create` 交互式创建标准工程。
- 实现 `arrange adopt` 交互式收编已有 native / UI 工程。
- create / adopt 除 `--registry <url>` 外不接收命令行参数。
- create / adopt 写文件前必须展示最终信息并等待用户确认。
- create / adopt 完成后询问是否执行 sync；若执行 sync，必须先准备本机工具链。

## 本机工具链与命令执行

- 按 [Arrange CLI 与工程模式](../../../arch/31-ArrangeCLI与工程模式.md) 实现本机工具链准备流程。
- 将业务命令、工程文件维护、本机工具链准备、外部命令执行分开，避免命令流程直接调用底层进程 API。
- 实现 Windows 本机工具链发现、询问、验证和写入。
- 实现统一外部命令执行入口，禁止业务命令直接裸调 `spawn`。
- Windows 下 `.cmd` / `.bat` 经 `cmd.exe` 执行，native CMake 与 native run 经 MSVC 环境执行。
- 底层执行错误必须转成明确提示，不得把 `spawn ENOENT`、`spawn EINVAL` 直接抛给用户。

## sync

- 实现 `arrange sync`。
- 实现 project sync：维护 CMake managed region 与 UI `package.json`。
- 实现 toolchain sync：调用 UI 包管理器 install 与 CMake configure。
- toolchain sync 执行前必须准备本机工具链。
- 实现 `--project-only`、`--toolchain-only`、`--ui`、`--native`、`--check` 及其组合规则。
- 损坏或无法安全处理的文件必须跳过并打印明确修复说明。

## dev / build / package

- 实现 `arrange dev`，默认启动 UI dev server 与 native debug Standalone。
- 实现 `arrange build`，默认 release flavor，构建 UI、构建 native，并整理 artifacts。
- 实现 `arrange package`，只整理已有构建产物，不编译、不 install、不 configure。
- 实现 `--flavor debug|release`、`--ui-only`、`--native-only`、`--no-package`、`--product standalone|vst3`、`--clean` 等命令参数。
- dev / build 执行外部工具前必须准备本机工具链。
- 实现 native 产物定位与 artifacts 布局。

## Demo

- Demo 先不改动。
- CLI 建立完成并通过审核后，再按命令迁移 Demo 为标准 Arrange 工程。
- 验证不能依赖任何特供路径或仓库内部源码直连。
