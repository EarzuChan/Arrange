# 第一弹 M2 第二期任务的描述

M2.2 第一弹任务的核心目标是**“工程体系规范化与独立 CLI 构建”**。通过将命令面与运行时解耦，建立起标准工程配置与本机开发环境的清晰边界，实现开发体验与构建链路的工业级闭环。

1.  **独立 CLI 独占命令**：新建了独立的 `@arrange/cli` 单包，独占 `arrange` 全局命令。彻底肃清了 `@arrange/framework` 与 `@arrange/vite-plugin` 内部的伪 CLI 入口，消除了打包污染与依赖泄漏。
2.  **配置双轨制与本地沙盒**：实现了项目配置（`arrange.config.yaml`）与本机配置（`arrange.local.yaml`）的物理分离。本机 CMake 产生器、参数、工具链路径及 MSVC 环境变量等均收拢至本地配置，不随项目代码版本控制传播，并自动维护 `.gitignore` 规则。
3.  **智能本机工具链准备**：目前构建了 Windows 环境下的工具链自动发现、多候选裁决、交互式补全与深度校验系统。支持通过 `vswhere` 精准定位并装载 MSVC 编译环境（`VsDevCmd.bat`），并将第三方外部工具（Vite、CMake、Ninja）的调用收敛于统一的安全执行器，屏蔽了底层 `spawn` 异常。
4.  **工程编排与模板深化**：
    *   `create` / `adopt`：支持向导式创建标准工程及收编已有工程，支持 `--registry` 用于版本元数据源头隔离，自动生成完整的 JUCE AudioProcessor C++ 脚手架模板。
    *   `sync`：实现了 CMake 受控区域（Managed Region）与 UI 依赖的安全同步，遇到文件损坏时提供异常隔离。
    *   `dev` / `build` / `package`：提供了开发、构建与多格式产物整理的完整工作流；支持 `arrangeViteApiRoot` 注入，解决开发阶段同进程 Vite 接口调用的目录重定向问题。

# 简要工作日志

1.  **独立 CLI 建立与旧入口肃清**：新建了 `cli/` 工作区项目，搞了真正高级美丽的 CLI；移除了 `@arrange/framework` 与 `@arrange/vite-plugin` 内部的 CLI 源码及 `bin` 字段。
2.  **双轨配置与本地化重构**：重构了配置文件结构，将本机专属参数移出 `arrange.config.yaml`；引入 `cli/src/local.ts` 实现了本地配置的校验、补全与写入。
3.  **工具链交互与进程管理**：编写了 Windows 平台 `vswhere` 候选收集器；废弃了可能假失败的 `cl /Bv`，改用在 VsDevCmd 环境下进行轻量级工具链可用性验证；统一了外部命令执行入口，实现了 Windows 下 `.cmd` 与 Native 命令的 MSVC 环境隔离执行。
   4.  **C++ 脚手架正规化**：将 `create` 生成的 Native Starter 占位文本替换为开箱即用的标准 Arrange Editor 入口。
5.  **发布验证升级**：
    *   修改 `pack-npm-package.ts` 与 `verify-npm-package.ts`，支持将 `@arrange/cli` 与 `@arrange/framework` 同时打包。
    *   移除了 `cli/bin/arrange.cjs` 中的 UTF-8 BOM，防止 shebang 解析失败。
    *   测试 Consumer 改为同时安装两个本地 tarball 并通过新 CLI 验证 UI 产物。
6.  **开发期端点隔离**：在 CLI 注入的临时 Vite 配置中新增 `arrangeViteApiRoot`，重定向二次构建路径至 CLI 自持目录，保障了开发期的独立性。
7.  **高标准测试与回归**：全量通过 CLI 单包测试、全局 Typecheck、Runtime/Native 测试及 Demo 临时开发端点验证。目前工作区已完成本期代码整改与验证。
