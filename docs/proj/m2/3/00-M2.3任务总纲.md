本文记录 M2.3 的具体施工任务。M2 按任务组织，不按时间、工期或阶段性凑数组织。

M2.3 的核心目标是把 Arrange 从“外部 Vue renderer 驱动 native UI”的形态，推进为“内部 Arrange Vue 与 Arrange runtime 一体化驱动 native UI”的形态。

M2.3 只有两个大方向：

1. 改造并接入 Arrange Vue。
2. 完成内部运行时正规化、FramePlan / hit-test / dirty / animation API 等系统能力。

其中第一项是最优先地基。Arrange Vue 不完成，Reactive Slot Runtime、阶段化响应式、动画与 Unified FramePlan 都只能变成外部 Vue 上的补丁，这不允许。

# 总原则

M2.3 不允许“最小闭环”“兼容性实现”“过渡期实现”“先做一点以后再说”这类口径。项目还不是完全体，旧实现没有兼容性价值。`/docs`的文档中的最终目标是最终事实源，本`/m2`下的文档要求达到的是本期任务的目标，旧代码只要不符合最终目标，就必须被替换、删除或重写。

施工原则：

- 交付状态是0%和100%的，要么做了，要么没做：不可拿所谓“最小闭环”糊弄主人。
- 不保护旧 renderer、旧 bridge、旧 prop hack、旧 timer、旧 fake slot、旧 debug JSON。
- 对一个方面进行重写时，重写必须是严格彻底的，不应保留任何历史代码，宣称什么“兼容性”也是非法的：我们没有历史包袱。
- 链路必须统一，任何核心逻辑不能“多头维护”，只能有存在单一地方的、真正的最佳实现。
- 不用“先跑起来”替代 typed schema、dirty attribution、lifecycle 与测试闭环。
- 不允许表面 API 看起来完成、内部仍靠字符串、魔法字段、旁路调度糊住。
- 每个任务都必须同时交付生产实现、内部模型、干净的生命周期、诊断和测试。
- C / C++ 新代码遵循 Google 风格。
- TypeScript / JavaScript 默认不可带有行末分号，除非不加会导致语法错误。
- 代码缩进 4 个空格。

# 完成定义

M2.3 完成时必须满足：

- 用户仍以 SFC、模板语法、`<script setup>` 与 `@arrange/framework` 编写 UI。
- 用户使用我们自己的 Vue 包用于项目开发。
- Arrange Vue compiler / runtime / reactivity / scheduler 成为生产主链路。
- host component、prop、Modifier、event、resource、reactive slot 都有明确 schema。
- Composition mutation 进入 typed `MutationTransaction`。
- UI value 更新进入 typed `SlotUpdateBatch`。
- Ref 变化按绑定位置进入 Composition / Layout / Draw / Transform / HitTest / Event / Resource 等失效域。
- 动画过程值由 VBlankSource 推进 JS Value Phase，不默认触发 component render / VNode diff。
- 同一 VBlank frame 内，MutationTransaction 与 SlotUpdateBatch 由 Unified FramePlan 消费。
- JUCE `paint()` 只读取 PublishedFrame。
- 生产路径不存在 animation timer fallback、visual frame timer fallback 或 synthetic production frame source。
- event slot、slot binding、animation binding 在 unmount、HMR、reload、error recovery、source switch、QuickJS context reset 时全部退休。
- 测试不维护 TS layout、serialization bridge、fake renderer 或任何第二生产语义。

# M2.3 不承诺

以下能力不因 M2.3 自动完成：

- Canvas 完整高频数据通道。
- Interop / APVTS 完整产品化。
- 正式 DevTools。
- 发布包完整工具链。
- 完整无障碍系统。
- 所有高级组件库或官方音频控件。

这些后续里程碑必须建立在 M2.3 的 Arrange Vue、Reactive Slot Runtime 与 Unified FramePlan 之上。
