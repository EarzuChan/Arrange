# M2.4：隐式行为清理与组件边界收紧

建立日期：2026-09-18。状态：问题收集，尚未实施。

本期承接 M2.3 后发现的 Vue/HTML 式隐式行为：自动造文本节点、根节点属性透传、事件合并、类型转换和宽松结构。治理方向是让节点、组件输入、Modifier 应用位置和事件转发明确可见。

以下均为待治理写法，不是推荐用法。示例省略从 `@arrange/framework` 导入的 `defineComponent`、`h`、`Text`、`Input`、`m` 等名称；自定义组件的定义与调用放在一起。现象来自本会话的实际编译及录制原生提交验证；叶节点条目只确认结构被接受，不声称其布局正确。

## 01．裸文本自动变成 Text

```vue
<Row>
    <ShowcaseGallery />
    恩情
    <AnimationGallery />
</Row>
```

**现象：**编译器生成 `createTextVNode("恩情")`，宿主自动创建原生 Text、写入 `text="恩情"`，再插入 Row。没有声明 Text，界面仍显示文字；未指定样式时为默认黑色、14 字号。该例另有主人实机截图佐证。

```vue
<Row>恩情</Row>
<Text>恩情</Text>
```

这两种写法也被接受：第一种自动插入 Text 子节点，第二种直接写入 Text 的文本。之前的代码并不保证必须只能显式 `<Text text="恩情" />`。

来源：[宿主适配器](../../../../packages/runtime/src/app.ts) 的 `makeTextNode`、`createText`、`setElementText`。

## 02．未声明属性穿透组件，覆盖内部 Modifier

```ts
const Xxx = defineComponent({
    setup: () => () => h(Text, { text: "内部", modifier: m.padding(8) }),
})
```

```vue
<Xxx text="abcd" :modifier="m.width(99)" />
```

**现象：**Xxx 没有声明任何 props，也没有转发输入，但最终原生 Text 收到 `text="abcd"`，Modifier 只剩 `width(99)`，内部 `padding(8)` 被覆盖。没有警告。父组件因此能越过 Xxx 的接口直接改它的内部根节点。

主人批注：另外，我不希望有什么Prop透传。什么叫“吃了就不透”？什么时候都不应该透！

来源：[组件根节点处理](../../../../packages/arrange-vue-runtime-core/src/componentRenderUtils.ts) 的 `fallthroughAttrs`、`inheritAttrs` 和 `cloneVNode`。

## 03．未声明事件自动下传，一次操作回调两次

```ts
const Xxx = defineComponent({
    setup: (_, { emit }) => () => h(Input, { onSubmit: value => emit("submit", value) }),
})
let count = 0
function onSubmit() { count++ }
```

```vue
<Xxx @submit="onSubmit" />
```

**现象：**Xxx 没有声明 `emits`。父监听器既被组件的 emit 调用，又自动落到内部 Input，与 Input 原有监听器合并。实测调用一次原生提交回调，count 从 0 变为 2。

主人批注：另外是否应该废除emits？我们不是Modifier链和Prop吗？ModelValue又应不应该废？

来源：[属性透传](../../../../packages/arrange-vue-runtime-core/src/componentRenderUtils.ts)、[事件合并](../../../../packages/arrange-vue-runtime-core/src/vnode.ts) 的 `mergeProps`。

## 04．标签之间的源码空白改变布局结构

```vue
<Row><Spacer/> <Spacer/></Row>
```

**现象：**Row 有三个原生子节点：Spacer、内容为一个空格的 Text（即：空格未被忽略+裸文本被做成节点）、Spacer。

仅把中间空格改成换行：

```vue
<Row><Spacer/>
<Spacer/></Row>
```

**现象：**Row 只剩两个 Spacer。源码排版决定是否插入有尺寸的节点；若 Row 使用 `Arrangement.spacedBy(...)`，间隔数量也随子节点数改变。

来源：[模板空白处理](../../../../packages/arrange-vue-compiler-core/src/parser.ts) 的 `condenseWhitespace`，以及第 01 项的文本节点转换。

## 05．文本类型错误被字符串转换掩盖

手写 JavaScript render：

```js
h(Text, { text: { a: 1 } })
```

**现象：**没有拒绝对象，原生收到文本 `"[object Object]"`。公开 TS 类型虽然要求 string，但 JS 或绕过类型检查的调用仍可进入。

换成模板插值：

```vue
<Row>{{ { a: 1 } }}</Row>
```

**现象：**对象被自动格式化成带换行和缩进的 JSON，再生成 Text。两条文本入口对同一种错误输入采取不同转换。

来源：[宿主输入转换](../../../../packages/runtime/src/app.ts) 的 `inputMutation`、[插值字符串转换](../../../../packages/arrange-vue-shared/src/toDisplayString.ts)。

## 06．Boolean prop 沿用 HTML 式转换

```ts
const Xxx = defineComponent({
    props: { flag: Boolean },
    setup: props => () => h(Text, { text: `${typeof props.flag}:${props.flag}` }),
})
```

| 调用写法 | setup 收到的值 | 现象 |
| --- | --- | --- |
| `<Xxx />` | `false` | 没有写 default，也被补为 false |
| `<Xxx flag="" />` | `true` | 空字符串变为 true |
| `<Xxx flag="flag" />` | `true` | 与属性同名的字符串变为 true |
| `<Xxx flag="false" />` | 字符串 `"false"` | 开发态警告后继续执行；按真假判断仍为真 |

来源：[组件 props 解析](../../../../packages/arrange-vue-runtime-core/src/componentProps.ts) 的 Boolean casting。

主人批注：另或得要求废掉这种写法，只能要`:="xxx"`的js表达式传入？另：如果传ref自动解包，又当何？value变刷新是对的，解包免写value对Vue也不是罪...

## 07．组件类型校验只警告，错误值继续进入 setup

```ts
const Xxx = defineComponent({
    props: { amount: { type: Number, required: true } },
    setup: props => () => h(Text, { text: `${typeof props.amount}:${props.amount}` }),
})
```

```vue
<Xxx amount="非数字" />
```

**现象：**setup 仍执行，收到 string，输出 `string:非数字`。开发态只有警告；实测切到生产分支，同样把错误类型交给 setup。这里记录的是自定义组件 props 校验，不与已有的原生宿主输入强校验混淆。

主人批住：同06的想法。

来源：[组件 props 校验](../../../../packages/arrange-vue-runtime-core/src/componentProps.ts) 的 `validateProps`、`validateProp`。

## 08．叶节点可以挂子节点

```vue
<Input>
    <Text text="子节点" />
</Input>
```

**现象：**编译和宿主提交都成功，原生提交中出现 `Input → Text` 的父子关系，没有报告 Input 不接受内容。原生插入检查也没有按节点种类限制内容，只检查身份、环等结构条件。不能把“允许挂入”当成“有正确的内容布局语义”。

来源：[宿主插入](../../../../packages/runtime/src/app.ts) 的 `insertHostNode`、[原生插入](../../../../native/arrange_core/src/LayoutTree.cpp) 的 `InsertChildMutation`。
