## 手测发现与修复（0.10.0 → 0.10.1）

- **首页标题文字发糊**（主人手测，Windows，对比旧版明显）：0.10.0 的图块吸附只按编辑器局部坐标算，默认编辑器原点落在整数设备像素上。实际上编辑器的逻辑整数位置乘以缩放可能落在半个像素，图块被双线性重采样。原生测试复现：缩放 1.5、原点偏移 1 个逻辑像素，与零偏移的图块最大通道差 103。修复：宿主把编辑器在窗口里的位置交给重放器，吸附按窗口坐标算，并把图块改为最近邻采样兜底；测试断言缩放 1.5、1.25、1.75 下偏移后的图块与零偏移的图块逐像素相同（整体平移若干整数像素）。
- **反复滚动反而退化为直接绘制**：降级判据把滚动新进入、本来就没建的图块也算作需要重建，内容每帧都变（悬停行随滚动更替、Lazy 项进出）时连续三次即触发，降级后不再建图块、缺口一直在，只有内容完全稳定才恢复。手动基准复现：每帧滚 40 像素并让悬停行随之更替，960 次绘制里 679 次降级。修复：降级只看内容变化覆盖可见范围的面积，不粘住；同时把图块整块重建改为只清掉并重放变化的那一块范围。基准同场景降级为 0。
- 慢滚加悬停（每帧 7 像素）：图块 0.55 ms/帧，直接重放 1.06 ms/帧（修复前图块 0.73）。快滚加悬停（每帧 40 像素）：图块 1.15 ms/帧，直接重放 1.02 ms/帧，持平略差：悬停行变化要在跨列的多块图块上各开一次 D2D 上下文，这笔开销还在，后续可考虑让图块按滚动轴取宽条形状、减少受影响的块数。

## 图块方案的历史验证记录（0.10.1，Windows）

- `test:native` 等价的全量构建与 CTest（`build/m4-native-xr`，Release）30 项通过；新增检查并入 `arrange_m3_draw`（tint 蒙版、缓存条目类型与索引）与 `arrange_retained_paint`（图块）。
- 图块对照直接绘制：滚动 0、37、300、511、1200 与缩放 2（滚动 37.5）、1.25（滚动 40）下，含中英文混排文字的列表最大通道差均为 0。
- 手动基准 `arrange_paint_bench`（视口 1280×720，原生图像目标，RTX 5070 Ti，经真实 SceneFramePipeline 发布的帧，每帧计 CPU 提交与回读同步后的 GPU 执行）：

| 场景 | 直接重放 | 图块 |
| :--- | :--- | :--- |
| 滚动列表 100 行 | 0.56 ms/帧 | 0.25 ms/帧 |
| 滚动列表 100 行，带 tint 图标 | 0.94 ms/帧 | 0.26 ms/帧 |
| 滚动列表 1000 行，带 tint 图标 | 1.15 ms/帧 | 0.34 ms/帧 |

  这里的直接重放已经含第一期的 tint 蒙版缓存；该设备的空帧地板约 0.25 ms，列表内容较轻；不能外推到真实界面。前期合成基准里 tint 图标每个约 0.3 ms，第一期之后不再每帧付出。
- 未验：macOS 上缓存转 native 图与图块的行为；Direct2D 设备丢失后的重绘；真实 Demo 的端到端帧时间。
