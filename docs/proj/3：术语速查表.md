# 术语速查表

本文只提供短定义和母文档链接，不承担具体设定解释。

# Arrange

项目名。Arrange 是面向 JUCE 的声明式原生 UI 框架。

# Arrange CLI

Arrange 工程的唯一官方 CLI，命令名为 `arrange`。详见 [Arrange CLI 与工程模式](../arch/31-ArrangeCLI与工程模式.md)。

# Arrange UI Pipeline

Arrange 的声明式 UI 主链路。详见 [架构总览](../arch/01-架构总览.md)。

# ArrangeEditor

C++ 侧主入口，托管 JUCE Editor UI。详见 [App入口](../arch/02-App入口.md)。

# App source

`useLive` / `useDist` 声明的 UI 加载来源。详见 [App入口](../arch/02-App入口.md)。

# Arrange Vue

面向 Arrange host target 的 authoring、composition 与 scheduling 前端。详见 [ArrangeVue宿主目标](../arch/27-ArrangeVue宿主目标.md) 与 [运行时](../arch/04-运行时.md)。

# SFC

Vue 单文件组件语法。Arrange Vue 使用 SFC 作为 authoring 资产。详见 [ArrangeVue宿主目标](../arch/27-ArrangeVue宿主目标.md)。

# 界面树 / LayoutTree

C++ core 中用于布局、绘制、事件与状态维护的原生 UI 树。第三期起统一命名为 `LayoutTree`；历史 `RenderTree` 命名必须重命名并收口为 `LayoutTree`。详见 [LayoutTree与NativeTransaction](../arch/15-LayoutTree与NativeTransaction.md)。

# 逻辑组件

Vue 运行时的组件概念。JUCE 不感知 Vue 逻辑组件。

# 渲染节点

Arrange 内部用于测量、放置、绘制和事件处理的节点。第三期起统一命名为 `LayoutNode`。

# Modifier

描述尺寸、内边距、背景、裁剪、对齐、事件等行为的链式对象。详见 [Modifier](../arch/11-Modifier.md)。

# 洋葱模型

Modifier 按顺序包裹节点；顺序不同，测量、绘制与事件结果可能不同。详见 [Modifier](../arch/11-Modifier.md)。

# 约束 / 测量 / 放置

Compose 风格布局流程中的核心概念。详见 [布局](../arch/09-布局.md)。

# 固有尺寸

节点在正式测量前暴露的期望尺寸能力。详见 [布局](../arch/09-布局.md)。

# dp / sp / px

Arrange 的布局、文本和物理像素单位。详见 [基础类型](../arch/10-基础类型.md)。

# DrawScope

Canvas 与绘制 Modifier 使用的绘制上下文。详见 [文本输入与绘制](../arch/18-文本输入与绘制.md)。

# UI owner

拥有 Arrange UI runtime 状态的单一线程，默认是 JUCE message thread。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# VBlankSource

Arrange 生产视觉帧源抽象。生产环境唯一实现是 `JuceVBlankSource`，由 JUCE `VBlankAttachment` 或等价 platform display-frame source 驱动。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)、[运行时](../arch/04-运行时.md) 与 [ADR 010](../adr/010-生产视觉帧源收束为VBlankSource.md)。

# VBlankReady

visible UI runtime ready 的必要阶段。没有 `VBlankReady` 时可以入队 work，但不得推进 visual frame、JS Value Phase animation tick、SceneFramePipeline visual publish 或 repaint pump。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# ManualVBlankSource

native test harness 的手动 VBlank 注入源。它不是 timer，不自动 tick，只在测试显式调用 `advanceFrame(timestamp)` 时向生产 FrameScheduler / FramePlan 路径注入一个 VBlank frame event。详见 [测试策略](../arch/22-测试策略.md) 与 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# FrameScheduler

Arrange 的帧调度语义层。它不产生帧源，只消费 VBlankTick，组织 Composition Phase、JS Value Phase、FramePlan 与 SceneFramePipeline；测试环境可由 ManualVBlankSource 手动注入同一条路径。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md) 与 [运行时](../arch/04-运行时.md)。

# Composition Phase

UI owner 上的 Arrange Vue composition 阶段，负责结构与语义状态稳定，并提交 MutationTransaction。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# JS Value Phase

UI owner 上的 UI value 阶段，负责动画、transition、computed UI value 与 reactive slot dirty，并提交 SlotUpdateBatch。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# Native Render Phase

UI owner 上的 native 输出阶段，消费 MutationTransaction 与 SlotUpdateBatch，执行 apply、dirty、measure、layout、DrawOps、hit-test、diagnostics build 与 publish frame。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# InputIntent

生产输入的统一抽象。声明式状态变化、pointer / wheel / key / IME、resize、reload / HMR、resource ready 与 diagnostics event 都必须先进入 intent / state / invalidation / FramePlan 链路。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# RuntimeStore

UI owner 上承载 native-first 状态的运行时状态模型，例如 scroll、focus、hover、pressed、text editing、diagnostics state 与 resource state。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# InvalidationGraph

记录 dirty 归因与阶段影响的失效模型，用于生成 FramePlan。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md) 与 [LayoutTree与NativeTransaction](../arch/15-LayoutTree与NativeTransaction.md)。

# FramePlan

输出阶段的唯一计划，决定 apply、measure、layout、DrawOps build、hit-test build、diagnostics build、publish frame 与 fallback。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# SceneFramePipeline

执行 FramePlan 的生产输出流水线。它可以是聚合对象，但阶段输入、输出、跳过原因与 fallback reason 必须显式可查。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# PublishedFrame

JUCE `paint()` 可读取的唯一绘制快照。paint 只能读取它并绘制，不执行状态迁移、JS、layout 或 DrawOps build。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# pending mutation queue

Composition Phase 与 SceneFramePipeline 之间的 typed mutation 队列。详见 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# SlotUpdateBatch

JS Value Phase 与 SceneFramePipeline 之间的 typed UI slot update batch。详见 [LayoutTree与NativeTransaction](../arch/15-LayoutTree与NativeTransaction.md) 与 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md)。

# Reactive Slot Runtime

Arrange Vue 中负责 typed UI slot binding、dirty slot batch 与阶段化失效的运行时。详见 [运行时](../arch/04-运行时.md)。

# Transition

多值动画状态机。target state 变化后，Transition 在 JS Value Phase 推进 child animated value，并通过 SlotUpdateBatch 进入 FramePlan。详见 [动画与Transition](../arch/28-动画与Transition.md)。

# RAF pump

QuickJS host 暴露并由 VBlankSource 推进的 `requestAnimationFrame` 链路。它不由 Promise、microtask、JS timer 或生产 timer fallback 驱动。详见 [运行时](../arch/04-运行时.md)。

# Lazy 组件

按可视范围创建和测量项目的集合组件。详见 [内建组件](../arch/12-内建组件.md)。

# 错误屏

加载、运行或热更新失败时显示的诊断界面。详见 [错误屏与重试](../arch/07-错误屏与重试.md) 与 [开发期诊断表层](../arch/25-开发期诊断表层.md)。

# 开发期诊断表层

正式 DevTools 之前的最小诊断层，包括 badge、错误屏、日志和 diagnostics toast。详见 [开发期诊断表层](../arch/25-开发期诊断表层.md)。

# DiagnosticsScene

独立于用户 App tree 的诊断视图。它不参与用户 layout / zIndex / focus / accessibility，但复用 core layout / paint / DrawOps pipeline。详见 [开发期诊断表层](../arch/25-开发期诊断表层.md)。

# DiagnosticEvent / DiagnosticsState

诊断事件与状态快照。详见 [开发期诊断表层](../arch/25-开发期诊断表层.md)。

# diagnostics toast

开发期诊断表层的短暂提示。详见 [开发期诊断表层](../arch/25-开发期诊断表层.md)。

# UI 源码项目

用户的 Node/Vite/Vue 项目。详见 [App入口](../arch/02-App入口.md)。

# UI 构建产物目录

发布包中可由 Arrange 加载的 `ui/` 产物目录。详见 [工具链与App发布包](../arch/14-工具链与App发布包.md)。

# QuickJS native boundary

QuickJS 与 C++ 的同进程 native 接入边界。它直接读取 JSValue / primitive / callback function，并构造 native typed transaction；它不是 JSON、二进制或字符串协议层。详见 [LayoutTree与NativeTransaction](../arch/15-LayoutTree与NativeTransaction.md)。

# NativeTransaction

Composition Phase 产生的 typed mutation batch。它由 QuickJS native boundary 构造，进入 MutationTransaction queue 后由 SceneFramePipeline 消费。详见 [LayoutTree与NativeTransaction](../arch/15-LayoutTree与NativeTransaction.md)。

# Parameter gesture

一次用户参数编辑的生命周期。详见 [互操作](../arch/16-互操作.md)。
