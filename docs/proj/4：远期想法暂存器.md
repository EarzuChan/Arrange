# GPU 效果与着色器

动态极光背景、实时扭曲等效果需要着色器。JUCE 目前没有开放用户着色器：Windows 的 Direct2D 渲染器只内置模糊、阴影等效果，macOS 用 Metal 合成但绘制仍在 CPU；JUCE 团队提过跨 Metal、Vulkan、DX12 的 GPU 渲染器方向，但没有时间表。

设想分两步，等 M5 的位图缓存层落地、且离屏方案成熟或 JUCE GPU 渲染器发布后再立 ADR：

1. 离屏 GPU 渲染为图像：着色器源码与 uniform 由 JS 声明，原生在离屏画到纹理、读回为图像，作为普通图像绘制交给现有片段与脏区链路；着色器源码随 UI 资源热更新；GPU 不可用时回退到静态图或低分辨率软件渲染。
2. JUCE GPU 渲染器落地后改为共享纹理、去掉读回，写法不变。

待定：着色器语言（WGSL 或 Slang 转译）与后端（Dawn、wgpu-native 或各平台原生 API）。社区反馈 Dawn 依赖重、变动快、难以接入构建。

# Arrange 专用副作用

- UI 提交等待与程序化焦点：按 [调度线程与帧阶段](../arch/26-调度线程与帧阶段.md) 设计成功、失败、取消与作用域归属，避免以微任务完成推断 UI 已建立。
- `useArrangeIdle`：等待正式调度器、MutationTransaction、FramePlan 与 SceneFramePipeline 稳定。
- `useNativeSubscription`：管理 native callback / subscription 生命周期。
- `useResourceEffect`：资源加载、释放与错误诊断绑定。

普通副作用使用 Arrange 的 `onMounted`、`onUnmounted`、`watch`、`watchEffect` 与 `effectScope`。专用副作用进入里程碑前必须重新设计 API、生命周期和测试口径；不另立公开逐帧循环入口。
