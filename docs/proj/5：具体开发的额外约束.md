# 具体开发的额外约束

本文是开发约束与代码风格的唯一事实源。其它文档不得重复定义代码风格，只能链接本文。

# 工作原则

- 绝不能“单行拆多行”：赋值、单行if-else，必须维持单行，不需要任何屏幕宽度折行！
- 以可维护为先，不可写应付、苟且的代码。
- 新增能力必须边界清楚、测试清楚、命名清楚。
- 不用临时实现冒充长期设计。
- 尽量避免魔法值、硬编码字符串和隐式约定。
- 文档和注释以中文为主，允许必要英文术语，禁止整篇纯英文。
- **缩进 4 个空格**。

# 代码风格

## C / C++

- **采用 Google 风格**。
- 新代码应减少上帝对象，按模块边界拆分职责。
- 不在 audio thread 调 JS。
- 不在公开 header 泄露私有第三方实现类型。

## TypeScript / JavaScript / Vue

- 新 runtime / tooling 源码优先 TypeScript。
- 除非必须（不加时会导致代码报错），每行代码**绝不能**加行末分号。
- 类型声明由 TypeScript 源码生成。以前手写的巨型 `.d.ts` 一定要消灭！
- `.mjs` 可作为构建产物或旧债存在；新增生产源码优先 `.ts`。

# 原生依赖约束

Arrange 的原生代码必须能在干净克隆上稳定复现。

## 工具链

Windows 首发目标：

- Visual Studio Build Tools / MSVC。
- Visual Studio 自带的 CMake，或普通安装的 CMake。

本仓库不依赖别的项目的 CLion 构建目录、不依赖别的工程里的 CMake `_deps`，也不依赖 `ArrangeOld`。

## 依赖入口

所有原生第三方依赖都通过以下入口接入：

```cmake
include(cmake/Dependencies.cmake)
```

当前固定依赖：

| 依赖 | 来源 | 锁定版本 | 用途 |
| --- | --- | --- | --- |
| JUCE | `https://github.com/juce-framework/JUCE.git` | `8.0.12` | Standalone / VST3 demo，以及后续 `arrange_juce` |
| QuickJS-NG | `https://github.com/quickjs-ng/quickjs.git` | `v0.14.0` | JS 引擎接入 |

## 干净检出覆盖

本地开发时，可指向干净检出：

```powershell
-DJUCE_DIR=C:/dev/JUCE
-DARRANGE_QUICKJS_NG_SOURCE_DIR=C:/dev/quickjs-ng
```

CMake 也支持标准的 `FETCHCONTENT_SOURCE_DIR_*` 覆盖。

拒绝的来源：

- `ArrangeOld`。
- 其他项目里复制过来的 `build/_deps/juce-src` 或 QuickJS 缓存。
- 任何硬编码到单机路径的配置。

## 构建提醒

如果原生依赖、CMake 配置或 JUCE / QuickJS 接入方式有大变化，应 clean configure + clean build，不要只信增量编译结果。
