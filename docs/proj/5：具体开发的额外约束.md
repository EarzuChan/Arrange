# 具体开发的额外约束

本文是开发约束与代码风格的唯一事实源。其它文档不得重复定义代码风格，只能链接本文。

# 工作原则

- 绝不能“单行拆多行”：赋值、单行if-else，必须维持单行，不需要任何屏幕宽度折行！（如得必须搞成 `export { onBeforeMount, onMounted, onBeforeUpdate, onUpdated, onBeforeUnmount, onUnmounted, onActivated, onDeactivated, onRenderTracked, onRenderTriggered, onErrorCaptured } from './runtime/apiLifecycle.ts'`、`if (this.scopes) for (i = 0, l = this.scopes.length; i < l; i++) this.scopes[i].resume()` 而不得换行）
- 以可维护为先，不可写应付、苟且的代码。
- 新增能力必须边界清楚、测试清楚、命名清楚。
- 不用临时实现冒充长期设计。
- 尽量避免魔法值、硬编码字符串和隐式约定。
- QuickJS 世界与C++的生产交互不得使用任何 JSON / string / binary serialization boundary；必须直接读取 JSValue 并落到 typed native transaction。
- 触碰到的文件应整理到可维护状态；不为了格式化制造巨大 diff，但也不能让缩进混乱、操作符空格混乱、旧调试残留继续作为完成状态。
- 文档和注释以中文为主，允许必要英文术语，禁止整篇纯英文。单行注释的末尾禁止带句号。
- **代码缩进 4 个空格**。

# 代码风格

## 总体来说

- 包名使用**单数**名词（动名词也行，如processing）形式，如：`style\`、`view\`、`data\`、`transforming\`

## C / C++

- **采用 Google 风格**。
- 新代码应不得有上帝对象（除非对主人三跪三求），按模块边界拆分职责。
- 不在 audio thread 调 JS。
- 不在公开 header 泄露私有第三方实现类型。

## TypeScript / JavaScript / Sfa（AXml）

- 新 runtime / tooling 源码必须 TypeScript。
- CLI 的长期重要常量（默认地址、包身份、版本要求等）统一归属 `cli/src/CliMetadata.ts`，业务模块引用，**不得散落或重复硬编码**；已有版本事实源继续通过导入读取，不复制版本号。
- CLI 的依赖创建、传递与生命周期遵循 [CLI 依赖管理](../arch/31-ArrangeCLI与工程模式.md#依赖管理)。
- 除非必须（不加时会导致代码报错），每行代码**绝不能**加行末分号。不得非必要把多行并为单行（如`import { Text } from '@arrange/framework/foundation'; import { AnimatedVisibility, Crossfade, tween, spring, linearEasing, animatedColorAsRef, animatedOffsetAsRef, animatedSizeAsRef, createTransition, animationStats } from '@arrange/framework/animation'`，你并它干啥！）。
- （如有）类型声明由 TypeScript 源码生成，不得手写 `.d.ts`！

## 格式工具

`pnpm format` 修正仓库 TS、JS 和 SFA 脚本格式，`pnpm format:check` 只检查。工具使用 TypeScript 语法树处理独立语句、导入、表达式与缩进；写入前验证语法树不变，保留必要的分号、注释和字符串内容，不改写测试字符串中的源码。

`pnpm format:native` 按根目录 `.clang-format` 修正 C++，`pnpm format:native:check` 只检查。使用 clang-format 22，可通过 `CLANG_FORMAT` 指定可执行文件路径，否则从 PATH 查找。中文文案、注释含义和逻辑分组仍需在代码审阅时确认，格式工具不猜测业务语义。

# 原生依赖约束

Arrange 的原生代码必须能在干净克隆上稳定能构建。

## 工具链

Windows 首发目标：

- Visual Studio Build Tools / MSVC。
- Visual Studio 自带的 CMake，或普通安装的 CMake。

本仓库不依赖别的项目的 CLion 构建目录、不依赖别的工程里的 CMake `_deps`，也不依赖 `ArrangeOld`。

## 依赖入口

所有原生第三方依赖都通过以下入口接入：

```cmake
include(cmake/Dependencies.cmake)
```

当前固定依赖：

| 依赖 | 来源 | 锁定版本 |
| --- | --- | --- |
| JUCE | `https://github.com/juce-framework/JUCE.git` | `8.0.12` |
| QuickJS-NG | `https://github.com/quickjs-ng/quickjs.git` | `v0.14.0` |

## 干净检出覆盖

本地开发时，可指向干净检出：

```powershell
-DJUCE_DIR=C:/dev/JUCE
-DARRANGE_QUICKJS_NG_SOURCE_DIR=C:/dev/quickjs-ng
```

CMake 也支持标准的 `FETCHCONTENT_SOURCE_DIR_*` 覆盖。

拒绝的来源：

- 如有`ArrangeOld`：这个是历史遗留工程，和当前的 Arrange 绝无任何关系，不可染指。
- 其他项目里复制过来的 `build/_deps/juce-src` 或 QuickJS 缓存。
- 任何硬编码到单机路径的配置。

## 构建提醒

如果原生依赖、CMake 配置或 JUCE / QuickJS 接入方式有大变化，应 clean configure + clean build，不要只信增量编译结果。
