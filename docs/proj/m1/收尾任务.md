M1 的 1-5 期正规化已经完成，主链路不再进入革命式大重做阶段。

本文件定义 M1 收尾化任务。收尾化不是继续推翻架构，也不是放松标准；它的目标是把已经建立起来的正规主链路进一步收紧，清除局部烂点、职责混杂、语义残留和静默容错，保证 M1 结束时的工程地基足够干净。

# 收尾原则

1. 不再更换主链路。
   - Vue/TS runtime 通过 QuickJS native API 直接调用 C++。
   - C++ 直接读取 JSValue。
   - 变更进入 typed MutationTransaction。
   - LayoutTree.apply 应用事务。
   - SceneFramePipeline 统一决定测量、布局、渲染、命中测试、发布与被动绘制。

2. 不允许旧链路复活。
   - 不允许重新引入 bridge batch/opcode。
   - 不允许重新引入 JSON/native 序列化协议。
   - 不允许重新引入字符串 value 编码。
   - 不允许重新引入 TS/headless layout 第二实现。

3. 允许局部重造。
   - M1 收尾不做革命大清洗。
   - 但 QuickJS adapter、modifier 读取、event prop 残留、prop 严格性、输入失效归因这些局部问题必须收紧。

4. 不能以“能跑”为验收标准。
   - 错误 shape 不能静默吞。
   - 未知 modifier 不能静默无效。
   - event 不能同时像 prop 又像 event slot。
   - 输入 intent 不能因入口统一而失去语义精度。

# 现存问题

## 1. QuickJS adapter 存在上帝对象风险

文件：

- `native/arrange_quickjs/src/QuickJsScriptHost.cpp`

具体问题：

- 同一个实现同时管理 QuickJS runtime/context 生命周期。
- 同一个实现同时注册 native API。
- 同一个实现同时读取 JSValue 到 C++ value。
- 同一个实现同时编译 modifier。
- 同一个实现同时维护 event slot callback。
- 同一个实现同时处理 module loading。
- 同一个实现同时处理 requestAnimationFrame/cancelAnimationFrame。
- 同一个实现同时读取 reload request。

这不是旧链路复发，但它是当前最大的职责集中点。后续任何 JS/native 互操作能力都容易继续塞进这个文件，形成事实上的 adapter 上帝对象。

## 2. modifier 读取不够严格

文件：

- `native/arrange_quickjs/src/QuickJsScriptHost.cpp`
- `packages/runtime/src/modifier.ts`

具体问题：

- C++ 侧 `readModifier` 遇到非数组 shape 可以退化为空 modifier。
- C++ 侧遇到未知 modifier type 可以直接忽略。
- 部分字段缺失时大量使用 fallback，无法区分“合法省略”和“错误输入”。
- TS 侧允许较多 `Record<string, unknown>`，C++ 侧实际支持集合没有被严格验证。

这会导致声明式输入错误被静默吞掉。Modifier 是布局、绘制、输入、滚动、事件的核心语义入口，不能容忍错误输入无声失效。

## 3. core 仍保留 event prop 语义残留

文件：

- `native/arrange_core/src/LayoutTree.cpp`

具体问题：

- `SetEventSlotMutation` 已经是事件正规链路。
- 但 `SetPropMutation` 路径里仍能识别 event prop。
- 这会造成语义歧义：event callback 到底是普通 prop，还是 event slot。

事件必须只有一条真实链路：event callback 由 QuickJS adapter 注册为 typed EventSlot，core 只通过 `SetEventSlotMutation` 和 `ClearEventSlotMutation` 理解事件槽。

## 4. PropValue 使用范围仍偏宽

文件：

- `packages/runtime/src/native.ts`
- `native/arrange_core/include/arrange/core/PropValue.h`
- `native/arrange_core/src/PropValue.cpp`

具体问题：

- TS 侧 `setProp` 仍是 `value: unknown`。
- C++ 侧 `PropValue` 仍支持递归 object。
- `stringOr`、`numberOr`、`boolOr` 等接口存在隐式转换。
- 已知核心 props 没有全部进入明确 schema。

这不是 JSON/序列化复发，但会继续制造“任意数据都能作为 native prop 传输”的错觉。第五期之后的正确方向是直接读取 JS 对象，但直接读取不等于任意对象无约束读取。

## 5. InputIntent 的失效归因仍偏粗

文件：

- `native/arrange_core/include/arrange/core/InputIntent.h`
- `native/arrange_juce/src/ScenePipelineState.cpp`

具体问题：

- pointer、wheel、key、text input、IME、animation frame 已进入统一 intent 队列，这是正确的。
- 但部分 intent 最终统一归因为 `DirtyFlag::EventSlot`。
- 这让“统一入口”有退化成“统一粗桶”的风险，所以必须严厉处理：先认真思考，规划代码，再修改。

输入统一是为了让所有外部输入进入同一 pipeline，而不是为了抹平不同输入对测量、布局、绘制、命中测试、事件派发的差异。

## 6. EditorSceneHost 仍是高耦合汇合点

文件：

- `native/arrange_juce/src/EditorSceneHost.cpp`

具体问题：

- 当前它已经主要是 host facade，状态比早期健康。
- 但它仍然汇合 package、runtime、diagnostics、interaction、pointer、text input、paint、timer、chrome。
- 如果继续向其中塞业务，会重新变成 JUCE 层上帝对象。

这不是必须拆碎的问题，而是必须冻结边界：EditorSceneHost 只能编排，不能重新承载业务细节。

## 7. 测试仍偏 smoke 汇总

文件：

- `cpp_tests/arrange_core_smoke.cpp`
- `cpp_tests/arrange_quickjs_app_smoke.cpp`
- `cpp_tests/arrange_juce_runtime_smoke.cpp`

具体问题：

- smoke 能证明主链路可用。
- 但对局部严格性的测试不足。
- modifier 非法 shape、未知 modifier、event prop 禁入、QuickJS direct read、event slot 生命周期、InputIntent 归因等都需要更具体的测试。

# 整改要求

## 1. QuickJS adapter 必须局部重造

必须把 `QuickJsScriptHost.cpp` 的职责边界收紧。

允许保持 `QuickJsScriptHost` 作为对外 facade，但以下职责不能继续混在一个大实现里：

- JSValue 基础读取。
- modifier 读取与编译。
- native API binding。
- event slot callback registry。
- module loading。

建议落地方向：

- 新增或整理 `QuickJsValueReader`：只负责 JSValue 到基础 C++ 值/对象读取。
- 新增或整理 `QuickJsModifierReader`：只负责 JS Modifier 对象到 `CompiledModifier`。
- 新增或整理 `QuickJsEventRegistry`：只负责 EventSlotId 到 JS callback 的生命周期。
- 新增或整理 `QuickJsNativeApi`：只负责注册 `__ARRANGE_NATIVE__` 及 native function。
- 新增或整理 `QuickJsModuleLoader`：只负责模块解析与加载。

验收标准：

- `QuickJsScriptHost.cpp` 不再直接承载全部 adapter 细节。
- modifier 读取逻辑不再与 runtime lifecycle 混在一起。
- event slot 生命周期不再散落在 native API function 内部。
- QuickJS adapter 仍然只是一条链路：直接读 JS object，不引入任何序列化或 JSON。

## 2. modifier schema 必须严格化

必须收紧 modifier 输入。

要求：

- 非法 modifier shape 必须报错或进入明确诊断。
- 未知 modifier type 必须报错或进入明确诊断。
- 必填字段缺失必须报错或进入明确诊断。
- 只有明确声明为可选的字段才允许 fallback。
- TS 侧暴露的 modifier 与 C++ 侧支持的 modifier 必须一致。

禁止：

- 非数组 modifier 被当作空 modifier。
- 未知 modifier 被直接忽略。
- 错字段名导致静默无效。
- 用“兼容未来扩展”为借口吞掉当前错误。

验收标准：

- 有测试覆盖非法 modifier shape。
- 有测试覆盖未知 modifier type。
- 有测试覆盖缺少关键字段。
- demo 不因严格化破坏正常 modifier。

## 3. event prop 残留必须清理

必须让 event callback 只有一条链路。

要求：

- core 中 `SetPropMutation` 不再识别 event prop。
- event callback 只能由 QuickJS adapter 注册为 `SetEventSlotMutation`。
- event callback 删除只能由 `ClearEventSlotMutation` 表达。
- 如果 TS/QuickJS 层把 event callback 作为普通 prop 传入，必须在 adapter 层拒绝或诊断。

验收标准：

- `LayoutTree.cpp` 不再存在 event prop 兜底判断。
- event slot 测试仍通过。
- click、scroll、text input update/submit/change/blur 仍可用。

## 4. PropValue 必须限定为受控 carrier

M1 收尾不要求彻底删除 `PropValue`，但必须收紧口径。

要求：

- 明确 `PropValue` 是 native prop carrier，不是任意对象传输协议。
- 已知核心 props 的读取应尽量走明确 schema。
- 数值、布尔、字符串等核心类型不应依赖宽松隐式转换。
- `value: unknown` 的影响范围不能继续扩大。

禁止：

- 以 `PropValue` 为理由重新实现任意对象序列化。
- 以 `unknown` 为理由跳过 schema 校验。
- 对 layout/paint 关键字段进行危险隐式转换。

验收标准：

- 新增/调整代码时不扩大 `PropValue` 的任意对象使用范围。
- 核心 prop 读取错误能被测试或诊断捕获。

## 5. InputIntent 失效归因必须更精确

必须保持统一入口，但提升 dirty attribution 精度。

要求：

- resize 明确影响 layout。
- resource ready/failed 明确影响 resource/paint，并按需要影响 diagnostics。
- diagnostics 明确影响 diagnostics/accessibility。
- pointer/wheel/key/text input/IME/animation frame 不应全部无脑归为同一语义。
- 能携带 target/eventSlot/reason 的 intent 必须尽量保留。

验收标准：

- `ScenePipelineState.cpp` 中不同 intent 的 dirty attribution 更具体。
- pipeline plan 能体现不同输入对 measure/layout/buildPaint/buildHitTest/buildDiagnostics 的不同影响。
- 不破坏统一 intent 队列。

## 6. EditorSceneHost 只能作为 host facade

要求：

- `EditorSceneHost` 可以继续作为 JUCE editor 的门面。
- 新业务不得直接塞入 `EditorSceneHost::Impl`。
- package、runtime、diagnostics、input、paint、timer 等业务细节必须继续由各自 owner/adapter 承担。

验收标准：

- 收尾期间不得让 `EditorSceneHost.cpp` 明显膨胀。
- 若必须新增能力，应优先放入现有明确职责类，或新增小的 owner/adapter。

## 7. 测试必须补强局部严格性

必须新增或调整测试覆盖收尾重点。

至少覆盖：

- QuickJS 直接读取 JS object，不经过 JSON/序列化。
- 非法 modifier shape。
- 未知 modifier type。
- event callback 不走普通 prop。
- event slot 注册、替换、删除生命周期。
- scroll callback 仍走 typed JS object。
- reload request 仍走 typed JS object。
- InputIntent 到 pipeline phase 的精确归因。

验收标准：

- C++ 测试通过。
- TS 测试通过。
- debug/release stand/vst clean build 通过。
- 需要人工验收的 demo 行为留给人工，不用模拟操作冒充人工测试。

# 禁止事项

1. 禁止重新引入 JSON/native value bridge。
2. 禁止重新引入字符串 value 编码。
3. 禁止重新引入 BridgeOp/BridgeBatch。
4. 禁止重新引入 headless layout。
5. 禁止维护多套 modifier 处理链路、event callback 链路。一定要“祖国统一”，禁止分裂。
6. 禁止把错误输入静默降级为“无效果”。
7. 禁止为了拆分而拆碎；只允许按真实职责边界局部重造。

# 验收标准

M1 收尾完成必须同时满足：

1. 主链路仍是唯一链路。
2. 无 JSON/序列化/bridge/string value 编码复发。
3. QuickJS adapter 职责边界清晰。
4. modifier 输入严格，错误输入可诊断。
5. event callback 只有 EventSlot 链路。
6. PropValue 未继续扩散为任意对象协议。
7. InputIntent 保持统一入口，并具有更精确失效归因。
8. EditorSceneHost 没有重新膨胀为业务上帝对象。
9. 测试覆盖收尾重点。
10. debug/release、stand/vst clean build 通过。
