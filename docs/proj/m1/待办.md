## 1. 动画链路（自动化已收口，人工视觉已确认）

目标：比如 `animateColorAsState` 必须真实平滑渐变，不能只在目标变化时跳变。

本项已按 `docs/adr/003-NativeFrameClock与动画刷新链路.md` 补齐 native FrameClock / RAF pump：

- JS runtime 保留动画语义、easing、插值和 Vue 生命周期。
- QuickJS host 提供 `requestAnimationFrame` / `cancelAnimationFrame` / `performance.now`。
- ArrangeEditor 使用 native timer tick 驱动 `pumpAnimationFrame(now)`，动画期间升至 60Hz，结束后停止或降回 dev/diagnostics timer。
- 每个 tick 都走 `RAF callback -> Vue update -> Bridge incremental batch -> RenderTree apply -> dirty/layout/paint -> repaint`。
- 禁止用 Promise / microtask 伪造 animation frame。
- reload / HMR reload / unmount / 错误恢复 / source 切换随 QuickJS context reset 清理 pending RAF。

检查链路：host frame clock / reactive state / bridge prop / native dirty / repaint / DrawOps 的具体参数都应随 tick 连续变化。

已补自动化回归：`scripts/test-quickjs-app.mjs` 的 `quickjs-animation-fixture` 覆盖 `animateColorAsState` 随 host clock tick 产生中间色 `0xff808080`，并经 Bridge / RenderTree / PaintModel DrawOps 到达最终色 `0xffffffff`。

已验收：Debug Standalone 人工确认视觉平滑，不跳变。

## 2. 诊断表层组件化与 overlay 锚点

目标：badge / toast / 错误 overlay 属于诊断 overlay，不参与用户 root layout，也不被用户内容挤压。
组件化的意思是：不要让这狗屁的东西直接调用g来画，而是和用户的组件一样，走标准Arrange生命周期。这么看，这玩意应远不合格。

要求：

- 诊断表层已先从 `ArrangeEditor.cpp` 抽为 `DiagnosticsOverlay`：事件记录、日志、badge、toast、错误屏绘制不再散落在上帝对象里。
- `ArrangeEditor` 只保留运行状态快照、timer / repaint 调度、Retry 等宿主事件入口。
- overlay 锚定 editor 可视区域，不参与用户 root layout / input。

验收：Debug Standalone / VST3 中 badge 与 toast 位于 editor 可视区域右上角附近；Release 默认隐藏时不影响用户 UI。
