第一期收尾化已经把 M1 主链路收紧到基本可封存状态。第二期收尾化继续延续：不推翻主链路，也不做革命式大清洗，而是：继续把 final review 中确认的轻微欠债彻底收束干净。

本期核心原则：**宁可少暴露，也不要假暴露；凡是公开 API，必须有 TS API、QuickJS reader、core/native 语义、pipeline 行为、测试覆盖的闭环。**

# 收尾原则

1. 主链路不变。
   - Vue/TS runtime 仍通过 QuickJS native API 直接调用 C++。
   - C++ 仍直接读取 JSValue。
   - 变更仍进入 typed MutationTransaction。
   - LayoutTree 与 SceneFramePipeline 仍是唯一 native UI pipeline。

2. 不接受“半支持”。
   - TS 暴露但 native 不执行，错误。
   - native 有字段但 pipeline 不使用，错误。
   - 未来会支持所以现在先放着，错误。
   - 可以留下中文注释说明“将来添加回来”，但当前公开面必须干净。

3. 不做兼容包袱。
   - M1 尚未对外发布，不需要兼容错误 API。
   - 已经确认是孤儿、半吊子、假支持的公开面，必须删除。

4. prop 必须 schema 化，semantics 留待以后正规化。
   - 直接读取 JS object 不等于允许任意对象横穿 native。
   - PropValue 只能是受控 carrier，不能重新变成“任意数据协议”。
   - testTag / accessibility / inspector 所需 semantics 通道本期不半吊子恢复；以后必须作为独立专题正规添加回来。

# 现存问题

## 1. `pointerInput` 是半支持 API

文件：

- `packages/runtime/src/modifier.ts`
- `native/arrange_quickjs/src/QuickJsModifierReader.cpp`
- `native/arrange_core/include/arrange/core/Modifier.h`
- `native/arrange_core/src/Modifier.cpp`

具体问题：

- TS 公开 `Modifier.pointerInput(handler)`。
- QuickJS reader 只把它读成 `result.input.pointerInput = true`。
- `handler` 没有注册为 callback。
- core 没有 `PointerInput` EventSlot。
- pointer dispatch 当前实际只支持 clickable / scroll 等已落地路径。

这会造成“用户以为 pointerInput 能用，但 handler 永远不会被调用”的假支持。

## 2. FocusRequester 是孤儿 API

文件：

- `packages/runtime/src/state.ts`
- `packages/runtime/src/modifier.ts`
- `native/arrange_quickjs/src/QuickJsModifierReader.cpp`

具体问题：

- `state.ts` 仍导出 `rememberFocusRequester`、`useFocusManager`、`FocusRequester`。
- `Modifier.focusRequester(...)` 已经不在公开 modifier API 中。
- QuickJS reader 明确拒绝 `focusRequester` / `onFocusChanged` / `focusProperties` / `focusGroup`。
- native focus 目前只覆盖 Input 自身的 focus、caret、IME、text session，不存在 JS 请求 focus 的正规链路。

这会造成“用户能 import focus requester，但没有正规挂载路径”的孤儿公开面。

## 3. PropValue / `setProp(value: unknown)` 仍有任意 carrier 气味

文件：

- `packages/runtime/src/native.ts`
- `native/arrange_quickjs/src/QuickJsNativeApi.cpp`
- `native/arrange_quickjs/src/QuickJsValueReader.cpp`
- `native/arrange_core/include/arrange/core/PropValue.h`
- `native/arrange_core/src/PropValue.cpp`
- `native/arrange_core/src/Layout.cpp`
- `native/arrange_core/src/Paint.cpp`
- `native/arrange_juce/src/TextInputLayoutModel.cpp`
- `native/arrange_juce/src/TextInputOwner.cpp`

具体问题：

- TS 侧 `setProp` 仍接收 `value: unknown`。
- QuickJS 侧 `propValue` 仍递归读取 object。
- core 侧仍通过 `objectProp` / `stringProp` / `numberProp` / `boolProp` / `colorProp` 分散读取 props。
- 当前虽然已经移除宽松跨类型转换，但 prop key、prop shape、合法对象结构尚未统一 schema 化。

这不是旧 JSON 链路复活，但如果继续放任，会形成新的“任意对象 native prop 协议”。

## 4. testTag / semantics 没有正规通道，但本期不做

文件：

- `packages/runtime/src/modifier.ts`
- `native/arrange_core/include/arrange/core/Modifier.h`
- `native/arrange_core/src/LayoutTree.cpp`
- `cpp_tests/arrange_core_smoke.cpp`
- `cpp_tests/arrange_quickjs_app_smoke.cpp`

具体问题：

- 第一阶段已删除 demo 中的 `testTag` 占位使用，这是正确的。
- 但测试、Inspector、accessibility 未来都需要稳定的声明式 metadata 通道。
- 当前没有 `CompiledModifier.semantics` 或等价结构。
- 不能把 `testTag` 再作为普通 layout/paint/input modifier 偷偷塞回去。

semantics 应当是独立、正规、可测试的语义通道，而不是临时调试字段。

本期结论：

- 不恢复 `testTag`。
- 不新建 semantics core 通道。
- 不把 semantics 塞进普通 prop map 冒充完成。
- 只保留中文注释说明：将来会把 semantics / testTag 作为完整正规通道添加回来。

# 整改要求

## 1. 删除孤儿 API，并留下中文关于将来添加回来的提示注释

要求：

- 删除当前公开但没有完整 native 闭环的 API。
- 删除后可以在原位置或相邻位置留下中文注释，说明该 API 将来会以正规闭环方式添加回来。
- 注释需是中文，且必须表达“现在故意不公开，等 native 语义、pipeline 与测试齐全后再添加回来”。

必须删除或收口：

- `Modifier.pointerInput(handler)`。
- `rememberFocusRequester`。
- `useFocusManager`。
- `FocusRequester` 类型。

禁止：

- 删除 TS API 但保留 C++ 假字段。
- 保留 C++ 字段但 pipeline 不使用。
- 用英文 TODO 或含混注释替代明确中文说明。
- 以“后面会做”为理由继续暴露半支持 API。

验收标准：

- 用户无法从 `@arrange/runtime` 正常调用这些孤儿 API。
- native reader 遇到这些 modifier 名称必须拒绝。
- core 中不再保留无用途的 pointerInput 字段。
- 测试和 demo 不依赖这些 API。

## 2. Prop schema 化必须完成

要求：

- 建立明确的 prop schema / prop reader，至少覆盖 M1 已支持节点和 props。
- QuickJS `setProp` 不能再无条件接受任意 key + 任意 object。
- 已知 props 必须按 schema 读取。
- 未知 props 必须进入明确策略：拒绝，或归入明确的 custom/accessibility/semantics 通道；不能无声进入任意 prop map。

至少覆盖：

- Text：
  - `text`
  - `textStyle`
  - `singleLine`
  - `minLines`
  - `maxLines`
- Input：
  - `modelValue`
  - `placeholder`
  - `selectAllOnFocus`
  - `textStyle`
- Image / Icon：
  - `source`
  - `src`
  - `tint`
  - `size`
- Row / Column：
  - `horizontalArrangement`
  - `verticalArrangement`
- accessibility 基础：
  - `contentDescription`
  - `label`
  - `description`
  - `role`
  - `enabled`

必须明确的 shape：

- `textStyle` 只能是受控对象。
- `Arrangement.spacedBy` 只能是受控对象。
- color / number / boolean / string 类型必须严格。
- function prop 仍必须拒绝，event callback 仍只能走 EventSlot。

验收标准：

- 错误 `textStyle` shape 有测试。
- 错误 arrangement shape 有测试。
- 未知 prop key 有测试。
- function prop 拒绝有测试。
- 合法 demo props 不被破坏。
- `PropValue` 不再表现为任意对象协议，只作为受控 carrier 或被 schema reader 包裹使用。

## 3. semantics / testTag 留置以后

本期不做 semantics 正规化，不恢复 `testTag`。

要求：

- 当前公开面必须保持干净：没有 `m.testTag(...)`，没有 `m.semantics(...)`。
- native reader 对 `testTag` / `semantics` 这类未公开、未落地名称必须明确拒绝。
- 不允许新增半吊子的 `CompiledModifier.semantics` 字段。
- 不允许把 testTag / semantics 临时塞进普通 prop map。
- 可以在 TS modifier 附近留下中文注释，说明将来会以正规 semantics 通道添加回来。

未来（不是本期做！仅作为初步展望）正规 semantics 至少应包括：

- 新增 `SemanticsModifierSemantics` 或等价结构。
- `CompiledModifier` 增加 `semantics` 字段。
- QuickJS modifier reader 支持 `semantics` / `testTag` 的正规读取。
- LayoutTree 存储 compiled semantics。
- test harness / inspector model 可读取 semantics。

未来 `testTag` 恢复要求：

- 可以恢复 `m.testTag(...)`，但必须通过 semantics 通道。
- 不允许恢复为“被 native 忽略但不报错”的占位 modifier。
- 不允许影响布局、绘制、输入。

验收标准：

- 本期没有公开 `testTag` / `semantics` API。
- native reader 不静默接受 `testTag` / `semantics`。
- 文档或代码注释明确说明：将来添加回来时必须走完整 semantics 通道。
- 没有新增任何“看起来像 semantics 但实际无闭环”的半支持结构。

## 4. 完整 pointerInput 留置以后

本期不做完整 pointerInput。

要求：

- 当前公开面必须删除。
- native 半支持字段必须删除。
- reader 对 `pointerInput` 必须明确拒绝。
- 文档和代码注释必须明确：将来以完整 typed pointer event slot 方式添加回来。

未来（不是本期做！仅作为初步展望）完整 pointerInput 至少应包括：

- `EventSlotKind::PointerInput`。
- typed JS pointer payload：
  - `type`
  - `x`
  - `y`
  - `pointerId`
  - `buttons`
  - `phase`
- QuickJS callback 注册与释放。
- JUCE pointer event 到 core pointer event 的统一转换。
- hit-test 后派发。
- 删除节点 / HMR / unmount 后 callback 清理。
- down / move / up / cancel 测试。

# 禁止事项

1. 禁止继续暴露半支持 API。
2. 禁止“TS 有、native 无”的公开能力。
3. 禁止“native 有字段、pipeline 不用”的死语义。
4. 禁止把 prop schema 化做成另一套 JSON/序列化协议。
5. 禁止把 semantics 塞进普通 prop map 冒充完成。
6. 禁止恢复 `testTag` 为无语义占位 modifier。
7. 禁止为了以后兼容而保留当前错误 API。

第二期收尾化完成必须同时满足：

1. 孤儿 API 删除完成，并有中文“将来添加回来”提示注释。
2. `pointerInput` 当前不再作为公开 API 或 native 半字段存在。
3. FocusRequester 公开面不再孤立暴露。
4. Prop schema 化覆盖 M1 已支持节点与核心 props。
5. 未知 prop / 错误 prop shape / function prop 有明确拒绝或诊断。
6. semantics / testTag 本期不恢复，并有中文“将来添加回来”提示。
7. native reader 不静默接受 `testTag` / `semantics` 等未落地名称。
8. 旧链路不复发：无 JSON/native value bridge、无字符串 value 编码、无 BridgeOp/BridgeBatch、无 headless layout 第二实现。
9. TS typecheck、TS tests、native tests、QuickJS tests 通过。
10. debug/release stand/vst clean build 通过。
11. 真实 demo 交互仍留给人工验收，不用模拟操作冒充真人。
