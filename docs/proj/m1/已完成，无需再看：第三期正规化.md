# 正规化描述

第三期正规化已完成核心链路的深度收束，彻底消除了长期存在的“双语义源”与“重复解释”问题。Arrange 现已实现真正的**单一事实源生产链路**：

1.  **链路归一化**：废弃了初始 `mount tree` 的旁路逻辑，TS Runtime 的初始挂载与增量更新均统一为标准 `BridgeOp`。QuickJS 宿主回归其“脚本引擎”本质，仅负责搬运 Commit 和绑定事件槽，不再作为第二个 Renderer 遍历 JS 树。
2.  **Modifier 语义收口**：彻底清除了 TS 层与 QuickJS 层生成的 `__arrange...` 系列派生 Prop。Modifier 的真实语义（Clickable、Scroll、Weight、Align、Transform、ZIndex 等）现在仅由 Native Core 在 `LayoutTree` 接收到 `SetModifier` 后进行单次编译。
3.  **编译驱动阶段执行**：引入了统一的 `CompiledModifier` 结构。`Layout`、`Paint`、`HitTest` 与 `Scroll` 模块不再各自解析 Payload，而是共享由编译器生成的语义结果。`LayoutTree` 的标脏逻辑也由手工判断转为基于编译 Diff 的自动化处理。
4.  **状态生命周期正规化**：`PublishedFrame` 完成了持久内容（DrawOps）与本帧变化标记（ChangeSet/RepaintBounds）的物理拆分，确保了局部重绘与跨帧渲染的逻辑严密性。
5.  **测试保护重心迁移**：删除了所有保护旧有派生 Prop 链路的测试，新测试集全面覆盖标准 Bridge 变动与 Native 编译结果的对齐。

# 简要工作日志

1.  **挂载链路统一**：TS Runtime 移除了 `mount tree` 分支，初始挂载改为发送标准 `createNode`、`setModifier` 等 Ops；`NativeCommitCommand` 移除 Tree 类型。
2.  **派生属性肃清**：`renderer.ts` 重写为纯粹的 `BridgeOpWriter`，删除了 `nativeModifierProps`，不再生成任何 `__arrange...` 派生 Prop。
3.  **Native 编译器落地**：核心层新增 `CompiledModifier`，`LayoutTree::SetModifier` 实现 “Compile + Diff + MarkDirty” 闭环。
4.  **消费端适配**：`Layout.cpp`、`Paint.cpp`、`HitTest.cpp` 等模块全面改写，停止调用 `parseModifierElements`，改为读取 Node 上的 `compiledModifier`。
5.  **宿主职责剥离**：`QuickJsScriptHost` 删除了所有 JS 树遍历逻辑（`emitNode`）及 Modifier 序列化代码，仅作为标准的 Bridge 数据转发层。
6.  **帧产物重构**：`PublishedFrame` 拆分为 `PublishedFrameContent`（持久）与 `FrameChangeSet`（瞬时），修正了 `SceneFramePipeline` 的状态重置逻辑。
7.  **命名收口与清理**：完成 `RenderTree` 到 `LayoutTree` 的全局改名；清理了 C++ Smoke 测试中对旧 Typed-Prop 的残留引用。
8.  **验证通过**：全量通过 `pnpm typecheck`、`test:runtime`、`test:native` 及 `test:quickjs`；Demo UI 编译及 Smoke 测试在 Release 模式下运行正常。下一步将交付主人进行最终的集成 UI 人工验收。
