# Arrange

项目名。在音乐世界，“Compose”是作曲，则“Arrange”是编曲

# Arrange UI Pipeline

Arrange 的声明式 UI 主链路：`Vue SFC authoring -> Arrange Runtime -> Bridge Commit -> C++ RenderTree -> Measure / Layout / Paint / Input -> JUCE Surface`。

# ArrangeEditor

C++ 侧主入口。托管整个 JUCE Editor UI，并加载用户的 Arrange App。

# App 入口

JS/TS 项目的入口脚本，负责 `createApp`、配置与挂载。

# SFC

Vue 单文件组件。Arrange 使用 script/template，不处理 style 块。

# 界面树

Arrange 运行时产生的原生 UI 描述树，不是 DOM。

# 逻辑组件

来自 Vue 运行时的组件概念。JUCE 不感知它，也不存在 Vue 组件与 JUCE 组件一一对应。

# 渲染节点

Arrange 内部用于测量、放置、绘制和事件处理的节点。

# Modifier

描述尺寸、内边距、背景、裁剪、对齐、事件等行为的链式对象。

# 洋葱模型

Modifier 按顺序包裹节点。顺序不同，测量、绘制与事件结果可能不同。

# 约束

父节点传给子节点的最小与最大宽高范围。

# 测量

节点在约束下计算自身尺寸。

# 放置

父节点决定子节点的最终位置。

# 固有尺寸

节点在正式测量前暴露的期望尺寸能力，用于文本、等高行、分割线等布局。

# dp / sp / px

`dp` 是布局主单位，直接对应 JUCE 逻辑坐标。`sp` 是文本单位。`px` 用于物理像素、高级 Canvas 或位图场景。

# DrawScope

Canvas 与绘制 Modifier 使用的绘制上下文。

# FrameClock

Arrange 的帧时钟。动画、Canvas frame invalidation 与 UI-thread 高频显示使用 native host 驱动的 tick，不使用 Promise / microtask 伪造 frame。

# RAF pump

QuickJS host 暴露 `requestAnimationFrame` / `cancelAnimationFrame` / `performance.now`，由 ArrangeEditor native timer 逐帧调用 pending RAF callback，并把产生的 Bridge 增量应用到 native RenderTree 后 repaint。

# Lazy 组件

按可视范围创建和测量项目的集合组件，使用数据加 slot。

# 错误屏

Arrange 内置兜底界面，用于展示加载、运行或热更新失败，并提供重试。

# 开发期诊断表层

正式 DevTools 之前由 Arrange Editor 托管的最小诊断层，包含状态 badge、Standalone 标题栏状态、错误屏、日志与必要 overlay toast。它不属于用户 App tree，不参与用户布局或事件语义。

# DiagnosticEvent / DiagnosticsState

诊断表层的结构化事件与状态快照。加载、HMR、错误、Bridge、Input、Scroll、Resource 等链路先写入该模型，再由 badge、错误屏、toast、日志或未来 DevTools 消费。

# overlay toast

开发期诊断表层的短暂提示，用于 reload、fallback、HMR 连接状态、复制诊断等低风险事件，不替代错误屏，不作为通用用户 UI 组件。

# 用户的 UI 项目源码

用户的 Node/Vite 项目，包含 SFC、入口脚本、package.json、vite.config 等。

# UI 构建产物目录

一般指发布包中的 `ui/` 文件夹，里面直接摆放用户 UI 项目的构建产物。

# Bridge

JS 与 C++ 之间传递界面树操作批次的协议层。

# Parameter gesture

一次用户参数编辑的生命周期。连续拖拽时用于通知宿主 automation 开始、变化、结束。
