# M5：Canvas 与视觉能力

状态：施工中。设计决策见 [ADR 020](../../adr/020-Canvas与视觉能力.md)；本文记录需求、范围、验收与施工状态。

## 目标

补齐 CSS 与 Compose 级别的常用视觉能力和 Canvas，让 Arrange 能独立撑起音频插件界面的设计；同时建立不进入用户树的原生诊断：采集层与叠加层。

## 现状

- 绘制修饰器 `drawBehind`、`drawWithContent`、`drawWithCache` 已有，`DrawScope` 只有矩形、圆角矩形、椭圆、线、裁剪与变换。
- `Brush` 只有纯色；`Shape` 只有矩形、圆与统一圆角；阴影、渐变只有 arch 草案（[Modifier](../../arch/11-Modifier.md#阴影)、[基础类型](../../arch/10-基础类型.md)）。
- Canvas 只有 API 草案（[基础 API 形态](../../arch/21-基础API形态.md#canvas)、[文本输入与绘制](../../arch/18-文本输入与绘制.md#canvas)）。
- 绘制命令在 JS 侧是每条一个冻结对象，`kind`、`shape` 为字符串。
- 带自定义绘制命令的层边界记为未知，[脏区重绘](../../arch/05-渲染设计.md#脏区重绘)遇到它整窗重绘：任何 draw 修饰器的变化都会整窗重绘。
- 诊断表层（错误屏、badge、toast）已是框架直接绘制、不进用户树的形态（[开发期诊断表层](../../arch/25-开发期诊断表层.md)）；帧与绘制计数已在 core 中，但没有对外读取与显示。

## 范围

### 1. Canvas

Canvas 是一个 Arrangable，节点、布局、命中、生命周期与热更新同其它 Arrangable 一致。按数据与绘制来源分三档，三档共用同一 Canvas 与同一 `DrawScope`，换档只改数据源或绘制源：

| 档 | 数据 | 绘制 | 用途 |
|---|---|---|---|
| A | JS 状态 | JS `DrawScope` | 旋钮、装饰、低频变化 |
| B | 原生数据源 | JS `DrawScope` | meter、波形、频谱 |
| C | 原生数据源 | 原生 painter | 追求性能上限 |

- B 档：音频线程写入无锁数据源，UI 帧在 C++ 侧取一次快照；JS 只拿只读句柄，在绘制回调中直接读取数值，不经响应式；Canvas 按帧或按数据版本失效。音频线程不运行 JS。
- C 档：用户在 C++ 按名称注册 painter 并声明参数 schema；JS 按名称引用，参数以类型化数据传入，绑定时校验。JS 不持有原生指针，HMR 后按名称重新绑定；名称不存在或参数不符时给诊断，不静默绘制。
- 失效方式：`auto`（依赖变化）、`manual`（`controller.invalidate()`）、`frame`（逐帧）。
- Canvas 与 `pointerInput`、动画组合可用。

### 2. DrawScope 扩充与绘制修饰器优化

- 新增绘制：路径（moveTo、lineTo、quadTo、cubicTo、arc、close，填充与描边，线帽与线接）、文字（经 `TextLayoutService`）、图片与 painter（含 filmstrip 按值选帧）。
- 填充与描边接受渐变 Brush。
- 命令编码改为紧凑的类型化形式（数值操作码与类型化数组），减少 QuickJS 分配与读取；跨边界不经 JSON 或字符串。
- 自定义绘制边界可计算：按命令与变换栈求外包盒，使 draw 修饰器与 Canvas 的变化也走局部重绘；不借用布局 bounds 限定用户绘制。
- 核对并补测：依赖与尺寸未变时不重新录制、不重新解码。

### 3. 视觉基础能力

对齐 CSS 与 Compose 的常用能力，混合模式除外：

- 渐变 Brush：linear、radial、sweep；用于 `background`、`border` 与 `DrawScope`。
- 分角圆角 Shape。
- `M.dropShadow`、`M.innerShadow`，按 [Modifier](../../arch/11-Modifier.md#阴影) 的设计工具式参数。
- 模糊：内容模糊与背景模糊（毛玻璃）。
- 图片：平铺、九宫格、filmstrip。
- 像素缓冲画布：低分辨率位图由 JS 或原生填充，平滑缩放绘制，用于极光一类低频背景。

### 4. 位图缓存层

- 图层可离屏缓存为位图；阴影、模糊与像素缓冲建立在它之上。
- 失效随片段变化；有内存预算，缓存命中、重建与保留字节进入计数。
- 将来 GPU 离屏输出（着色器）接入同一位置，见[远期想法暂存器](../4：远期想法暂存器.md#gpu-效果与着色器)。

### 5. 原生诊断：采集层与叠加层

诊断分三层，M5 只做前两层：

- 第 0 层采集：帧时间线、各阶段耗时、片段与命令复用、重绘区域、Canvas 重录次数、节点数等；只产数据，关闭时没有额外开销；提供只读接口。
- 第 1 层叠加：帧时间指示、状态指示、脏区闪烁、bounds 描边、命中高亮。框架在场景之后直接绘制，与现有诊断表层同属框架表层：不进用户树，不参与布局与命中，按开关插拔。
- 第 2 层 Inspector 不在 M5，见[里程碑](../2：里程碑.md)。

第 1 层只读第 0 层的数据，不读取用户 JS 内部状态。
