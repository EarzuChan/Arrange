# M6 字节码测量与退出验收

## 字节码测量

2026-11-18，Windows x64、仓库锁定的 QuickJS-NG 0.14.0。取真实构建的 Gallery、Viewport fixture ESM，`qjsc -b -m -s -s -n app.js` 生成去源码与调试信息的字节码。`arrange_bytecode_bench` 每个样本交替测 120 对，预热三对，每次使用新 QuickJS context；仅计内存中的 `JS_Eval(COMPILE_ONLY)` 与 `JS_ReadObject`，不计 I/O、模块执行或首帧。体积对照使用相同 Deflate 策略。

| 夹具 | 编译 P50 / P95 | 反序列化 P50 / P95 | JS / 字节码（原始 B） | JS / 字节码（Deflate B） |
|---|---:|---:|---:|---:|
| Gallery | 46.19 / 50.93 ms | 1.59 / 1.99 ms | 463604 / 475929 | 85292 / 138245 |
| Viewport | 13.45 / 14.04 ms | 0.63 / 0.79 ms | 129003 / 147799 | 40272 / 66613 |

结论：字节码确实显著减少编译阶段耗时，但压缩脚本增大约 62%–65%。这是单模块微基准，不是实机首屏数据。0.11.0 不发布字节码选项；将来以端到端收益、跨平台生成链路和保留诊断信息的成本重新判断。本次不做半套生成器或加载器。

## Demo 交接

Framework `0.11.0` 和 CLI `1.3.0` 已发布至 `http://localhost:4873`，两者的 dist-tag 均为 `local`，可按精确版本安装。Framework 源码使用本地 `v0.11.0`（`0f592f0`）。用本机 registry 和本地源码仓库时，保持 [本机配置覆写](../../arch/31-ArrangeCLI与工程模式.md#配置分工)；新兼容码为 `2`，旧 CLI `1.2.5` 不用于这个版本组合。

1. `arrange sync` 后跑 `arrange dev`。打开关于页应见静态数据提供的 `Arrange Gallery`；改 `public/gallery.json` 并检查 public 重载。不与旧 Dist 资源混读。
2. 默认目录模式构建 Release；离线运行 Standalone，并在 DAW 加载 VST3。换工作目录仍能启动；检查图片、字体和关于页静态数据。
3. 在 `arrange.project.yaml` 加 `ui.packageFormat: zip`，对相同构建输出执行 `arrange pack` 并重试两种产品。原落点 `ui` 变为普通 ZIP 文件，不应出现展开的资产目录。再切回 `directory` 并验证双向替换；替换前关闭占用产物的宿主。
4. 在发布产物的副本上验证缺包、损坏包与协议不匹配诊断；macOS 同时验签。记录平台、架构、宿主与结果。不得通过破坏正式已签名产物来验收错误屏。
