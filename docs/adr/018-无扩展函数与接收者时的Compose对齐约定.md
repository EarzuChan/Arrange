# ADR 018：无扩展函数与接收者时的 Compose 对齐约定

日期：2026-10-27。状态：已定；SFA 父布局数据静态检查待施工。

## 背景

Arrange 的公开 API 尽量对齐 Compose 的处理思路。Compose 的许多写法建立在 Kotlin 的扩展函数与带接收者 lambda 上：组合修饰写成 `fun Modifier.toggleable()` 后可直接链式调用；`BoxScope.align` 只在 Box 内容中存在，用错位置编译不过；`DrawScope.() -> Unit` 让绘制调用省掉作用域前缀；`16.dp` 是扩展属性；`with(density) { }` 借接收者完成单位换算。

TypeScript 没有扩展函数，也没有接收者。此前各处已按场景各自绕开，但没有成文：`adjustable()` 是普通函数，需要 `then()` 拼接；父布局数据是任何位置都能写出的 `Modifier` 方法，用错只在原生布局时报错；绘制作用域以参数传入。本篇把这些替代写法定为统一约定，供官方与第三方 API 共同遵守。

## 决策与理由

1. **组合修饰写成函数并以 `then()` 拼接。** `Modifier` 上的方法只留给原语，即对应单个原生 Modifier 元素的能力；由多个原语组合而成的能力写成返回 `Modifier` 的普通函数，使用处写 `M.size(48.dp, 48.dp).then(adjustable(knob))`。官方组合与第三方组合使用同一写法。第三方无法往 `Modifier` 上加方法，若官方组合独占链式写法，两者就不再处在同一起点；`then(组合函数)` 是 TypeScript 中最接近扩展函数的写法。

2. **有状态的组合由 setup 中创建的状态承载，组合函数只是状态的纯函数。** Compose 可以在 `composed {}` 或 `Modifier.Node` 中记住状态；Arrange 的组合函数在每次重排时都会被调用，不能在内部创建或记住状态。状态以 `createXxxState()` 在 setup 中创建一次后传入。组合函数交给原语的回调须挂在状态上、身份稳定：原生按回调身份登记事件槽，身份变化即退休旧槽并登记新槽，既浪费命中与焦点重算，也可能丢弃已排队的事件。随声明变化的输入（如 `enabled`）由状态记住最近一次值，回调内读取。

3. **父布局数据以静态检查代替作用域。** `align`、`weight`、`matchParentSize` 仍是 `Modifier` 方法，在任何位置都能写出。SFA 编译器根据模板中的父子标签，把原生已有的匹配规则提前到构建期报错；修饰链来自变量、prop 或跨组件传递而无法静态判断时，仍由原生布局校验兜底。不采用由插槽提供作用域化 `M` 的方案：它最接近 Compose，但让模板写法明显变笨重，收益不抵代价。

4. **带接收者 lambda 改为显式首参。** 作用域对象作为回调的第一个参数传入，惯例命名为 `scope`，如 `M.drawBehind(scope => scope.drawRect(...))`。作用域的单位、生命周期与可用操作由其母文档声明一次。

5. **单位以编译期值壳与带单位的字段名代替扩展属性。** SFA 中 `.dp`、`.sp`、`.px` 由编译器展开；纯 TypeScript 中，公开数据字段用单位后缀命名（`xDp`、`widthPx`），整个作用域统一单位的（如绘制作用域统一为 PX）在作用域文档中声明。需要换算时显式取得 `Density` 对象调用其方法，不提供隐式接收者。

6. **DSL 接收者按场景改为模板、插槽或显式参数**，不为对齐 Compose 而在 TypeScript 中模拟接收者。

具体规则以 [Modifier](../arch/11-Modifier.md#便捷组合)、[SFA 与模板写法](../arch/33-SFA与模板写法.md)、[基础类型](../arch/10-基础类型.md) 与 [基础 API 形态](../arch/21-基础API形态.md) 为准。本文记录选择与原因，不另定义接口。

## 实施与验收影响

`adjustable()` 已按第 2 条改为状态内的稳定回调。SFA 父布局数据静态检查需要编译器了解各内建 Arrangable 的父布局种类，作为后续施工项，完成前行为不变。新增官方组合须使用函数加 `then()` 的形态，评审时检查回调身份是否稳定。
