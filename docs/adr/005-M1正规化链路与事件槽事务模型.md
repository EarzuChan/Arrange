# ADR 005：M1 正规化链路与事件槽事务模型

日期：2026-05-11

## 背景

M1 早期链路已经能运行 demo，但 editor、脚本宿主、事件回调、mutation apply、布局和绘制准备之间边界不够清晰，导致两个核心风险：

- native tree 可能持有短命 JS callback handle，快速交互、节点替换或 reload 后容易命中 stale callback。
- 输入事件、RAF、pending mutation、LayoutTree apply 和 repaint 由多个局部 helper 顺手推进，不能稳定解释为 Compose-like 的 composition phase 与 render phase。

## 决策

### 1. 采用正规 Compose-like 主链路

Arrange UI runtime 的目标链路固定为：

```txt
host event / frame tick
-> JS Composition Phase
-> MutationTransaction
-> NativeScene apply
-> measure / layout / place
-> DrawOps preparation
-> passive paint
```

`paint()` 只消费已经发布的绘制模型，不执行 JS、不 apply mutation、不做布局。

### 2. EventSlotId 取代 native tree 长期持有 callback handle

native tree 持有稳定 `EventSlotId`。QuickJS 侧维护 slot 到当前 JS function 的 registry。callback 替换、节点删除、reload/HMR 时，slot update 与退休 slot 通过 transaction 边界处理。

旧 callback handle 只可作为兼容或调试过渡，不能作为最终生产事件生命周期模型。

### 3. MutationTransaction 是 JS 与 native 的提交边界

JS/Vue composition 产出的 tree mutations、event slot updates、retired event slots 必须进入同一 `MutationTransaction` 或等价事务。

C++ Render Phase 原子消费 transaction，更新 `NativeScene`，然后执行三件套和 draw-op preparation。

### 4. FrameClock 优先贴近显示帧

host FrameClock 归 UI owner 线程。存在 native peer 且有 runtime frame work 时，优先使用平台 vblank/display-frame 机制；无 peer 或不可用时使用 JUCE Timer fallback。dev reload 与 diagnostics 维护 tick 不应伪装成显示帧。

### 5. ArrangeEditor 退化为宿主壳层

`ArrangeEditor` 的长期职责是 JUCE 生命周期、平台事件采样、paint 转发和 frame clock 接入。runtime、composition、event、scene、pipeline、paint、input、diagnostics、package binding 等职责必须在独立对象中表达。

## 影响

- `ArrangeRuntime` / `FrameCoordinator` 是事件、RAF、transaction 与 render phase 的主入口。
- `NativeScene` 是 native tree、event slots 与渲染状态的 owner。
- deterministic runtime/headless/native/QuickJS 测试优先于屏幕自动化。真实 standalone GUI 点击、滚动、IME 作为人工验收项。
- `docs/arch/` 中当前母文档是最终事实源；本 ADR 只记录 M1 正规化决策背景。

## 不做

- 不用自动化屏幕点击、滚动、输入作为常规回归手段。
