# ADR 008：M1 收尾化诊断、资源与 Vue 边界

日期：2026-05-14

## 背景

M1 三四五期正规化已经把主链路收束为 QuickJS JSValue 直读、typed native transaction、LayoutTree 与 SceneFramePipeline。进入收尾化后，又发现三类必须提前定清楚的长期问题：

- Debug 与用户可见诊断不只靠散落日志；Arrange 项目组和 Arrange App 开发者都需要可过滤、可复制、可输出、可有限调控的诊断信息。
- `Image` / `Icon` 的资源来源必须可预测、可复现；当前 demo 中 `Icon source="play"` 实际由 native painter 硬编码三角形，属于假资源语义。
- Arrange 借用 Vue authoring，但不采用 DOM / CSS；必须明确哪些 Vue 能力支持，哪些能力与 Compose-like / Modifier / LayoutTree 路线冲突。
- clipping、Text overflow、scroll viewport clip 不能继续混作一件事；应按 Compose 思路分别定义。
- 插件持久化数据、缓存数据、用户数据目录暂不详细设计，但给出警告与远期方向，避免用户误用 cwd、bundle 或 dist package。

本 ADR 记录这轮收尾化新增决策。长期事实源系沉淀在 `docs/arch/` 当前母文档中。

## 决策

### 1. 诊断统一为 DiagnosticEvent

日志、toast、错误屏、Copy diagnostics 和未来 DevTools 共用 `DiagnosticEvent` 作为事实源。历史 `DiagnosticsOverlay` 命名必须被替换掉，因为它暗示旁路 overlay 绘制；生产命名按职责拆为 `DiagnosticEvent`、`DiagnosticEventStore` / `DiagnosticLogger`、`DiagnosticsState` 与 `DiagnosticsScene`。

`DiagnosticEvent` 必须具备：

- level：`trace / debug / info / warn / error`。
- category：采用分层类别，例如 `app`、`host.live`、`host.dist`、`host.hmr`、`runtime.script`、`runtime.transaction`、`pipeline.frame`、`pipeline.layout`、`pipeline.paint`、`input.pointer`、`input.key`、`input.ime`、`input.scroll`、`resource.package`、`resource.image`、`resource.icon`、`diagnostics`。
- id / timestamp / code / message / detail / source / path/url / errorCode。
- debugger log、recent event ring、可选 file sink。
- level 与 category 过滤。

toast 不是第二套事实源，而是部分 `DiagnosticEvent` 的短暂可视化输出。调用 diagnostics toast 必须同时产生对应日志事件；toast 显示可以关闭，但该日志事件依旧打印。致命错误必须进入错误屏与日志；高频事件不得默认 toast。diagnostics toast 建议仅用于开发期诊断（虽然不阻止你在 Release 中调用），面向最终插件用户的业务 toast 应由开发者在自己的 Arrange App 内实现。

file sink 初期允许同步写入以完成最小闭环，但文档必须警告：不得在 audio thread、paint 或高频关键路径依赖同步文件 I/O。

### 2. 公开 logger API 与 diagnostics API

`@arrange/runtime` 应提供面向 Arrange App 开发者的诊断入口，例如：

```ts
logger.info("resource", "Loaded icon set")
logger.warn("resource", "Icon missing", { source })
diagnostics.toast("Saved")
diagnostics.requestReload()
diagnostics.triggerFakeError({ message: "..." })
```

`console.log/warn/error` 应桥接为 `script` 类别日志事件。Release 默认克制输出，Debug 默认提供足够排查信息。

申请重载、fake 报错、log、toast、Copy diagnostics、log level / category / toast 显示等开发者可诊断能力应有 native + TS 双 API；app source、file sink 路径、recent ring size、Release 完整诊断暴露、环境变量覆盖、诊断快捷键和“是否允许 TS 调试控制 API 生效”等底层开关只留 native。

### 3. 资源引用必须受控

资源引用可以来自：

- Vite import。
- `new URL(..., import.meta.url)`。
- Arrange Vite 插件规范化出的 `ResourceRef`。
- UI package root 内的字符串路径。

禁止：

- 绝对文件系统路径。
- `../` 逃逸 UI package。
- 隐式当前工作目录查找。
- 未经单独设计的远程网络资源。
- 未经单独设计的用户数据目录、开发者自定义缓存目录或任意外部路径。

资源缺失、格式不支持、解码失败必须产生 `resource` 类别诊断事件，不得静默失败。

### 4. Icon 初期支持 SVG，核心不内建图标包

核心不提供官方图标包，不提供 `Icons.Play` 之类内建集合。用户必须提供 SVG 资源。

当前硬编码 play 三角形必须删除，不能作为长期行为。

Icon 初期支持 SVG 子集：

- `svg`。
- `viewBox`。
- `path` 与基础 shape。
- 基础 `fill`。

初期不支持 CSS、script、animation、filter、外部引用和远程资源。

### 5. Icon tint 与大小对齐 Compose 思路

`Icon` 适合单色符号图形，并默认参与 content color：

- 显式 `tint` 优先。
- 未传 `tint` 时读取 `LocalContentColor`。
- 没有 `LocalContentColor` 时 fallback 黑色。
- 若用户要保留 SVG 原色，应使用 `Color.Unspecified` 或等价未指定色。

Icon 默认尺寸来自 SVG intrinsic size / `viewBox`；无法取得时 fallback `dp(24)`。父容器约束、`Icon size` prop 与 Modifier 的 size / width / height 均可覆盖最终布局尺寸。

`Image` 保留资源原色，不提供 `tint` prop。位图着色、滤镜或 shader 处理应作为后续专门能力设计，不和 `Icon.tint` 混用。`Image` 默认尺寸来自图片 intrinsic size，并同样受父容器约束、props 与 Modifier 尺寸影响。

### 6. Arrange Local 使用 Vue provide/inject

Arrange 不重新发明 CompositionLocal。核心约定 typed Local key 与 helper，但底层沿用 Vue `provide/inject`。

核心内置 Local：

- `LocalContentColor`。
- `LocalTextStyle`。
- `LocalDensity`。
- `LocalLayoutDirection`。

默认优先级：

```txt
显式 prop
-> Modifier / component 参数
-> Arrange Local
-> 组件默认值
```

### 7. Vue 能力边界必须写清楚

支持：

- SFC、`<script setup>`、props、emits、slots。
- ref、reactive、computed、watch、watchEffect、lifecycle、provide/inject。
- `v-if`、`v-for`、`v-model`。
- dynamic component。
- Pinia。
- Vue Router 的 memory / navigation 方向。

目标支持但必须严测：

- KeepAlive。
- Suspense。

不支持：

- DOM 标签。
- `class` / `style` / SFC `<style>` 作为生产样式入口。
- `v-show`。
- DOM `@click` 主模型。
- Teleport。
- Transition。
- browser / hash history。
- 依赖 DOM / window / document 的 Vue 插件。

### 8. 普通副作用走 Vue，Arrange 专用副作用进入远期想法

当前用户实现副作用应使用 Vue Composition API：

- `onMounted` / `onUnmounted`。
- `watch` / `watchEffect`。
- `watch(..., onCleanup)`。
- `effectScope`。

Arrange 不把 `LaunchedEffect` / `DisposableEffect` 作为当前首选 API。未来可评估 `useFrameEffect`、`useArrangeIdle`、`useNativeSubscription`、`useResourceEffect`，但应先进入远期想法暂存，不在 M1 详细设计。

### 9. clipping 与 Text overflow 必须分开

普通容器默认不裁剪子内容。显式视觉裁剪由 `m.clip(shape)` / 后续 `clipToBounds` / `graphicsLayer(clip = true)` 表达，并必须保留 Modifier 顺序语义。滚动容器和 Lazy 组件自身是 viewport，必须自带 viewport clipping；不能只平移内容而不裁剪。

`Text overflow` 是 Text 自身文字超出文本框时的策略，不等于视图树裁剪：

- `clip`：裁在 Text rect 内。
- `ellipsis`：在有界宽度与行数限制下省略。
- `visible`：Text 自身不主动裁剪，但仍受祖先 clip、scroll viewport、Lazy viewport 和宿主窗口裁剪。

### 10. 插件数据与缓存暂不详细设计

Arrange 当前不提供官方插件持久化数据、缓存数据或用户数据目录 API，也不宣称已有跨 Standalone / VST3 / AU 的最佳实践封装。

当前必须警告：

- 不得假设 cwd。
- 不得写 plugin bundle、安装目录或 UI dist package。
- 不得在 audio thread 做文件 I/O。
- 不得在 paint 或高频关键路径依赖同步文件 I/O。

远期把 `ArrangeStorage` 放入 Icebox，至少包含 userDataDir、cacheDir、logDir、tempDir、settings/properties helper、格式差异、多实例隔离，以及插件 host state / 用户数据 / 缓存 / 诊断日志边界。

## 不做

- 不内建官方图标包。
- 不把 `source="play"` 魔法映射到 public 或内置 play 图标。
- 不把 toast 做成用户 UI 组件。
- 不引入 DOM / CSS 兼容层。
- 不支持 Vue DOM Teleport / Transition / v-show 的 DOM 语义。
- 不在 M1 设计完整 Arrange 专用 effect API。
- 不在 M1 详细设计官方 `ArrangeStorage`。
- 不把 cwd、plugin bundle 或 UI dist package 当作可写数据目录。
- 不把 Text overflow 当作普通视图 clipping。
