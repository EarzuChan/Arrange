# ADR 020：Canvas 与视觉能力

日期：2026-11-04。状态：已定，施工中。

## 背景

M5 要补齐 CSS 与 Compose 级别的常用视觉能力和 Canvas，并建立不进入用户树的原生诊断，需求见 [M5 需求与待办](../proj/m5：快完成了/01-M5需求与待办.md)。动工前的现状有三处直接影响设计：

- 绘制修饰器的命令在 JS 侧每条是一个冻结对象，`kind`、`shape` 为字符串，原生逐条按属性名读取。
- 带自定义绘制命令的层边界记为未知，脏区重绘遇到它整窗重绘。
- 高频数据已有 `Meter`、`Waveform`、`Spectrum` 三种无锁结构，但到 JS 后每帧写入 `shallowRef`，绘制只能经响应式取数。

另有一处残留：`PaintStyleSemantics.shapeType` 仍是字符串。

## 决策与理由

1. **绘制命令改为数值流加引用表。** `DrawScope` 把命令写入一条可增长的 `Float64Array`：操作码与全部数值参数依次排列，颜色作为整数存入，64 位浮点能精确表示。字符串、painter 句柄、像素缓冲等非数值参数放入引用表，数值流中只记其下标。原生一次取得整块缓冲并顺序解码，不再按属性名逐条读取，JS 侧也不再为每条命令分配对象。只用 `Float64Array` 而不分数值类型，是为了让颜色与坐标同处一条流、解码只有一种读法。

2. **自定义绘制的边界由命令求出。** 解码时按命令重放变换与裁剪栈，求每条命令在层局部坐标中的外包盒；内容标记处的子片段按当时的变换投影后并入。层边界因此可知，脏区重绘对绘制修饰器与 Canvas 的变化取新旧边界并集，不再整窗重绘。不借用布局 bounds 限定用户绘制，用户画到哪里边界就到哪里。变换矩阵的组合与投影收为 core 中一处共用实现，片段边界、脏区计算与绘制命令求界都用它。

3. **Brush 与 Shape 的扩展。** Brush 增加线性、径向与扫描渐变，由颜色与可选位置组成色标。渐变的几何以所绘形状的外包盒为参照，坐标取 0 到 1 的比例：线性渐变给起点与终点，径向渐变给中心与半径（1 表示到达最远角），扫描渐变给中心与起始角度。这样同一 Brush 在不同尺寸下观感一致，修饰器与 `DrawScope` 共用同一定义，也不必为渐变几何引入单位后缀。Shape 增加分角圆角，四个角各有 Dp 与 PX 两部分。原生侧形状改为枚举与四个半径，`shapeType` 字符串删除。混合模式不在本期。

4. **`DrawScope` 的扩充。** 增加路径（moveTo、lineTo、quadTo、cubicTo、arcTo、close，填充与描边，线帽与线接）、文字、图片与 painter；填充与描边接受任意 Brush。路径动词直接写入数值流。文字在原生解码时经 `TextLayoutService` 排版，与 Text 共用测量与绘制。所有坐标仍为逻辑 PX。

5. **位图缓存由框架按效果自动建立。** 阴影、内容模糊与背景模糊需要离屏位图，由 JUCE 重放层按需建立并缓存，不公开显式开关。缓存键取不可变片段的身份：片段未变就复用位图，片段替换即失效。缓存有总字节预算，按最近使用淘汰，命中、重建与保留字节进入计数。将来 GPU 离屏输出也接入这一层。

6. **阴影与模糊。** `M.dropShadow`、`M.innerShadow` 按 [Modifier](../arch/11-Modifier.md#阴影) 已有的设计工具式参数实现：形状、模糊半径、扩展、偏移与颜色；阴影位图按形状尺寸与参数缓存。`M.blur` 模糊其后的内容。`M.backdropBlur` 模糊绘制顺序上位于它之前、且落在本节点形状内的内容：每次重放从发布根重放到本层之前，截取本层采样范围到离屏位图再模糊。缓存键取截取像素的摘要而非片段身份：背后内容可能来自任意祖先、兄弟与变换，按片段身份组键既繁且易漏，按像素则背后不变就不重算模糊，代价只剩一次截取。

7. **图片能力。** 图片绘制增加平铺与九宫格。filmstrip 是由一张图与帧数、方向构成的 painter 视图，按帧下标或 0 到 1 的比例选帧，用在一切接受 painter 的位置。像素缓冲是 JS 创建的定长位图，数据为 ARGB 的 `Uint32Array`，带版本号；`commit()` 时把像素复制进原生并递增版本，本身作为 painter 绘制、平滑缩放，同一版本只复制、只转换一次。复制放在提交而不是绘制，是为了让缓冲与普通 painter 走同一条快照与依赖路径，不另设绘制期的数据通道。

8. **Canvas 一个节点，三档来源。** Canvas 是 Arrangable，`onDraw` 与绘制修饰器共用 `DrawScope`、编码与缓存。失效方式为 `auto`（读取的响应式依赖或原生数据源变化）、`manual`（`controller.invalidate()`）与 `frame`（逐帧）。
   - A 档：JS 状态加 JS 绘制，即现有绘制修饰器的同一机制。
   - B 档：原生数据源加 JS 绘制。`Meter`、`Waveform`、`Spectrum` 统一为原生数据源：音频线程照旧无锁写入，UI 帧开始交付时把最新数据写进各数据源在 JS 侧持有的固定 `Float32Array`，并推进版本号。写入沿用已有的交付通路，在 JS 侧原地复制：交付本就每帧一次，原生直接持有 JS 数组只省一次小拷贝，却要多管一份跨边界的数组生命周期。绘制回调中调用数据源的 `read()` 直接取数，不经响应式；Canvas 在 `auto` 下登记读过的数据源，版本变化即失效。现有 `useMeter`、`useWaveform`、`useSpectrum` 保留为数据源之上的响应式包装。
   - C 档：原生数据源加原生 painter。用户在 C++ 按名称注册 painter 并声明参数表，参数为数值、颜色、布尔或数据源名；绘制函数接受 JUCE `Graphics`、目标矩形与只读参数视图，只能画在目标矩形内，边界即该矩形。JS 以 `scope.drawNative(name, params)` 引用，名称与参数在解码时校验，不符即报错进诊断，不静默跳过。JS 不持有原生指针，热更新后按名称重新绑定。注册表分实例与进程两级：实例级挂在处理器的 `Interop` 上，解码时先查它再查进程表。只设进程表时，插件多开会让各实例共用最后注册的实现、画错数据；改用全局唯一 id 要让 JS 知道 id，禁止重名则第二个实例无法注册，都不如让名称只在一个处理器内唯一。

9. **原生诊断分层。** 第 0 层采集：core 保存最近若干帧的帧时间线，含各阶段耗时、片段与命令复用、重绘区域、Canvas 重录次数与节点数；关闭时不记录。第 1 层叠加：帧时间指示、状态指示、脏区闪烁、bounds 描边与命中高亮，由框架在场景之后绘制，与错误屏、badge 同属框架表层，不进用户树、不参与布局与命中。第 1 层自身的重绘范围单独计算，不计入场景脏区，否则脏区闪烁会把自己的重绘也显示出来。开发模式下由快捷键与调试菜单切换，默认关闭；Release 默认不可用，宿主配置可显式开启。调试菜单先由宿主经 Editor 接口接入，Arrange 不自带菜单：插件宿主各有自己的菜单与右键约定，框架自带菜单会与之争抢。

10. **版本。** 原生入口与绘制协议变化，本期结束时发布 `0.7.0`，协议号递增。

## 实施与验收影响

施工串行，分六批：

1. 变换共用实现、绘制命令数值流编码、自定义绘制边界与局部重绘，`shapeType` 改枚举。
2. `DrawScope` 路径、文字、图片与 painter；渐变 Brush；分角圆角。
3. 位图缓存层；阴影、内容模糊与背景模糊；图片平铺、九宫格、filmstrip 与像素缓冲。
4. Canvas 与三档来源、三种失效方式。
5. 诊断第 0 层与第 1 层。
6. Demo 验收视图、arch 沉淀、`0.7.0`。

每批跑 JS 测试、类型检查、格式检查与原生测试。命令编码以现有绘制基准对比前后 JS 录制与原生解码耗时；边界计算以脏区测试证明绘制修饰器变化只局部重绘；缓存与效果先测有形数据（缓存命中、重建、边界），再看截图。着色器、混合模式、Inspector 与多根不在本篇范围。
