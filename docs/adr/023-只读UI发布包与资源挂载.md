# ADR 023：只读 UI 发布包与资源挂载

日期：2026-11-18。状态：已决定，M6 施工中。长期契约见 [UI App 发布包](../arch/14-工具链与App发布包.md)。

## 背景

Live 与 Dist 已有资源来源隔离，但 Dist 入口、ESM loader 与 Painter 各自打开文件；CLI 的交付凭据也不是运行时包清单。单纯压缩现有目录不会统一这些边界。

## 决策

1. Dist 按强制运行时清单挂载只读 UI 包。入口、模块、图片、字体和静态数据共用挂载，区分模块与资产两类读取。Live 保持 Vite 快照与同源资源获取，不借读 Dist。JUCE 继续管宿主与解码；命名、选源与发布由 Arrange 决定。
2. 目录和标准 ZIP 正式并列。CLI 在同一个产品资源位置放其中一种；应用不因换载体改代码。ZIP 按索引读单条目，不在安装或首次启动时解包，不持久化解压缓存。
3. 静态引用继续走 Vite import；按名字读取的静态数据留在 `public/`，提供异步文本、字节读取，不给脚本裸文件系统接口。用户数据、缓存、日志与宿主状态不并入 VFS。
4. Framework 0.11.x 与 CLI 1.3.x 一起更新 `cliCompatibility`，不实现无清单包或旧 CLI 的兼容分支。旧项目使用 CLI 1.2.5 与相应 Framework。包格式、脚本与原生协议、CLI 兼容码是三个独立契约。
5. 首版以 ESM 源码作为脚本表示。独立测源码编译与字节码反序列化，有实际收益才加入并列的字节码表示。不以混淆、防二改或签名系统作为目标。

## 后果

- 升级需重新构建和整理 UI；两种载体必须通过相同的行为与错误测试。
- UI 放进产品以后才能最终签名；包摘要用于发现错配和损坏，不等同于签名。
