# ADR 022：位图缓存驻留 GPU、tint 蒙版缓存与滚动层提升

日期：2026-11-13。状态：位图及蒙版缓存保留，本次ADR中的最早提出的滚动图块，自 0.10.2 因实践效果差而撤销；施工与验证见 [M5-EX2 需求与待办](../proj/m5：已完成/03-已完成：M5-EX2需求与待办.md)。

## 背景

M5 的位图缓存层（[渲染设计](../arch/05-渲染设计.md#位图缓存层)）与滚动重绘在 Windows（JUCE 8.0.12、Direct2D）上有三处可量化的浪费。数据来自独立基准（1280×720、RTX 5070 Ti、D2D 原生图像加回读同步，每场景前后各夹一次空帧测净耗时），是合成场景的相对代价，不是真实 Demo 的端到端数字：

| 场景 | 当前 | 缓存的 native 图 |
| :--- | :--- | :--- |
| 40 个 22px tint 图标 / 帧 | 13.1 ms | 0.06 ms |
| 10 张 400×300 位图 / 帧 | 软件图 0.48 ms | 0.02 ms |
| 滚动列表 20 行，tint 图标 | 5.4 ms | 0.01 ms（预栅格化层） |
| 滚动列表 60 行，tint 图标 | 8.3 ms | 0.03 ms（预栅格化层） |

成因：

1. tint 矢量每帧新建一张离屏图、栅格化整个矢量、再着色绘制，没有任何缓存，约 0.25 ms 每个；这张离屏图还按逻辑像素建，高分屏上偏软。
2. 位图缓存里的图全是 `SoftwareImageType`。Direct2D 绘制软件图时每次都转成一张新的 GPU 位图并上传，用完即弃：CPU 上命中缓存，GPU 上每帧重传。
3. 滚动时内容片段身份不变，只有 viewport 层到内容片段那条引用边上的偏移变了；[脏区重绘](../arch/05-渲染设计.md#脏区重绘)得到整个视口，视口内全部命令每帧重放。

DXGI 的滚动矩形（`Present1` 的 `pScrollRect`）JUCE 不开放，也不由我们决定；几何对象每帧重建同属 JUCE 内部。本篇只处理我们这一侧能做的部分。

## 决策与理由

1. **位图缓存统一使用 native 图。** 条目在 build 后转成平台原生图（`NativeImageType`）一次再入缓存，之后每次绘制都是 GPU 驻留位图。模糊等像素运算仍在软件图上完成再转换；字节预算与计数口径不变。查找由线性扫描改为哈希表加 LRU 链表，避免命中查找随条目数线性增长。

2. **tint 矢量缓存与颜色无关的蒙版。** 蒙版按物理像素（视口缩放量化到 1/16）栅格化，键为内容身份、帧、像素尺寸、缩放、适应方式与对齐；着色在绘制时由 `drawImage` 的 alpha 着色完成。颜色动画不触发重新栅格化，同一图标在不同色下共用蒙版。带缩放或旋转的祖先变换沿用同一键，缩放量化后命中；不为此另设直接绘制分支。

3. **历史方案：0.10.0–0.10.1 在 JUCE 重放层实现滚动图块，不改发布模型。** 实现前核对发现：滚动值不进入层身份（构建层时清零），viewport 层只有一个子片段，滚动偏移完全在这条引用边上，内容片段身份与偏移无关，因此无需把偏移改造成新的片段属性。重放时满足条件就取内容坐标系的 GPU 图块绘制：只建与裁剪相交的图块；偏移吸附物理像素且只作用于绘制，吸附按窗口坐标算；内容换新时复用脏区的片段树比较，相交的图块只局部重画；不满足保守条件时回退直接绘制，内容持续大面积变化时降级。回退条件取保守，是因为图块是整层合成，与逐操作透明度等价、且只有平移时才与直接绘制逐像素一致。

4. **不做。** 滚动矩形与几何缓存（JUCE 内部）；后台预栅格化邻近图块（首次进入的图块一次性付出一次栅格化，与直接绘制该区域同量级，后续不再付）；不带 tint 的矢量缓存栅格（缩放后发糊，待有真实数据再议）。

## 后果

- 图块以下表现是 0.10.0–0.10.1 的历史行为，不适用于 0.10.2一帧只剩若干张整数对齐的纹理绘制；首次进入新图块与内容变化时多一次栅格化。
- 滚动内容的绘制位置吸附物理像素，低速滚动时视觉步进为 1 物理像素；停下来的静态画面也由图块给出，不再与直接绘制有半像素的差。
- 图块内文字走 JUCE 的原生离屏渲染，整数物理偏移下与直接绘制逐像素相同；高分屏与小数缩放下的观感以主人手测为准，若有可见差异再收窄条件。
- 首版（0.10.0）吸附只按编辑器局部坐标算，默认编辑器原点落在整数设备像素上；Windows 上缩放 150% 等情形下逻辑整数位置乘缩放会落到半个像素，图块被双线性重采样，文字明显发糊（主人手测发现，原生测试复现：缩放 1.5、原点偏移 1 个逻辑像素时与零偏移的图块最大通道差 103，修复后为 0）。0.10.1 改为按窗口坐标吸附，并改用最近邻采样兜底。同一版的降级判据把滚动新进入的图块算作需重建，快速滚动加悬停变化时 960 次绘制里有 679 次降级为直接绘制且不会恢复；0.10.1 改为只看内容变化的面积，并把图块整块重建改为局部重画。
- 位图缓存的图为 GPU 位图，Direct2D 设备丢失后由 JUCE 重建；缓存只持有 JUCE 图对象，不持有设备资源，丢失后的重绘按需重建。
- 0.10.2 撤销滚动图块：在微软 D2D1 真实窗口对照中，禁用图块后首页猛滚与动画切换的 paint 调用耗时分别下降约 30% 和 94%，主要代价是离屏构建与修补，见[渲染归因测试](../proj/m5：已完成/04-无需再看：M5-EX2渲染归因测试.md)。因此移除图块路径和专用诊断，直接重放滚动内容，继续复用片段、剔除不可见操作与计算脏区。 [渲染设计](../arch/05-渲染设计.md)。
