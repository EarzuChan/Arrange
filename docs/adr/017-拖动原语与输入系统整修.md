# ADR 017：拖动原语与输入系统整修

日期：2026-10-27。状态：设计已定，待施工。

## 背景

M4 之后要提供旋钮、滑杆等参数控件。当前 Framework 没有公开的拖动能力，Demo 用定时器模拟拖动来演示参数 gesture。借这次补拖动的机会，把现有指针、键盘、滚轮与焦点行为一并梳理，发现以下问题：

- 任意鼠标键都会触发 `clickable`，右键也会调用 onClick。
- `hoverable` 只有声明，原生侧没有悬停跟踪；也没有光标管理。
- 编辑器失焦或隐藏时只取消滚轮会话，按下与文本拖选状态不取消。
- 指针按下用浮点坐标，拖动与抬起用整数坐标。
- 每次指针按下都夺取键盘焦点，点击空白处后宿主快捷键（如空格走带）也被插件吞掉。
- 用户无法处理按键；方向键无条件移动焦点，Enter / Space 在按下时激活且随按键重复连发；没有 key up 与修饰键变化事件。
- F5–F7 诊断快捷键在 Release 中同样抢占按键。
- 滚轮只服务滚动容器；双击只服务文本；`InteractionState` 只有设计；文档里的 `M.scrollable` 从未实现。

## 决策与理由

1. 控件拖动与拖放是两件事。前者是输入手势，只产出位移；后者是跨节点、跨窗口乃至跨进程的数据传递，需要载荷类型、目标命中与平台会话。本轮只做控件拖动，拖放另行设计。
2. 能力按原语逐层叠加：原生指针会话 → `M.draggable` 等手势原语 → 不带外观的数值拖动状态 → 设计系统控件。每层只使用下层的公开能力，`M.pointerInput` 复用同一套会话与捕获，在本计划最后公开。这样第三方控件与官方控件处在同一起点。
3. 手势识别放在原生侧：按键过滤、拖动阈值、指针捕获、独占、取消与按帧累加都由原生完成，JS 只收到开始、位移与结束。这与 clickable、滚动会话一致，减少跨界调用，取消也不依赖 JS 侧记账。
4. 拖动会话独占指针：期间滚轮被丢弃且不开启滚动会话，悬停冻结，祖先不接管。因此拖动与滚动、与精调修饰键之间不存在冲突。按下后移动从未超过阈值的会话仍可识别为点击，双击复位与拖动可以共存。
5. 无界拖动作为手势原语的选项：原生隐藏光标并解除屏幕边缘限制，结束时光标回到按下点。旋钮类控件普遍需要它，且只能由原生实现。
6. 手势原语不持有数值。数值逻辑由 `createValueDragState()` 承担，与 `createScrollState()` 一样在 setup 中创建一次，配置字段为响应式；挂载用 `adjustable()` 组合函数，它只组合公开 Modifier，不含私有能力。不采用 Modifier 形态，因为数值状态需要被绘制、键盘、语义等多处共同读取。
7. 数值域统一为全程比例：参数绑定读写归一化值，skew 由参数自身的范围处理；`range` 只服务普通 ref 绑定。内部累加值不量化，写入时才按步长吸附，避免步进参数在小位移下卡住。精调修饰键按位移段生效，途中按下不跳变。参数 gesture 的 begin 延迟到首次真实写值，没有改变数值的拖动不向宿主产生空编辑。旋钮的角度拖法一并提供。
8. 与 JUCE 的边界：不使用 `juce::Slider` 与 `SliderAttachment`。灵敏度、精调、双击复位、旋钮拖法与滚轮调值在 Arrange 原语上重新实现；与 JUCE 相连的只有参数层的 begin / set / end，以及平台输入转发。互操作补充 `param.editable()` 与宿主参数菜单入口。
9. `clickable` 只响应主键；上下文点击（右键，macOS 上 Ctrl+点击）由 `M.onContextClick` 单独声明，留给宿主参数菜单与自定义菜单。`clickable` 增加 `onDoubleClick`。
10. 补齐原生悬停跟踪与 `hoverable` 的进入 / 离开回调，新增 `M.pointerIcon` 管理光标；`InteractionState` 本轮落地，提供悬停、按下、焦点与拖动中四种状态。
11. 统一取消来源：丢失捕获、编辑器失焦或隐藏、节点退休、受体替换、热更新与编辑器关闭，对按下、文本拖选、拖动会话与滚轮会话一并生效。平台坐标统一按浮点逻辑坐标进入。
12. 键盘焦点只在指针命中焦点受体时获取；点击非受体区域清除 Arrange 焦点并交还键盘。所有未消费的按键都报告为未消费，由宿主继续处理。插件运行在宿主里，宿主快捷键优先于插件的空白区域。
13. 新增 `M.onKeyEvent`：按键先交给焦点受体及其祖先的处理器（冒泡），未消费时再执行默认行为（激活、焦点导航、键盘滚动）。补齐 key up、重复标记与修饰键变化。Enter / Space 改为按下进入 pressed、抬起激活，重复不连发。诊断快捷键只在开发模式存在。
14. 新增 `M.onWheel`：声明了它的节点参与滚动会话的初始候选选择，按命中链上最近的消费者锁定；会话锁定后途经的值控件不截取滚轮。删除未实现的 `M.scrollable`，其用途由 `draggable` 与 `onWheel` 覆盖。
15. 新增最小语义 `M.semantics`，承载角色、标签、数值文本与增减动作，先服务键盘与测试；平台无障碍桥接仍属后续。

具体行为以 [事件与输入](../arch/17-事件与输入.md) 和 [拖动与数值控件](../arch/37-拖动与数值控件.md) 为准，公开签名见 [基础 API 形态](../arch/21-基础API形态.md)，参数绑定见 [互操作](../arch/16-互操作.md)。本文记录选择与原因，不另定义接口。

## 实施与验收影响

原生侧需要把按下、文本拖选与拖动收拢为同一个指针会话与捕获所有者，JUCE 适配层补齐移动、进入 / 离开、修饰键与按键状态转发，并实现无界移动。键盘派发顺序、焦点获取策略与诊断快捷键需要调整，可能改变现有应用的按键行为。0.x 版本中这些变化按破坏性变更发布。

自动化测试需覆盖：拖动阈值、独占与各取消来源；参数端 begin / set / end 序列（取消必有 end，无变化无编辑）；精调分段；键盘冒泡与默认行为顺序；宿主按键回传；滚轮候选与锁定；悬停与光标。无界拖动与宿主快捷键需要在真实宿主中验收。
