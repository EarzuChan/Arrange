# ADR 007：M1 三四五期正规化收束总结

日期：2026-05-14

## 背景

M1 第二期之后，Arrange 的声明式主链路已经从“能跑 demo”进入“必须可长期维护”的阶段。第三期、第四期、第五期连续处理的不是新增功能，而是同一个问题的逐层加严：

- 生产链路不能有多套入口、多套状态源、多套输出阶段。
- QuickJS native boundary、Modifier、event slot、scroll、text input、FramePlan 必须能解释为同一条声明式 UI pipeline。
- 测试不能只证明表面产物存在，必须证明真实 callback、真实 mutation、真实 invalidation、真实 pipeline 执行。
- 代码命名、职责和格式必须足够清楚，不能靠历史旧名、魔法 prop、字符串搜索和临时 serializer 继续向后滚雪球。

第五期进一步指出：Arrange 当前架构不是“JS 前端向 C++ 后端传输数据”的传统前后端模式。QuickJS 与 C++ 同进程，C++ 能通过 QuickJS C API 直接读取 JS object、primitive 与 function。原把 JS object 先序列化成 JSON、字符串、二进制 buffer 或 BridgeOp，再由 C++ 解析，是错误方向。

本 ADR 记录三四五期正规化的收束决策。长期事实源仍以 `docs/arch/` 当前母文档为准；本 ADR 只记录这轮收束为什么发生，以及后续维护不得回退的方向。

## 决策

### 1. 生产树统一为 LayoutTree

第三期起，生产树概念收束为 `LayoutTree` / `LayoutNode` 方向。历史 `RenderTree`、多套 tree、测试 reference 与生产 tree 混用的思路不得继续扩张。

`LayoutTree` 是 C++ core 中服务 layout、paint、hit-test、input、accessibility、dirty attribution 的唯一生产树。TS headless layout 第二实现必须删除，不能作为“测试工具”继续维护另一套布局、绘制、命中或文本测量事实源。

### 2. Modifier 生产语义只能来自 QuickJS JSValue 直读与 native ModifierCompiler

Modifier 不再展开为 `__arrangeModifier.N.*`、`__arrangeClickable*`、`__arrangeVerticalScrollValue`、`__arrangeZIndex` 等 JS 层派生 prop。

生产链路固定为：

```txt
TS stable Modifier object shape
-> QuickJS ModifierReader 直接读取 JSValue
-> native ModifierSpec / ModifierCompiler
-> CompiledModifier
-> Layout / Paint / HitTest / Input / Invalidation
```

QuickJS 不得作为完整 Modifier 实例 fallback serializer。Layout、Paint、HitTest、Input 与 Invalidation 不能各自解析 Modifier payload。

### 3. Event slot 必须是真实 callback 注册，不允许假 slot

第四期确认：event slot 不是字符串占位。进入 active registry 的 slot 必须绑定真实 JS function。

禁止：

- 用 `JS_UNDEFINED` 注册 active event slot；
- 通过 payload 字符串 contains 推断 slot；
- native callback adapter 找不到真实 prop 时根据 node id / kind 生成假 valid slot；
- 用 event slot count 代替真实 invoke 测试。

event slot 生命周期必须随 setModifier、setProp、deleteNode、removeChild、unmount、reload / HMR 一起处理，退休后不得残留为可调用 callback。

### 4. Scroll 状态源回到 JS 声明式状态

第四期确认：native 可以负责命中、clamp、消费 delta 和派发 scroll snapshot，但不能直接写旧派生 scroll prop。

滚轮链路固定为：

```txt
JUCE wheel
-> Wheel InputIntent
-> C++ hit path / ScrollDispatcher
-> invoke scroll EventSlot with C++ 构造的 JS object snapshot
-> JS ScrollState update
-> Vue reactive flush
-> native setModifier typed mutation
-> LayoutTree apply / ModifierCompiler / dirty attribution
-> FramePlan
```

禁止 native 通过 `SetProp("__arrangeVerticalScrollValue")` 或 `SetProp("__arrangeHorizontalScrollValue")` 直接写回滚动状态。也禁止把 scroll snapshot 转成 JSON string 再交给 JS 解析。

### 5. 删除生产 Bridge 协议，改为 QuickJS native transaction

第五期确认：不再维护生产 Bridge schema、command buffer、binary buffer、encoded prop 或 JSON/string value 编码。

生产链路固定为：

```txt
Vue renderer host op
-> QuickJS native transaction API
-> QuickJS host 直接读取 JSValue / primitive / callback function
-> native typed MutationTransaction
-> MutationTransaction queue
-> SceneFramePipeline
```

严肃要求：

- TS 不编码。
- TS 不 stringify。
- TS 不生成二进制 buffer。
- TS 不生成 JSON payload。
- QuickJS host 不做泛用 serializer。
- core 不解析 JSON、不解析 encoded string、不依赖 QuickJS 类型。
- 批处理只能是 native transaction batching，不能重新变成另一套可传输协议。

旧 `BridgeOp`、`BridgeBatch`、`BridgeEncodedValue`、`EncodedProp`、`modifierPayload`、`commitCommandBuffer` 等只能作为待删除旧债存在，不得被文档、测试或新代码继续保护。

### 6. native internal invalidation 不得伪装成普通 prop

第五期确认：native-first 状态允许存在，例如 text editing、caret、selection、IME composition、diagnostics、resource state。

但这些内部状态变化必须走：

```txt
InputIntent / RuntimeStore / typed native invalidation / dirty API
-> InvalidationGraph
-> FramePlan
```

不得长期通过 `SetProp("__arrangeNativeInput...")` 一类 magic key 伪装成普通声明 prop。

同理，内部刷新或结构意图不得通过 `__arrangeSubtreeReplaced` 这类无定义普通 prop 表达。需要结构变化就用结构 mutation；需要失效就用明确 dirty API。

### 7. Dirty / diff 必须结构化，不能靠猜测保底

`CompiledModifierDiff` 必须继续向结构化表达收敛。layout、paint、transform、parent data、zIndex、input、focus、scroll value、click event slot、scroll event slot 等变化应能分别归因。

纯 event callback / event slot 替换不得触发无理由 measure、layout 或 paint。event slot dirty 应来自真实字段比较，不能长期靠“diff.dirtyMask == 0 时保底标 EventSlot dirty”来维持正确性。

### 8. Paint semantics 继续向 typed paint op 收敛

第四期已经用 `PaintChainOp` 修正 padding / background / clip 顺序补丁味。第五期继续确认：Paint 阶段不应长期靠自由字符串 `style.type == ...` 作为主要绘制分派依据。

ModifierCompiler 应把字符串 payload 编译成 typed paint op。Paint 只消费 compiled semantics。

### 9. 测试必须证明真实链路

三四五期后，测试原则进一步加严：

- QuickJS smoke 必须真实 invoke click / scroll / input callback。
- native runtime smoke 必须从当前 `LayoutTree` compiled modifier 或真实 event prop 读取 slot。
- NativeTransaction test 必须覆盖 JSValue 直读到 typed native mutation。
- internal invalidation、event prop schema、Paint typed op、CompiledModifierDiff 必须有防回流测试。
- 测试不得维护 TS headless layout 等非法第二实现。
- 测试不得以 fixture / command buffer / encode-decode roundtrip 名义保护旧 bridge：我们没有兼容性包袱，垃圾必须彻底清理替换。
- 人工 GUI 验收仍用于最终体验确认，但不能替代自动回归。

### 10. 收尾化补充：公开面必须闭环

M1 收尾化确认：已经公开但没有完整闭环的 API，应从当前公开面删除，而不是保留半支持形态。

公开 API 必须同时具备：

- TS 侧稳定 API / object shape。
- QuickJS reader 直接读取 JSValue。
- core / native 的 typed 语义。
- pipeline 行为与 dirty 归因。
- 自动化测试或明确人工验收闭环。

`pointerInput`、FocusRequester、semantics / testTag 这类能力仍属于长期设计方向；但在某个里程碑内，若尚未形成上述闭环，就不能作为该里程碑的当前公开能力暴露。prop schema 化同理：直接读取 JS object 不等于接纳任意对象协议，unknown prop 与 extension bucket 必须有明确 schema 和诊断策略。

## 影响

- 当前 `docs/arch/15-LayoutTree与NativeTransaction.md`、`docs/arch/26-调度线程与帧阶段.md`、`docs/arch/11-Modifier.md`、`docs/arch/17-事件与输入.md`、`docs/arch/22-测试策略.md` 是第五期整改时的主要长期事实源。
- ADR 005 / 006 仍保留历史背景；若旧表述与本 ADR 或当前 `arch/` 冲突，以当前 `arch/` 与本 ADR 的较新决策为准。
- 第五期代码执行不得重新引入旧派生 prop、假 event slot、native scroll 直接状态写入、QuickJS Modifier fallback serializer、普通 prop 形式的 internal invalidation、BridgeBatch / BridgeOp / command buffer / encoded prop 生产链路。

## 不做

- 不机械复刻 Compose Desktop 的具体 Kotlin / Snapshot / Skia 实现。
- 不为对齐名词把合理聚合对象拆碎。
- 不以“过渡、兼容、fixture、test-only”为理由保留旧生产协议。
- 不在 M1 重新设计传统跨进程 wire protocol；当前 QuickJS 同进程事实决定生产链路必须 JSValue 直读。
