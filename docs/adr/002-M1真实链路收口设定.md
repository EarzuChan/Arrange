# ADR 002：M1 真实链路收口设定

日期：2026-05-08

## 背景

M1 已经跑通基础 UI 闭环的多条第一切片，但真实 Standalone / VST3 宿主人工测试暴露出以下问题：

- 滚动视口内鼠标滚轮仍会触发错误。
- Debug dist fallback 后，错误页点击重试又进入 `Dev Server not reachable`。
- 错误页恢复后存在局部重绘不完整、旧画面与新画面叠画。
- Standalone 窗口无法拖拽 resize，影响 resize 验收。
- 真实 OS IME 已能提交文本，但 Input 文本、光标、选区与 IME bounds 存在明显偏移。
- runtime 内存在自研 `h`、`.mjs` 源码与代码样式债，容易混淆 Vue/SFC 主路径。

这些是 `Arrange UI Pipeline` 仍需收口的证据。

## 决策

### 1. App source API

`ArrangeEditor` 不再 `App::fromHere(...)` 。改为：

```cpp
arrange::juce::EditorConfig config;

config.app.useDist(); // 使用默认 dist 包目录
config.app.useDist("../ui"); // 显式提供 dist 包目录
config.app.useLive(); // 使用默认 http://127.0.0.1:9178
config.app.useLive("http://host:port"); // 显式提供
```

规则：

- `useLive(...)` 可缺省，缺省时使用 `http://127.0.0.1:9178`。
- `useDist(...)` 可缺省，缺省时使用约定 `ui/` 产物包目录。
- Debug Demo 推荐同时配置 `useLive()` 与 `useDist("../ui")`。
- Release 推荐只配置 `useDist(...)`。
- 若既没有 live，也没有 dist，进入错误屏，诊断必须明确说明没有可加载 App。

旧 API 全面移除：

- 删除 `App::fromHere(...)`、`App::fromPath(...)`、`App::defaultApp()`、单路径构造 `App(path)`。
- 删除旧单路径读取别名 `App::path()`，读取 dist source 必须使用 `distPath()`。

所有生产代码、Demo、测试和文档示例都必须使用新 source 配置 API：测试不得为了便利重新引入静态工厂或单路径构造。若测试需要构造 dist source，应和用户代码一样创建 `App` / `EditorConfig` 后调用 `useDist(...)`；动态测试路径应传入绝对路径或已明确解析过的路径。

### 2. reload 规则

每次刷新、错误重试、HMR reload 和手动 reload 都走同一条链路：

```txt
if live enabled:
  try live
  if success return
if dist enabled:
  try dist
  if success return
show error
```

不记录复杂 fallback 状态。这样自然支持：

- 一直开 live。
- 半路关闭 live。
- 半路才启动 live。
- 完全没有 live，走 dist。
- 只配置 live，live 不通则报错。

Debug 下需要提供手动操作：

- `F5`：按上述链路重新加载。
- `Ctrl+F5`：切换 live enabled 状态后重新加载。

### 3. Debug / Release 状态可见

Editor 内统一绘制运行状态 badge：

- `Debug live`
- `Debug dist`
- `Release dist`
- 必要时显示 `Debug live failed -> dist`

Standalone 额外尝试把标题栏设置为 `Arrange Demo [live]` 或 `Arrange Demo [dist]`。VST3 宿主外层标题栏不作为可靠显示渠道。

badge、标题栏、错误屏、日志与必要 overlay toast 统一归入开发期诊断表层。具体模型、样式、行为、用户开关和未来 DevTools 边界见 `docs/arch/25-开发期诊断表层.md`。

### 4. window / editor config

`EditorConfig` 应包含窗口行为配置：

```cpp
config.window.title = "Arrange Demo";
config.window.resizable = true;
config.window.useCornerResizer = true;
config.window.minWidth = 360;
config.window.minHeight = 240;
config.window.maxWidth = 4096;
config.window.maxHeight = 4096;
```

Standalone 应尽量完整尊重这些配置；插件宿主中按宿主允许范围尽力尊重。

### 5. invalidation 优先正确

M1 收口阶段，重绘正确性优先于局部 repaint 优化。

必须强制 full repaint 的场景：

- 初次加载成功。
- reload / HMR reload。
- error -> loaded。
- loaded -> error。
- root tree 重建。
- editor resized。
- dev / dist source 切换。
- scroll / clip / transform 相关 dirty bounds 无法可靠证明正确时。

dirty repaint 只用于普通 prop/text/paint 小变化。dirty 清理必须发生在 repaint 调度语义明确之后，不能过早清掉导致漏画。

### 6. TextLayoutService 是文本唯一模型

Text、Input、IME、selection、caret、hit-test 不能各自手写测量。

必须建立共享的 `TextLayoutService`：

```txt
text + style + width constraints
-> line metrics
-> glyph / cluster positions
-> caret rect
-> selection rects
-> point -> text index
-> draw plan
```

以下路径必须共用该模型：

- Text 测量与绘制。
- Input 文本绘制。
- Input 光标绘制。
- Input 选区绘制。
- IME `getCaretRectangleForCharIndex(...)`。
- IME `getTextBounds(...)`。
- 鼠标点击定位。
- 拖拽选择。

禁止用 `fontSize * 常数` 作为长期 caret / selection 测量。

### 7. 生产事实源在 C++ core

生产路径的事实源为：

```txt
arrange_core
  LayoutTree
  LayoutEngine
  TextLayoutService
  PaintModel
  HitTester
  ScrollDispatcher
  InputEditing
  Invalidation
```

TS runtime 负责 Vue/SFC authoring、响应式状态与 bridge 提交；不得形成第二套生产布局、绘制、命中或文本测量事实源。

测试层可以有轻量 TestTree / TestRule，但必须明确是测试模型，不得伪装为生产引擎。

### 8. Scroll 双向同步

滚动交互期间，native 是事实源：

```txt
JUCE wheel
-> C++ hit path
-> C++ consume / clamp
-> C++ layout / repaint
-> typed mirror event to JS ScrollState
```

JS `ScrollState` 是响应式镜像与声明式输入，不应在同一轮交互里反向覆盖 native 刚计算出的值。

### 9. 协议优先，debug JSON 只能诊断

生产代码不得依赖 `modifierDebugJson.find(...)` 解析语义。滚动、回调、文本样式、资源、Input 等信息都应逐步进入 typed bridge 字段。

`modifierDebugJson` 只能用于日志、诊断和临时 smoke 对照。

### 10. Vue 是主 authoring 路径

正式 authoring 路径为：

```txt
Vue SFC / Vue render function
-> Vue custom renderer
-> Arrange host nodes
-> Bridge
```

`@arrange/runtime` 不公开自研 `h` 作为主 API。若测试仍需轻量 vnode helper，应迁移到 `@arrange/runtime/test` 或内部模块，并明确不属于生产 authoring。

### 11. TS-first 与代码样式

新 runtime / tooling 源码应使用 TypeScript。`.mjs` 作为构建产物或旧债存在，后续迁移。

JS/TS 代码样式：

- 不加行末分号。
- 不把多行逻辑压成一行。
- 缩进 4。
- 类型声明由 TS 源码生成，避免长期手写巨型 `.d.ts`。

## 影响

- M1 complete 前必须修复真实测试暴露的阻塞问题。
- 之前“只缺人工截图”的判断作废。
- `verify-m1-slice` 通过不再足以说明 M1 可退出。
- 后续实现按本 ADR 收口，若与早期文档冲突，以本 ADR 和更新后的架构文档为准。
