# ADR 019：全链路肃清

日期：2026-10-27。状态：已定，施工中。

## 背景

M4 拖动与输入整修完成后，对框架主链路做了一次整体审视。骨架成立：阶段化失效、候选事务、稳定事件槽与被动绘制都按设计运转。问题集中在三类：重构后旧路未删，同一能力有第二条路径；同一张表在多处手抄，靠字符串分派；候选模型每帧付出全量复制的代价。本篇把整改取舍一次定下，施工与验收状态见 [M4 全链路肃清待办](../proj/m4：进行中/03-全链路肃清待办.md)。

## 决策与理由

1. **同一能力只留一条路径。** 原生旧指针处理器 `PointerInputProcessor` 已无生产调用方，删除。无障碍只留 `M.semantics` 一条通道：节点宿主输入 `contentDescription`、`label`、`description`、`role` 删除；`Image`、`Icon` 的 `contentDescription` 属性降解为 `semantics({ role: 'image', label })`，Layout 与 Box 不再接受该属性。诊断叠加层的重建改用独立的 `DirtyFlag::Diagnostics`，不再借用 Accessibility。

2. **输入语义归 core，JUCE 只做翻译。** 指针手势、滚轮会话、按键状态与冒泡、Enter / Space 激活、焦点遍历与 Lazy 焦点请求，都是与平台无关的规则，收进 core 的统一输入会话 `InputSession`，与命中器共用一处。JUCE 层只把平台事件、`KeyPress` 与 IME 接口翻译进会话。滚轮输入结构 `WheelInput` 一并归 core，只为测试存在的“每单位 48 PX”重载删除。这样键盘、焦点与滚轮规则可以脱离 JUCE 测试。

3. **修饰表只有一个事实源。** `@arrange/shared` 的修饰 schema 声明每种修饰的字段单位、回调字段及其事件种类；JS 降解、编译器单位检查与原生读取白名单都由它驱动。C++ 不能导入 TypeScript，因此像版本号那样由脚本生成原生白名单与种类名表，并提供检查模式防止漂移；解析逻辑仍手写。JS 端的 `UnitResolver` 拆为修饰降解与事件载荷适配两部分，前者按 schema 换算单位并管理绘制实例的事务生命，后者负责 PX 到 DP 的事件换算与稳定包装。

4. **原生热路径不用字符串表达枚举。** 节点宿主输入在第 1 条之后只剩 `enabled`，`LayoutNode` 改为类型化字段；`DrawOp` 的文本对齐、溢出、内容缩放与对齐改为枚举，字符串只在 QuickJS 读取边界转换一次。帧计划与阶段记录的原因改为位标志与枚举，字符串只在诊断需要时生成。

5. **候选场景以写入日志代替整树复制。** 帧管线不再每帧复制整棵 `LayoutTree`。可变访问统一经过 `mutableNode`，每帧首次写入某节点时把旧值记入日志；失败按日志恢复，成功清空日志。复制代价从全树降为被改动的节点。不采用持久化 map：它同样能做到结构共享，但改动面与常数开销都更大。

6. **重绘按脏区进行。** 发布帧时比较新旧绘制片段，取变化节点在窗口坐标下的新旧边界并集（含变换）交给宿主局部重绘；区域过多或变换复杂时退回整块重绘。遮挡剔除另作后续项。

7. **公开状态对象统一形态。** 所有 `createXxxState()` 返回的对象对外是只读 getter 与方法，内部通道一律经 WeakMap 取得，公开类型上不出现内部钩子。公开数据字段按 [ADR 018](018-无扩展函数与接收者时的Compose对齐约定.md) 第 5 条带单位后缀，如 `ScrollState.valuePx`、`LazyVisibleItemInfo.offsetPx`。这是破坏性变更，随 `0.6.0` 发布。

8. **原生宿主接口如实声明。** `NativeTransactionTarget` 中真实运行时必然提供的成员改为必选，生产代码不再以可选调用兜底；测试替身由统一的帮助函数补齐空实现。

9. **残留一并清除。** 删除空源文件；arch 文档中无对应代码的词汇（如 `SlotUpdateBatch`、`ReactiveSlotRuntime`、`NativeSceneState`、`MeasureAndLayoutEngine`）改为代码实名或删除；文件名与类名对齐；`pointerInput` 的按下外推按目标逆变换换算；`Interaction` 的按下与拖动状态归属各自受体，悬停仍以节点为单位。

## 实施与验收影响

施工串行进行：先清障（第 1、4 条的帧原因、第 9 条），再改候选场景与热路径（第 4、5 条），再收输入（第 2 条），再统一修饰表与状态（第 3、7、8 条），最后做脏区重绘并发布 `0.6.0`。每批跑 JS 测试、类型检查、格式检查与原生测试；第 5 条以现有本地工作量与 M23 性能基准对比前后“候选复制”与帧耗时，并以注入失败验证回滚。无障碍接入宿主 `AccessibilityHandler` 属功能施工，不在本篇范围，arch 中标“暂无能力”。
