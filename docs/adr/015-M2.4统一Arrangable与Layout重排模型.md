# ADR 015：M2.4 统一 Arrangable 与 Layout 重排模型

日期：2026-09-20。状态：设计确立，代码尚待重建。

## 背景

M2.4 第一趴的两轮实现先后使用字符串宿主节点、专属 Foundation 注册与执行、capabilities 文本通道及通用 Context.layout。它们把 Foundation 来源当作运行时权限，将文本保留在 Modifier 之外，并继续以 VNode 承载结构。类型校验和测试通过没有消除这些职责错误，完成结论已撤回。

## 决策与理由

1. SFA 编译和直接代码编写采用同一种 Arrangable 定义、初始化、调用及生命周期。FA 只表示代码编写方式，避免为内建视图设立用户 SFA 无法表达的行为通道
2. Layout 保留为唯一深入框架节点管理的 Arrangable。特权存在于其实际实现内，不由名称、定义注册或可扩展权限表授予，从而使所有调用者使用相同入口
3. RearrangeNode 唯一由 Layout 管理，不再定义为 VNode 的继承者。删除旧虚拟树及其构造、diff、patch 和编译消费者，再重建结构程序的调用协调；调用账本和作用域不冒充布局节点
4. 文本显示和编辑进入正式 Modifier 元素及实例生命周期。撤销 Layout 的独立 TextMeasurePolicy 和文本属性旁路，复用既有排版服务，避免两套测量、几何和输入资源归属
5. 同日进一步确认新的第一趴范围：重排重建、持久调用账本、完整 RearrangeScope、arrangeValue 删除及全部 prop getter 内化一起交付，避免以 VNode/AV 过桥或把精细依赖留给后续修补。最早第一趴有效契约作为历史基础回归；第二趴收窄为包整理与原生阶段优化，第三趴统一辅助行为与生产帧调度，不能据此推迟第一趴必要的作用域调度、取消与提交边界

完整对象模型与过程以 [运行时](../arch/04-运行时.md) 为准，组合职责见 [内建 Arrangable](../arch/12-内建Arrangable.md)，文本职责见 [文本输入与绘制](../arch/18-文本输入与绘制.md)。此前 ADR 的 Vue/custom renderer 背景不再构成保留 VNode 的依据；原有阶段化值更新、原生提交和候选帧发布原则继续有效。

## 实施影响

错误能力通道已按单独授权拆除，当前源码存在缺失实现与失效引用。本次只修订文档，不宣称已实现新模型，不复用旧测试记录作为验收。
