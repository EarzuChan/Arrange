# Arrange CLI TUI 验证

`arrange-tui-test` 是自有整帧 TUI 原型。终端接管、输入解码、路由、会话历史、布局与绘制由本目录实现；退出后由一次性拍扁渲染器把完整历史写回主屏幕。运行依赖只保留 `string-width` 及其依赖，用于 Unicode 单元格宽度；Terminal-Kit、Ink、React 及其入口和依赖已移除，没有运行时切换路径。这里积累显示和交互实践，尚未迁移回生产 CLI。

原型刻意采用“边框单元”和“内文单元”分离的渲染思想：布局先产生带颜色和宽度的行单元，最后一刻才把它们拍印成一行。因此四条边都按同一框宽绘制，右边线由 padding 明确补齐；运行期框宽跟随视口，退出拍扁时则由任务最长原始文本行决定，不按终端视口换行。主历史在内容少于屏高时贴底，子控制台固定六行且缓冲内容不足时从底部贴起。

任务是可观察的模拟过程：先等待，再显示旋转指示、百分比和不断增长的子控制台输出，最后转为完成状态。任务视图只读，执行计时状态结束后仍保留屏幕数据。

多选用 `○` / `●` 表示未选 / 已选。带子控制台的任务在等待期间只显示任务行，第一次开始执行后才展开控制台；完成或取消后保留已展开的画面，未开始的任务不会在拍扁历史中产生空框。

问题与任务批次统一在主项前留一行引导空行，首个问题也与前面的说明隔开；不再由上一题末尾补空行。子控制台完成后在底边左侧显示“╰─已完成──…╯”，取消则显示“╰─已取消──…╯”，六行内容和独立滚动保持不变；拍扁沿用留白及状态标记，框宽同时容纳原始文本与底边文字。

鼠标命中区域由子控制台的实际边框几何生成，包含四条边及框内区域；历史滚动、贴底和 resize 后，矩形随布局平移并裁剪到可见范围。框外的引导线、缩进和留白自然命中历史视口，不使用整行判断或边缘特例。

子控制台顶边左侧显示“可往上滚”“可往下滚”或“可上下滚”，底部跟随时追加“·跟随中”；内容不足六行时只显示“跟随中”。向上滚动暂停跟随，滚回底部恢复跟随并持续显示新增输出。拍扁展开全部内容，不保留滚动与跟随提示。

Windows Terminal 的 IME 合成文字由终端本身绘制，当前 VT 输入路径没有 composition 开始/更新事件；程序收到已提交字符后隐藏 placeholder，暂不尝试猜测合成状态。

交互顺序是选择题、输入题、多选题、SETUP 任务批次、完成状态。活跃提问始终追加在历史末尾；提交答案后才显示下一项。任务控制台固定六行，只读，内容各自独立滚动。

本原型独立于根目录的 pnpm workspace，根目录运行 `pnpm i` 不会安装本目录的依赖。首次运行需要进入本目录，使用随附的 `package-lock.json` 安装依赖；Node.js 要求 24 或以上。

```sh
cd temp-cli-for-test
npm ci
node index.js
```

需要全局命令时，在本目录执行 `npm install -g .`，之后运行 `arrange-tui-test`。

输入项目名并按 Enter 继续。方向键选择，Space 切换多选；PageUp/PageDown 或 Home/End 滚动历史；鼠标滚轮按所在区域滚动历史或对应子控制台。最终按 Enter 拍扁历史并退出；Ctrl+C 也会恢复终端并输出当前历史。

屏内退出提示前留一行空白；拍扁历史首尾各留一行空白，分别与执行命令和下一个 shell 提示符分隔。

## 职责边界

```text
index.js                    组合命令与 TUI 入口，汇合错误和退出码
app.ts                      CLI 业务编排：顺序提问，调用服务，呈现进展和结果
simulation.ts               模拟业务服务：接收模块选择和取消信号，产生业务进展
tui/index.ts、api.ts         公共边界：运行命令、语义提问与任务呈现接口
tui/session.ts              交互生命周期、内部事件路由、取消与异常收尾
tui/document.ts             通用历史内容模型，不含具体命令或执行资源
tui/prompt-controller.ts    选择、文本、多选的输入状态与答案解析
tui/task-controller.ts      任务呈现状态与只读控制台内容，校验更新顺序
tui/viewport-controller.ts  历史与子控制台滚动、几何命中、渲染调度
tui/view.js                 布局、框与文本单元、整帧渲染、一次性拍扁
tui/terminal-driver.ts      唯一终端所有者：模式、流、信号、尺寸、恢复、写出
tui/input-decoder.ts        有状态的 UTF-8 / VT 字节流 → 内部输入事件
tui/protocol.js             VT 模式序列及输出换行转换
```

依赖方向是 `入口 → TUI 运行器 + CLI 业务`，`CLI 业务 → 公共交互接口 + 业务服务`。`tui/` 不导入命令或服务，`simulation.ts` 不导入任何 TUI 类型；CLI 业务只持有 `CommandUi`，不创建驱动、不订阅键盘或 resize、不写 ANSI、不管理视口、不触发绘制。旧的业务显示混合模型及转发型输入路由已删除，没有兼容入口。

业务用 `await ui.select(...)`、`await ui.text(...)`、`await ui.multiselect(...)` 顺序取得答案，用 `ui.tasks(...)` 的呈现句柄报告开始、进度、输出和完成，再调用 `ui.result(...)`。句柄不包含文档、执行会话、流、坐标或输入事件；选项值和历史显示标签分别处理，颜色与六行控制台高度属于 TUI 主题和布局。公共对象在运行时冻结，内部文档不交给业务修改。

会话保证当前问题或任务批次完成后才能追加下一项，业务命令返回后由 TUI 负责停屏等待 Enter、恢复终端和写出历史。取消只通过通用 `AbortSignal` 通知业务，服务在自己的执行路径中释放资源；TUI 等待命令退出后再交还终端。任务呈现内容在执行结束后留在文档中，用户只能观看和滚动，不能向执行过程输入。

输入事件以零基单元格坐标表示鼠标位置，只在 TUI 内部流转。解码器不访问布局，视口控制器依据布局矩形处理滚轮；子控制台与历史不获取键盘焦点，pointer 不向执行会话透传。

驱动对输入、输出流分别取得唯一所有权，拒绝重复接管。普通关闭和异常关闭走同一条路径：停止调度、丢弃尚未提交的旧帧、等待在途帧完成、禁用鼠标/粘贴报告、在 raw mode 下短暂接收并丢弃迟到报告、恢复原 `isRaw` 和输入流动状态、退出备用屏幕、等待完整拍扁文本的写回调，最后移除监听、归还所有权。关闭幂等，正常路径不调用 `process.exit()`，也不关闭 stdin/stdout 或操作父进程。

输入静默等待默认 25ms，持续收到输入时最多 100ms；这是交接时的有限等待，不承诺清空所有宿主的输入队列。Node 的 `isRaw` 只暴露 raw 状态，不能据此宣称保存了 Windows 控制台每一个原生模式位。正常输出等待 write 回调，慢输出最多保留一帧在途和一帧最新待绘制帧；帧中间态不会无限排队。

`exit` 钩子只作最后的同步恢复，不尝试在该阶段补做异步拍扁；进程被强制杀死或终端连接已断开时，无法保证恢复和写出。正式交互中的 Ctrl+C、Escape、外部终止信号和被捕获的运行异常均在异步关闭完成后结束程序。不可把这个退出兜底当成正常关闭的第二条路径。

输入解码覆盖分包 UTF-8、CSI/SS3 导航键、单独 Escape 的超时判定、SGR 鼠标、括号粘贴；未知控制报告不会直接变成输入文本。粘贴作为单一数据事件交给文本问题，换行在单行输入中转为空格，不会合成回车提交或 Ctrl+C 取消；退格按 grapheme 删除。

本原型面向支持备用屏幕、SGR 鼠标和括号粘贴的现代 VT 终端，要求 stdin/stdout 为 TTY；不做终端品牌猜测或旧式控制台回退。目前任务输出仍为模拟文本，未假装实现 ANSI 终端模拟器。未来接真实进程时，输出终端语义应由 `@xterm/headless` 等成熟解析器负责，执行生命周期与只读视图缓冲继续解耦。
